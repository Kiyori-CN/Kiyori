# Kiyori shared context

This file defines the stable product language and compatibility boundaries for this repository.
Current work status and implementation notes belong in `docs/TODO/`.

## Product identity

- **Kiyori** is the brand.
- **Kiyori** is the Android application and user-visible product name.
- **Kiyori** is the repository and Gradle root-project name.
- The project repository is `https://github.com/Kiyori-CN/Kiyori`.
- The Android application ID is `com.kiyori`.
- Android system surfaces, the default assistant persona, Kiyori-owned file-provider titles, WebChat, generated workspace display text, and Kiyori-owned companion UI use the Kiyori brand.

## Product position and ownership

- **Kiyori** is an all-purpose browser powered by Operit AI. Web access and content handling are the product center; video, music, reading, downloads, files, ad blocking, and later content capabilities are browser-owned domains.
- **Operit AI** is Kiyori's embedded AI subsystem. It owns AI conversation and AI-specific runtime capabilities, but it does not own the Kiyori application shell, global navigation, product identity, or system-wide settings.
- Every Kiyori capability may provide a human-facing page and an AI-facing capability contract. AI integrations call those contracts instead of directly driving Activities, Composables, or ViewModels.
- Kiyori has never had a user-facing release. The inherited Operit navigation drawer is not a published Kiyori interface, so the product-shell migration removes that design instead of maintaining a parallel legacy route.

## UI design sources

- **Kiyori Professional Browser Theme** owns two visual domains. The application accent domain uses Material Blue 600 `#1E88E5` and low-saturation blue-gray `#536D79` semantics across AI, settings, shared controls, and App Shell selection. The browser protection domain keeps Browser Home, browser chrome, Full-Screen Web Search, and browser child pages neutral. Software Home retains its fixed five-color search-frame border and fixed blue Search/AI selection; the three legacy-replica root pages retain their own fixed palettes. The theme does not use wallpaper dynamic color as a product default.
- **Operit Original UI** remains the visual-language authority for typography scale, shapes, component treatment, general icon behavior, dialogs, settings rows, glass effects, motion, and interaction density so AI and non-AI surfaces form one product. Kiyori-owned App Shell and browser chrome instead use the Legacy Kiyori outline Vector family. The inherited Operit purple palette and unconditional wallpaper dynamic color are intentional Kiyori product differences.
- **Legacy Kiyori Design Reference** is `Kiyori-CN/kiyori-android@24a2dfa91f0a4166dc58e5c4732d11861173f766`. It provides the page composition, navigation intent, browser behavior, and feature layout for Kiyori-owned surfaces.
- When the two sources differ, an accepted Kiyori product contract determines behavior, Operit Original UI determines visual treatment, and Legacy Kiyori Design Reference determines the Kiyori page's content structure.
- Source references are design and migration evidence, not runtime dependencies. New hard-coded visual systems must not be introduced beside the shared Kiyori theme.

| **Software Home** | The default center page shown after launch and the first of five primary destinations. It owns the three-page horizontal home space and uses one centered title-over-search column at the `<600dp`, `600-839dp`, and `>=840dp` width gates. Drawer entry returns to AI Home; Settings Home entry uses `RouteEntrySource.KIYORI_SETTINGS` and returns to Settings Home. Crossing source families opens the AI Settings root. |
| **AI Navigation Root** | An AI top-level route explicitly identified by its registered navigation-entry ID. Root ownership is stored on the route entry itself and is never inferred from route arguments, stack depth, or an instance-ID naming convention. |
| **Kiyori Edge-to-Edge Shell** | The window contract in which Kiyori-owned page backgrounds and the Modal AI Drawer scrim paint behind a transparent status bar. Interactive page content applies system insets, while the drawer panel itself starts below the status bar. |
| **Professional Browser Theme** | The Kiyori-owned default visual contract. Light mode uses `#FFFFFF` backgrounds, `#202124` primary content, application primary `#1E88E5`, and secondary `#536D79`; dark mode uses near-black backgrounds, layered gray surfaces, primary `#90CAF9`, and secondary `#B9CBD4`. App Shell bottom navigation, browser bottom navigation, and the four-row browser menu use Kiyori-owned outline Vector assets; selection changes tint or container, never swaps to a filled icon. Software Home and the three legacy-replica roots use their explicit fixed page palettes. New installs and theme reset start in Kiyori light mode; system mode follows light/dark without wallpaper dynamic color. |
| **Permission Center** | A Kiyori system-level read-only overview and navigation destination that separates device capabilities from AI tool authorization. Its overview contains no direct permission switches and does not own another copy of either domain's persisted state. |
| **Device Capability Authorization** | Android and privileged-execution capabilities granted to Kiyori itself, including runtime permissions, file access, overlay, accessibility, battery exemption, Shizuku, Root, and debug capability. It is distinct from permission to invoke an AI tool. |
| **AI Tool Authorization** | The Operit AI policy that decides whether a registered tool is allowed, requires confirmation, or is forbidden. `ToolPermissionSystem` remains its single persisted source of truth. |
| **Software Home Search Frame** | The central same-background input surface, `114dp` high on regular windows and `96dp` in the short layout, with a fixed five-color `1dp` outline and no outer glow. The segments select the meaning and placeholder without navigating: Search opens Full-Screen Web Search when the frame is pressed, while AI enters the existing AI Home, preserves its conversation and draft, and requests focus for the real chat input after pager settlement. The saved mode survives return and configuration recreation; a cold launch starts in Search. The title ring is `18dp`. Attachment, voice, and camera remain immediate AI Home shortcuts. |

| **Full-Screen Web Search** | The shared web-only search surface opened from the Software Home Search Frame or Browser Home top bar. It shares the browser search-engine owner and normal-mode recent records, requires a real normal/incognito Profile control, and represents normal with an open eye and incognito with a closed eye. The control is a borderless standard icon action; mode changes show only a short inverse-surface bottom message. Software Home always creates a new shared WebSession; Browser Home reuses the active tab only when its immutable Profile matches the selected Profile and otherwise creates a matching tab. It does not search bookmarks, browser history, files, mini apps, or AI conversations; those domains own their search pages. |
| **Settings Home** | The Kiyori-owned settings root reproduced from the fixed Legacy Kiyori reference. It renders four borderless white cards and sixteen entries with fixed page colors. `AI Settings` opens the existing AI-owned page, `网页浏览器` opens Browser Settings, and `文件下载器` opens Download Settings directly; the other rows and all four header actions remain inert and own no persisted state. |
| **Settings Detail Surface** | The shared visual shell for Kiyori-owned settings children. Group cards are borderless white surfaces. The root title is one continuously transformed text element: the first `72dp` of list scrolling moves it from the expanded `32dp / 60dp / 26sp` frame to the pinned `56dp / 16dp / 20sp` frame while the header content height contracts from `128dp` to `56dp`; the Back action and real status-bar inset remain fixed. Browser Settings uses `网页浏览器设置` and Download Settings uses `文件下载器设置`. |
| **File Management Home** | The Kiyori-owned file root reproduced from the fixed Legacy Kiyori reference. It renders eight categories, seven quick-access entries, and four storage locations with zero placeholder counts. The phone-storage row reads available and total bytes from the app's actual data volume on composition and host resume; every page action remains inert. |
| **Browser Settings** | The fixed Legacy Kiyori browser-settings page opened from Settings Home or the fourth browser-menu row. Its five cards preserve the legacy order and visual treatment. `WebSessionBrowserSettingsStore` is the one owner for the custom home URL, webpage external-app policy, webpage geolocation policy, and floating-sniff-playback preference; every other legacy row is an explicit inert placeholder until its reference implementation has a real Kiyori runtime consumer. |
| **Browser Download Runtime** | `BrowserDownloadManager` is the only persisted Kiyori browser-download task owner. Its JSON records feed one `StateFlow` snapshot projection shared by the compact browser drawer, the full-screen Download Center, Minus-One, and AI events. New and explicitly resumed tasks enter one global FIFO scheduler; the versioned `BrowserDownloadSettingsStore` exposes `1..8` concurrent-task options, freezes each new HTTP task's ordinary Range-thread preference `3/6/12/20/32` (default `6`), M3U8 concurrency `3/8/16/20/32/48/64`, automatic-package preference, automatic public-transfer preference, chunk size, HTTP protocol preference, and optional SAF target directory. The task limit is synchronously capped at `8` and narrowed by `128 / max(normalThreads, m3u8Threads)` when a higher thread setting is selected. Old records without the new network or transfer field retain ordinary HTTP semantics with `16 / false / false / 2048 KiB / HTTP2 enabled / non-package` defaults. Ordinary HTTP runs through one task-owned `BrowserDownloadTransport`: HEAD and exact `0-0` probing resolve metadata, non-Range work uses one stream with the frozen buffer size, and Range plans use `max(chunkSize, 1 MiB)` parts under a Semaphore whose permit count is the smaller of the frozen ordinary preference and the size-derived segment capacity. `thread_count` remains the configured concurrency limit and is not rewritten to the number of parts. Every Range response must be `206` and match the requested bounds, probed total length, response-body length, and final part length; a failed attempt rolls back its file and progress before retry or failure. With automatic merge disabled, an M3U8 playlist is an ordinary file; with automatic merge enabled, up to four master levels select the highest `BANDWIDTH` variant, download `KEY`, `MAP`, and media resources under the frozen M3U8 semaphore, and rewrite a local `<playlist>.files/` companion directory. Confirmed offline packages remain in the application download directory and reject SAF/public transfer, while rename and delete keep the playlist and companion directory together. Ordinary internal downloads complete in the application download directory; automatic public transfer copies the finished file to `Download/Kiyori/browser/downloads/` and removes the application copy only after the public copy is complete. Process restoration converts interrupted and queued work to an explicit non-networking state until the user resumes it. A SAF write failure is a visible task failure and never changes the destination. The same settings owner stores `INTERNAL` or `SYSTEM`, skip-confirmation, completion-tip, and APK auto-clean policy. A confirmed `INTERNAL` request enters the JSON owner; a confirmed `SYSTEM` request is transferred directly to Android `DownloadManager` and remains absent from Kiyori task counts, progress, JSON state, SAF policy, and APK auto-clean. `blob:` and `data:` payloads remain internal because Android `DownloadManager` cannot own them. Completed Kiyori records can rename, change suffix, move to a SAF directory, copy the source URL or saved location, share the saved file, and transfer it to the public directory; moves delete the source only after a successful copy. Opening an internal APK schedules removal of its record and current file after `90s` when APK auto-clean is enabled. Path-based shares use `FileProvider`, while SAF shares retain their `content://` URI. All Kiyori task cards use one deletion confirmation dialog: deleting a record always removes its unreachable partial files, and the persisted checkbox decides only whether the completed destination file is also removed. |
| **Kiyori Capability API** | UI-independent contracts through which Operit AI observes and operates Kiyori browser, media, reader, file, download, and later domains. |
| **High-Impact AI Action** | An AI-requested operation with destructive, privacy, financial, external-communication, account, permission, or persistent-state impact. It requires explicit authorization and an inspectable operation record. |

## Navigation contract

- App launch opens the center Software Home page.
- The Software Home horizontal order is Minus-One Page, Software Home, then AI Home.
- All three home pages use one `PagerState` and one fling behavior. Movement follows the pointer, and a new reverse drag can cancel an unfinished fling; Shell state changes only after the pager settles.
- The five primary destinations are Software Home, Browser Home, Mini App Home, File Management Home, and Settings Home.
- The five-item bottom navigation is visible on Software Home, Mini App Home, File Management Home, and Settings Home. Browser Home is an immersive root with its own bottom bar; Minus-One Page, AI Home, Full-Screen Web Search, child pages, and immersive content pages also hide the Kiyori bottom navigation.
- Browser Home and the browser overlay are presentations of one Browser Runtime. Tabs, the active WebView, history, bookmarks, downloads, userscripts, and the pending-download confirmation are not copied between them. Browser downloads retain the existing JSON records as their only persisted Kiyori task state, publish one snapshot `StateFlow`, and use a global FIFO scheduler. Reducing the `1..8` concurrency preference never cancels work already running; a completed, failed, paused, canceled, or deleted task releases capacity for the next queued task. Each HTTP task freezes its selected ordinary Range concurrency from `3/6/12/20/32`, M3U8 concurrency, automatic-package preference, automatic public-transfer preference, chunk size, HTTP protocol preference, and internal target-directory URI when it is created, so pause/resume or later settings changes cannot alter its network plan or final destination. Ordinary Range part count follows chunk size while a Semaphore enforces the smaller of the frozen ordinary preference and the size-derived segment capacity; strict Browser transport validation rejects ignored Range responses and remote-length drift. Disabled M3U8 merge saves a single playlist, while enabled merge selects the highest-bandwidth variant through up to four master levels and builds a local playlist/companion package under the frozen M3U8 semaphore; confirmed packages stay in the application download directory and reject SAF/public transfer, with paired rename/delete. Ordinary internal tasks finish in the application download directory unless the frozen public-transfer setting moves the completed file to `Download/Kiyori/browser/downloads/`. SAF creation or copy failure is reported as `FAILED` and never changes the requested destination. Before confirmation, the pending request freezes file name, MIME, content length, selected engine, Cookie, User-Agent, and Referer. Internal dispatch enters `BrowserDownloadManager`; system dispatch gives Android `DownloadManager` complete ownership and never mirrors system progress into Kiyori or consumes Kiyori's SAF directory. Internal completion-tip policy shows completed/failed Toasts only for Kiyori-owned tasks, while system completion UI remains system-owned. APK auto-clean checks the setting when an internal APK opens and removes its task/file after the fixed 90-second delay. Website data is shared only inside each WebSession Profile: normal and incognito CookieManager, WebStorage, userscript Cookie/XHR, and download headers remain separated. Normal sessions write search and browsing history; incognito sessions never call the shared search-history, visit-history, or title-update writers. The expanded overlay paints through the status-bar and display-cutout bounds while browser chrome applies content insets. Android 13+ routes system Back through the overlay `OnBackInvokedDispatcher`; Android 12 and earlier route `KEYCODE_BACK` from the overlay ViewRoot. Both inputs call the same browser Back state machine. When the overlay is expanded, system Back first cancels a visible download confirmation, then closes browser layers and minimizes to the floating indicator before webpage history is considered. Browser Home entered from AI Home records that source and returns to AI Home while restoring the indicator.
- Operit AI discovers human-created browser state through `browser_tabs list`. The list enumerates the same Browser Runtime used by Browser Home and the overlay, exposes each stable `session_id`, `profile`, title, URL, index, and active state, and requires the intended tab to be selected before `browser_snapshot`, click, type, or navigation operations. `browser_tabs create` accepts `profile=normal|incognito`; omission uses the Browser Runtime default Profile. Incognito isolates website data, not Kiyori AI actions already authorized by the user.
- Browser Home's top bar is ordered Back, Search, and Refresh/Stop. The top-left action exits Browser Home according to its recorded Shell source; webpage history is owned by the bottom-bar Back and AI `browser_navigate_back`. Search opens the shared full-screen web search surface without recreating the active WebView. Its Profile control is always present; submission reuses the active tab only when the selected immutable Profile matches, and creates a matching shared WebSession otherwise. Engine selection and recent records remain browser-owned state. The bottom bar is ordered Back, Forward, Home, Tabs, and Browser Menu. Home navigates the active WebSession to the custom home URL, and human/AI new-tab creation uses the same URL. App Shell and browser bottom bars use five equal slots with `16dp` horizontal, `0dp` top, and `6dp` bottom padding, `44dp` circular targets, and `26dp` icons; the App Shell center icon is `25dp`. The browser window counter is a `20dp` square with a `1.75dp` outline. Browser Menu opens a content-sized four-row surface: its three five-column rows use `21dp` outline icons in `32dp` containers with `1dp` row spacing, while its fourth row directly distributes three `46×36dp` actions with `22dp` icons and no synthetic five-slot placeholders. History, bookmarks, downloads, userscripts, user-agent mode, network logs, page source, and capability explanation pages open draggable child drawers. The menu's Incognito action opens the real window overview, AI Dialogue returns to AI Home, and Exit Browser uses a power icon and removes the presentation layer while retaining sessions. The fourth-row Browser Settings button opens the same Shell child as Settings Home; App Shell presentation keeps the existing WebView mounted underneath, while overlay presentation first minimizes its focusable window and uses the explicit internal Kiyori Intent. The window overview has only normal/incognito selectors at the top, uses 2/3/4 columns, filters the one WebSession registry by immutable Profile, and displays `5:8` vertical in-memory thumbnails that fit the complete current WebView viewport without cropping. New and clear actions affect only the selected Profile. Unsupported Multi-Profile or failed cold-start private-profile cleanup disables incognito explicitly and never substitutes a normal window.
- Software Home uses one centered single-column composition on phones, tablets, and landscape screens. Its top-left weather owner requests coarse/fine location only through the Android runtime permission flow, resolves `Address.locality`, and sends the resulting latitude/longitude to Open-Meteo for `temperature_2m` and `weather_code`; failures remain explicit icon states and never display invented or stale values. Open-Meteo's free endpoint is non-commercial and subject to its published limits and privacy terms, so commercial distribution requires a separately licensed provider decision. A successful weather tap searches `<city> weather` with the current browser engine in a new shared WebSession. The top-right count is published by the same `StandardBrowserSessionTools` projection used by Browser Home and AI tools; tapping it enters Browser Home and sets the original host route to `WebSessionBrowserSheetRoute.TABS`.
- Software Home's Search action opens Full-Screen Web Search above the existing home pager without rebuilding Software Home or AI Home. The input is focused on entry; Back closes an open search-engine panel before leaving the page. Blank input creates no state. Its Profile button changes the Browser Runtime default new-window Profile when AndroidX Multi-Profile is available, uses open-eye normal and closed-eye incognito icons, and shows only a `1.2s` bottom status message. `BrowserAddressResolver` resolves a submitted address or query with the selected engine, `BrowserPresentationCoordinator.openUrlInNewSession` creates and activates a new shared WebSession with that Profile, and the Shell then enters Browser Home with Software Home as its return target. Only normal-mode searches are written to the `WebSessionHistoryStore` observed by Browser Home. The AI segment resets navigation to the AI Chat root and registers a focus request; pager settlement marks it ready, after which the active classic or agent input requests focus, shows the IME, and consumes the request exactly once. The Software Home attachment quick action uses the same `Icons.Default.Add` glyph and `24dp` size as the default Agent input. Attachment, voice, and camera use the same one-shot channel and delegate to the existing `ChatViewModel` attachment state, input microphone launcher, or `AttachmentSelector` camera launcher.
- Settings Home uses the fixed legacy single-column layout: a four-action header followed by four borderless white cards containing `4/4/4/4` entries. Its first row enters the unique AI Settings root with `KIYORI_SETTINGS` return semantics; `网页浏览器` opens Browser Settings; `文件下载器` opens Download Settings directly; all other rows and header actions remain inert until their own verified implementation milestone. Browser Settings and Download Settings share the Settings Detail Surface, including borderless group cards and the same continuous expanded-to-pinned title motion. The Software Home fifth destination and the browser menu's fourth-row Settings action share the full hexagonal gear derived from the fixed legacy `icons/设置-齿轮` asset. File Management Home uses the fixed legacy category, quick-access, and storage sections and refreshes its read-only phone-capacity label on host resume. The Minus-One Download card opens Download Center and observes its real task count; browser menu Download opens the shared compact Download Center drawer. Browser Settings preserves the reference page's `5/5/2/5/6` card groups. Custom home, external-app permission, geolocation permission, and floating-sniff preference are connected; placeholder navigation opens an empty page with the matching legacy title and placeholder toggles remain non-interactive. Tencent X5 remains a placeholder because Kiyori uses Android System WebView.
- Download Center is a Shell child opened by the Minus-One Download card, while Settings Home opens Download Settings directly. It uses one or two task-card columns according to width and partitions the same Kiyori-owned task snapshots into Downloading, Completed, and Failed. Its settings action opens a nested child, so Back returns to Download Center before returning to the original owner. Download Settings preserves the legacy `5/3/3/1` twelve-row structure. Default downloader, skip confirmation, completion tip, persisted SAF custom directory with an explicit restore-default action, `1..8` concurrent-task preference, `3/6/12/20/32` ordinary HTTP Range-thread preference, `3/8/16/20/32/48/64` M3U8 resource-thread preference, M3U8 automatic-package toggle, automatic public transfer, `12288/8192/4096/2048/1024/512/256 KiB` chunk-size selection, APK auto-clean, and `HTTP/2` versus `HTTP/1.1` protocol selection are connected to real consumers. Changing ordinary or M3U8 threads updates the same settings owner and synchronously narrows the allowed concurrent-task range through `128 / max(normalThreads, m3u8Threads)` capped at `8`; changing automatic packaging, public transfer, chunk size, or protocol updates only the settings frozen into subsequently created tasks. The selection sheet uses compact `13dp/10dp/44dp/20dp` header, option, minimum-row, and check-icon metrics. Already running or persisted tasks retain their frozen values. Completed internal tasks expose rename, suffix, move, source-link copy, saved-location copy, share, and public-directory transfer actions from the same manager record. System-owned tasks remain in Android's download UI rather than appearing as incomplete Kiyori records and do not use the SAF directory setting. Opening an internal APK with auto-clean enabled removes its task and file after `90s`.
- AI Home and every explicitly identified AI Navigation Root show the hamburger button, including roots opened by shortcuts, widgets, raw routes, or router-gateway requests. AI deep pages show Back until navigation reaches an explicit root. Browser, Mini App, File Management, and Kiyori Settings pages do not expose the drawer button.
- Host navigation roots match their registered route ID. ToolPkg plugin roots match both route ID and registered route arguments. Route arguments, stack depth, and instance-ID prefixes never establish root ownership.
- The drawer contains Packages, Permission Grant, Workflow, AI Dialogue, Assistant Configuration, Memory, Toolbox, ToolPkg dynamic destinations, and AI Settings. AI Dialogue returns to the existing AI Home without creating a conversation or clearing its draft.
- AI Home always renders the conversation surface and input controls, even when no usable model configuration or API key exists. Model configuration is opened as a separate settings route; missing credentials are reported when the user attempts model-dependent work, never by replacing or trapping the AI Home.
- The Permission Grant quick action opens `Screen.ShizukuCommands`, while AI Tool Authorization continues to use `ToolPermissionSystem`. The static Settings Home does not currently route to Permission Center or copy either persisted state.
- The Permission Grant quick action keeps the short Permission label and Operit quick-card treatment.
- Conversation history, new-chat, search, and delete actions remain in the original AI Home history selector. They are not duplicated in the drawer.
- The Terminal button remains in the upper-right AI Home toolbar during the product-shell migration. This plan does not add another Terminal entry.
- Opening the Modal AI Drawer never translates, scales, tilts, rounds, shadows, fades, or otherwise transforms the page below it. The page continues rendering but cannot receive touch while the drawer is visible.
- The Modal AI Drawer follows the shared Kiyori theme tokens. Dedicated drawer glass, background-color, and accent-color preferences are not restored.
- Back first closes an open drawer. Back from an AI Top-Level Page returns to AI Home, and Back from a deep AI page returns to its owning top-level page. Back from AI Home or Minus-One Page returns to Software Home; Back at a non-Software root returns to Software Home; Back at the center Software Home requests exit confirmation.
- Each primary destination retains its own child stack and scroll state while the user switches roots.
- Native AI roots use stable host instances. Every ToolPkg root entry creates a new route instance; only a ToolPkg route declaring `keepAlive=true` retains its composition key and saved child stack across drawer switches.
- AI Settings retains one page composition, form state, scroll state, and persisted settings. Re-entry from the same source family may restore its child stack; crossing between the AI drawer family and Kiyori Settings always opens the AI Settings root so the visible Back contract matches the current source.
- The Modal AI Drawer is `75%` of window width below `600dp`, `320dp` from `600dp` through `839dp`, and `360dp` from `840dp`. A separating hinge caps it to the left physical region. Window-size and fold-posture changes preserve the current route, form state, scroll state, and AI Home lifecycle.
- Detailed ownership, gesture, adaptive-layout, and migration rules are defined in `docs/doc-src/architecture/kiyori_product_shell_and_navigation.md`.

## System bar contract

- The Kiyori App Shell uses one edge-to-edge status-bar policy for Software Home, Minus-One Page, AI Home, all five primary destinations, and AI pages. Page backgrounds paint to the physical top edge. The Modal AI Drawer's full-window scrim follows that policy, while the drawer panel is an explicit exception whose top edge starts at the status-bar bottom; panel content applies only horizontal and bottom safe insets.
- The status bar is transparent whenever it is visible, and platform contrast scrims are disabled where the Android API supports that control. Status-bar icon brightness follows the actual foreground surface presented by the Kiyori Shell.
- The inherited transparent-status-bar and custom-status-bar-color controls and persisted preferences do not exist in Kiyori. The user may still hide or show the status bar.

## Settings ownership

- Kiyori system settings own application language, product-wide appearance, storage, downloads, notifications, privacy, shared permissions, browser, player, reader, file management, and other cross-product behavior.
- AI Settings own model providers, model routing, prompts, personas, AI memory and context, AI tool authorization, MCP, Skill, ToolPkg, workflows, conversation policy, and AI usage information.
- A setting has one owner and one persisted source of truth. Other pages may deep-link to that owner but do not duplicate its state.
- `WebSessionBrowserSettingsStore` owns the browser home URL, webpage external-app policy, webpage geolocation policy, and floating-sniff preference. `StandardBrowserSessionTools` consumes the first three in the existing active WebView request path; the floating-sniff preference is reserved for the later media-candidate/player consumer and does not claim that sniffing exists before that milestone.
- Permission Center is a coordination surface, not another settings owner. Device-capability controls remain in Kiyori system security settings, and AI tool policy remains in the existing Tool Permission destination backed by `ToolPermissionSystem`.
- Permission Center groups High-Impact Action policy and AI Operation Records under one AI Security section. Neither entry is shown until its complete policy or record page exists.
- Backup, conversation-data management, token statistics, and the Toolbox utility that changes permissions of other installed applications are not Permission Center domains.

## AI action authorization

- Risk is assigned to a concrete command and its target, scope, reversibility, data sensitivity, and external impact. A tool name alone never determines risk.
- **R0 Read-Only** operations do not change local or external state and need no operation confirmation after the tool gate permits them.
- **R1 Low-Impact** operations are local, bounded, and easy to reverse or stop. Persistent tool authorization may permit them without per-operation confirmation.
- **R2 High-Impact** operations change persistent state, access sensitive data, affect multiple objects, or prepare external impact. They require one-time confirmation by default; an explicit session grant is allowed only for a fixed target and scope.
- **R3 Critical** operations are difficult to reverse, privileged, financial, account-sensitive, or create an external action that cannot be recalled. Every operation requires confirmation; session and persistent bypass are prohibited.
- `FORBID`, `ASK`, and `ALLOW` control whether a tool may be invoked. The R0-R3 contract separately controls whether the concrete operation may produce side effects. `ALLOW` cannot bypass R2 or R3 confirmation.
- When `ASK` and an R2 or R3 confirmation apply to the same command, Kiyori presents one combined authorization decision rather than consecutive prompts.

## Distribution contract

- This private development build does not check the Operit release channel or receive Operit remote announcements.
- User-facing project, help, issue, and release links must use the Kiyori repository unless a feature explicitly documents a third-party service.
- Updates are distributed deliberately from the Kiyori repository. The application does not perform automatic or manual in-app update checks at this stage.

## Compatibility boundary

The following names are implementation or interoperability identifiers, not the Kiyori brand, and are not renamed by a visual-brand migration:

- the source namespace `com.ai.assistance.operit`;
- the `operit://` OAuth callback and other externally consumed URI schemes;
- persisted database, preference, backup, workspace, plugin, ToolPkg, MCP, Intent action, and file-format identifiers;
- `.operit/config.json`, `com.operit.*` ToolPkg IDs, `remote_operit`, `operit-pc-agent` filenames and directories, and `OPERIT_*` environment variables;
- attribution, license history, source references, and upstream documentation that must continue to identify Operit accurately.

Changing one of these identifiers requires a separate compatibility design and migration plan.

Kiyori's user-visible `versionName` and the **Operit Market Compatibility Version** are independent version axes. `versionName` identifies the Kiyori product release. `BuildConfig.OPERIT_MARKET_COMPAT_VERSION` is a non-user-facing semantic version that identifies the inherited Operit script and ToolPkg runtime contract used for market `minAppVer` and `maxAppVer` checks. Its current value is `1.12.0+4`, matching the Operit source compatibility baseline; it changes only when Kiyori adopts a different market runtime contract.

## Development identity and migration

- The continuous-development branch is `main`; parent and `terminal` remotes publish Kiyori changes only to their respective `main` branches.
- The `terminal` directory is the `KiyoriTerminalCore` submodule and is pinned by a parent gitlink.
- `com.kiyori` is a new Android application identity. It cannot in-place upgrade `com.ai.assistance.operit`; users must export and import supported backups.
- Kiyori creates public runtime data under `Download/Kiyori`. An old Operit backup may be selected through an explicit import flow, but Kiyori does not automatically scan, merge, migrate, or delete `Download/Operit`.
- Current-app sandbox references use `/data/data/com.kiyori`; source namespaces and external action or provider contracts continue using their established compatibility identifiers.
- Terminal user-visible surfaces use Kiyori, including the Ubuntu welcome banner, file-provider title, and generated package-source comments. Terminal keeps `installed-rootfs/ubuntu`, `.operit_installed_ok`, its existing internal mount variables, and native filenames.
- The terminal Node.js environment is ready only when `node`, `pnpm`, and `tsc` all execute successfully. The setup uses npm's existing global bin so visible and hidden Ubuntu sessions share one PATH contract.
- Inherited backup formats, market wire types, plugin IDs, ToolPkg IDs, MCP IDs, namespaces, and protocol identifiers remain interoperability boundaries even when visible text says Kiyori.
- Root JavaScript metadata is private development tooling (`kiyori-tooling`), not a runtime package or public npm contract.
