# Kiyori shared context

This file defines the stable product language and compatibility boundaries for this repository.
Current work status and implementation notes belong in `docs/TODO/`.

## Product identity

- **Kiyori** is the brand.
- **Kiyori** is the Android application and user-visible product name.
- **Kiyori** is the repository and Gradle root-project name.
- The project repository is `https://github.com/Kiyori-CN/Kiyori`.
- The Android application ID is `com.kiyori`.
- Android system surfaces, the default assistant persona, Kiyori-owned file-provider titles, WebChat, generated workspace display text, and Kiyori-owned companion UI use the Kiyori brand.

## Product position and ownership

- **Kiyori** is an all-purpose browser powered by Operit AI. Web access and content handling are the product center; video, music, reading, downloads, files, ad blocking, and later content capabilities are browser-owned domains.
- **Operit AI** is Kiyori's embedded AI subsystem. It owns AI conversation and AI-specific runtime capabilities, but it does not own the Kiyori application shell, global navigation, product identity, or system-wide settings.
- Every Kiyori capability may provide a human-facing page and an AI-facing capability contract. AI integrations call those contracts instead of directly driving Activities, Composables, or ViewModels.
- Kiyori has never had a user-facing release. The inherited Operit navigation drawer is not a published Kiyori interface, so the product-shell migration removes that design instead of maintaining a parallel legacy route.

## UI design sources

- **Kiyori Professional Browser Theme** owns two visual domains. The application accent domain uses Material Blue 600 `#1E88E5` and low-saturation blue-gray `#536D79` semantics across AI, settings, shared controls, and App Shell selection. The browser protection domain keeps Browser Home, browser chrome, Full-Screen Web Search, and browser child pages neutral. Software Home retains its fixed five-color search-frame border and fixed blue Search/AI selection; the three legacy-replica root pages retain their own fixed palettes. The theme does not use wallpaper dynamic color as a product default.
- **Operit Original UI** remains the visual-language authority for typography scale, shapes, component treatment, general icon behavior, dialogs, settings rows, glass effects, motion, and interaction density so AI and non-AI surfaces form one product. Browser Home, Minus-One Page, Settings Home, and their child pages must be compared against the current Operit source before UI implementation because these Kiyori surfaces directly reproduce Operit layouts and interactions. Kiyori-owned App Shell and browser chrome instead use the Legacy Kiyori outline Vector family. The inherited Operit purple palette and unconditional wallpaper dynamic color are intentional Kiyori product differences.
- **Legacy Kiyori Design Reference** is `Kiyori-CN/kiyori-android@24a2dfa91f0a4166dc58e5c4732d11861173f766`. It provides the page composition, navigation intent, browser behavior, and feature layout for Kiyori-owned surfaces.
- When the two sources differ, an accepted Kiyori product contract determines behavior, Operit Original UI determines visual treatment, and Legacy Kiyori Design Reference determines the Kiyori page's content structure.
- Source references are design and migration evidence, not runtime dependencies. New hard-coded visual systems must not be introduced beside the shared Kiyori theme.

## Product shell language

| Term | Definition |
| --- | --- |
| **Kiyori App Shell** | The Kiyori-owned root navigation, adaptive layout, window-inset, Back, and top-level state boundary. Operit AI is hosted inside this shell. |
| **Software Home** | The default center page shown after launch and the first of five primary destinations. It owns the three-page horizontal home space and uses one centered title-over-search column at the `<600dp`, `600-839dp`, and `>=840dp` width gates. On regular-height windows, the Search Frame top border is exactly `38.2%` of the available home height; short windows use the minimum top position that keeps the measured title visible. Compact, Medium, and Expanded cap content width at `544dp`, `584dp`, and `624dp`, with minimum horizontal padding of `24dp`, `48dp`, and `72dp`. |
| **Minus-One Page** | The page immediately left of Software Home. It is part of the home pager, hides the five-item bottom navigation, and reproduces the fixed legacy layout with four data cards and eight inert quick tools. Bookmark and Download observe their respective Browser Runtime counts and open the same shared drawers as Browser Menu; Collection and History remain zero-count placeholders. |
| **AI Home** | The full-screen Operit AI conversation page immediately right of Software Home. It hides the five-item bottom navigation, shares Software Home's pager state and fling physics, and has no edge-drawer gesture. |
| **Browser Runtime** | The single in-process WebSession state owner shared by Browser Home, the 1×1 background anchor, the minimized indicator, and Operit AI browser tools. The anchor and indicator own no tabs, navigation, downloads, or userscript state. |
| **WebSession Profile** | The immutable website-data boundary of a WebSession: `normal` uses the default WebView profile, while each live `incognito` window group shares one uniquely named Kiyori AndroidX WebKit Profile generation. Closing the last window retires that generation immediately; the next group uses a new generation, and the next cold start deletes all retired Kiyori Profiles before loading any of them. |
| **Browser Home** | The immersive Kiyori browser root. It hides the five-item Kiyori bottom navigation and presents the shared Browser Runtime through browser-owned top-bar search, full-screen search, normal/incognito window overview, fixed browser-menu drawer, draggable child drawers, and bottom-bar chrome. |
| **Browser Presentation Owner** | The exclusive host currently mounting the active browser WebView: either `APP_SHELL` or `BACKGROUND_ANCHOR`. `APP_SHELL` is the only complete visible browser UI; `BACKGROUND_ANCHOR` is a 1×1 invisible, non-touchable, non-focusable attach point used only when Browser Home is not mounted. Browser Home owns a one-shot App presentation lease, so an explicit exit followed by Compose disposal cannot release twice. Repeated requests for the current owner are no-ops. A real `APP_SHELL <-> BACKGROUND_ANCHOR` change removes the old WebView and background window, verifies a null parent, crosses one `Choreographer` frame, and only then attaches the same View to the requested host without navigation or reload. |
| **Player Runtime** | The single in-process `PlayerSession` and MPV core. It owns one immutable media request at a time, request headers, content file descriptor, playback/track/render state, and one explicit Surface lease state machine. A lease records the floating/fullscreen role, owner-instance token, monotonic generation, current and pending owner, native attach/detach state, transfer target, and one-shot fullscreen Activity launch/finish requests; Android `Surface` objects remain session-private. Fullscreen and browser-floating presentations transfer only the Surface and never reload media. The old owner must report `surfaceDestroyed`, then `PlayerSession` completes the single native detach before a pending target may attach. Both presentations use `PlayerSurfaceView`; browser floating is fixed full width, fixed `16:9`, zero side margins and square corners, initially attached to the browser bottom bar and movable only on the Y axis until its top edge reaches the browser top bar. Browser floating marks its Surface as a media overlay while the existing unique WebView retains its normal layer type. A new request creates and initializes the single mpv core before Android Surface callbacks. The first valid Surface is attached only after `mpv_initialize`; `loadfile` remains pending until that Surface lease completes native attach. This ordering matches the packaged mpvlibAndroid binding and the legacy Kiyori player. Decoder selection is the persisted mpv profile `fast/default/high-quality/gpu-hq/low-latency/sw-fast`; the unpublished default is `fast`. GPU Next selects `vo=gpu-next`, Vulkan selects `gpu-context=androidvk`, and both renderer switches apply when the unique mpv core is next created. Anime4K and playback speed begin from their stored value only when their independent memory switches are enabled. Volume enhancement raises mpv software volume to `150%` under a `300%` ceiling. The fullscreen control layer is the source-faithful `kiyori-android@24a2dfa9` layout and original drawable set. Its bounded `PlayerDebugLogBuffer` records player lifecycle, selected decoder and visible runtime errors without copying request headers. Its arm64 native stack contains non-overlapping mpv and FFmpegKit AARs plus the single `libc++_shared.so` produced with the same Clang toolchain as `libmpv.so`; build and APK gates verify the required C++ symbols before delivery. |
| **Browser Media Candidate** | Session-scoped evidence captured passively from the existing WebSession request path or a read-only DOM bridge. It preserves the browser-provided URL and actual request identity fields; MIME and URL shape are confidence evidence, never permission to rewrite or resolve another URL. |
| **Modal AI Drawer** | The Kiyori-owned, button-triggered left overlay that exposes AI top-level navigation without moving or rebuilding the page below it. Its scrim covers the window while its panel begins below the status bar. It has no edge or drag gesture. |
| **AI Top-Level Page** | AI Home, Packages, Permission Grant, Workflow, Assistant Configuration, Memory, Toolbox, a ToolPkg drawer destination, or AI Settings when entered from the Modal AI Drawer. Native roots retain independent state and child stacks; ToolPkg roots retain them only when their route declares `keepAlive=true`. |
| **AI Settings** | The one settings page and persisted state owned specifically by the AI subsystem. It is entered from the Modal AI Drawer or the first Settings Home row. Drawer entry returns to AI Home; Settings Home entry uses `RouteEntrySource.KIYORI_SETTINGS` and returns to Settings Home. Crossing source families opens the AI Settings root. |
| **AI Navigation Root** | An AI top-level route explicitly identified by its registered navigation-entry ID. Root ownership is stored on the route entry itself and is never inferred from route arguments, stack depth, or an instance-ID naming convention. |
| **Kiyori Edge-to-Edge Shell** | The window contract in which Kiyori-owned page backgrounds and the Modal AI Drawer scrim paint behind a transparent status bar. Interactive page content applies system insets, while the drawer panel itself starts below the status bar. |
| **Professional Browser Theme** | The Kiyori-owned default visual contract. Light mode uses `#FFFFFF` backgrounds, `#202124` primary content, application primary `#1E88E5`, and secondary `#536D79`; dark mode uses near-black backgrounds, layered gray surfaces, primary `#90CAF9`, and secondary `#B9CBD4`. Browser-owned surfaces replace those application accents with a fixed neutral ColorScheme. App Shell bottom navigation, browser bottom navigation, and the four-row browser menu use Kiyori-owned outline Vector assets; selection changes tint or container, never swaps to a filled icon. Software Home and the three legacy-replica roots use their explicit fixed page palettes. New installs and theme reset start in Kiyori light mode; system mode follows light/dark without wallpaper dynamic color. |
| **Permission Center** | A Kiyori system-level read-only overview and navigation destination that separates device capabilities from AI tool authorization. Its overview contains no direct permission switches and does not own another copy of either domain's persisted state. |
| **Device Capability Authorization** | Android and privileged-execution capabilities granted to Kiyori itself, including runtime permissions, file access, overlay, accessibility, battery exemption, Shizuku, Root, and debug capability. It is distinct from permission to invoke an AI tool. |
| **AI Tool Authorization** | The Operit AI policy that decides whether a registered tool is allowed, requires confirmation, or is forbidden. `ToolPermissionSystem` remains its single persisted source of truth. |
| **Software Home Search Frame** | The central same-background input surface, `114dp` high on regular windows and `96dp` in the short layout, with a fixed five-color `1dp` outline and no outer glow. Search/AI occupy one `120×32dp` rounded segmented control with equal halves, a center divider, clipped rounded press feedback, and fixed light/dark blue selection. The segments select the meaning and placeholder without navigating: Search opens Full-Screen Web Search when the frame is pressed, while AI enters the existing AI Home, preserves its conversation and draft, and requests focus for the real chat input after pager settlement. The saved mode survives return and configuration recreation; a cold launch starts in Search. The title ring is `18dp`. Attachment, voice, and camera remain immediate AI Home shortcuts. |
| **Software Home Weather** | The top-left location-derived city, current temperature, and WMO weather icon. Android location and `Geocoder` determine the city; Open-Meteo receives latitude/longitude for the current Celsius temperature and weather code. No unverified city or weather value is displayed or persisted. |
| **AI Home Quick Action** | A request-ID-bearing one-shot command from Software Home. It becomes consumable only after the shared pager settles on AI Home, then delegates input focus and IME display, attachment, microphone/fullscreen voice, or camera capture to the existing AI input owner and is consumed exactly once. |
| **Full-Screen Web Search** | The shared web-only search surface opened from the Software Home Search Frame or Browser Home top bar. It shares the browser search-engine owner and normal-mode recent records, requires a real normal/incognito Profile control, and represents normal with an open eye and incognito with a closed eye. The control is a borderless standard icon action; mode changes show only a short inverse-surface bottom message. Software Home always creates a new shared WebSession; Browser Home reuses the active tab only when its immutable Profile matches the selected Profile and otherwise creates a matching tab. It does not search bookmarks, browser history, files, mini apps, or AI conversations; those domains own their search pages. |
| **Settings Home** | The Kiyori-owned settings root reproduced from the fixed Legacy Kiyori reference. It renders four borderless white cards and sixteen entries with fixed page colors. `AI Settings` opens the existing AI-owned page, `网页浏览器` opens Browser Settings, and `文件下载器` opens Download Settings directly; the other rows and all four header actions remain inert and own no persisted state. |
| **Settings Detail Surface** | The shared visual shell for Kiyori-owned settings children. Group cards are borderless white surfaces. The root title is one continuously transformed text element: the first `72dp` of list scrolling moves it from the expanded `32dp / 60dp / 26sp` frame to the pinned `56dp / 16dp / 20sp` frame while the header content height contracts from `128dp` to `56dp`; the Back action and real status-bar inset remain fixed. Browser Settings uses `网页浏览器设置` and Download Settings uses `文件下载器设置`. |
| **File Management Home** | The Kiyori-owned file root reproduced from the fixed Legacy Kiyori reference. It renders eight categories, seven quick-access entries, and four storage locations with zero placeholder counts. The phone-storage row reads available and total bytes from the app's actual data volume on composition and host resume; every page action remains inert. |
| **Browser Settings** | The fixed Legacy Kiyori browser-settings page opened from Settings Home or the fourth browser-menu row. Its five cards preserve the legacy order and visual treatment. `WebSessionBrowserSettingsStore` is the one owner for the custom home URL, webpage external-app policy, webpage geolocation policy, and floating-sniff-playback preference; every other legacy row is an explicit inert placeholder until its reference implementation has a real Kiyori runtime consumer. |
| **Browser Download Runtime** | `BrowserDownloadManager` is the only persisted Kiyori browser-download task owner. Its JSON records feed one `StateFlow` snapshot projection shared by the browser and Shell presentations of one Download Drawer, Minus-One, and AI events. New and explicitly resumed tasks enter one global FIFO scheduler; the versioned `BrowserDownloadSettingsStore` exposes `1..8` concurrent-task options, freezes each new HTTP task's ordinary Range-thread preference `3/6/12/20/32` (default `6`), M3U8 concurrency `3/8/16/20/32/48/64`, automatic-package preference, automatic public-transfer preference, chunk size, HTTP protocol preference, and optional SAF target directory. The task limit is synchronously capped at `8` and narrowed by `128 / max(normalThreads, m3u8Threads)` when a higher thread setting is selected. Old records without the new network or transfer field retain ordinary HTTP semantics with `16 / false / false / 2048 KiB / HTTP2 enabled / non-package` defaults. Ordinary HTTP runs through one task-owned `BrowserDownloadTransport`: HEAD and exact `0-0` probing resolve metadata under the same five-attempt bounded retry policy as body and resource transfers, non-Range work uses one stream with the frozen buffer size, and Range plans use `max(chunkSize, 1 MiB)` parts under a Semaphore whose permit count is the smaller of the frozen ordinary preference and the size-derived segment capacity. `thread_count` remains the configured concurrency limit and is not rewritten to the number of parts. Every Range response must be `206` and match the requested bounds, probed total length, response-body length, and final part length; a failed attempt rolls back its file and progress before retry or failure. With automatic merge disabled, an M3U8 playlist is an ordinary file; with automatic merge enabled, up to four master levels select the highest `BANDWIDTH` variant, download `KEY`, `MAP`, and media resources under the frozen M3U8 semaphore, and rewrite a local `<playlist>.files/` companion directory. Confirmed offline packages remain in the application download directory and reject SAF/public transfer, while rename and delete keep the playlist and companion directory together. Ordinary internal downloads complete in the application download directory; automatic public transfer copies the finished file to `Download/Kiyori/browser/downloads/` and removes the application copy only after the public copy is complete. Process restoration converts interrupted and queued work to an explicit non-networking state until the user resumes it. A SAF write failure is a visible task failure and never changes the destination. A persisted tree permission is released only after the current setting and every retained task stop referencing that directory. The same settings owner stores `INTERNAL` or `SYSTEM`, skip-confirmation, completion-tip, and APK auto-clean policy. A confirmed `INTERNAL` request enters the JSON owner; a confirmed `SYSTEM` request is transferred directly to Android `DownloadManager` and remains absent from Kiyori task counts, progress, JSON state, SAF policy, and APK auto-clean. `blob:` and `data:` payloads remain internal because Android `DownloadManager` cannot own them. Completed Kiyori records can rename, change suffix, move to a SAF directory, copy the source URL or saved location, share the saved file, and transfer it to the public directory; moves delete the source only after a successful copy. Opening an internal APK schedules removal of its record and current file after `90s` when APK auto-clean is enabled. Path-based shares use `FileProvider`, while SAF shares retain their `content://` URI. All Kiyori task cards use one deletion confirmation dialog: deleting a record always removes its unreachable partial files, and each confirmation requires an explicit records-only or records-and-files choice; no deletion preference is persisted. |
| **Browser Network Log** | The current WebSession's in-memory request record captured by its existing Android WebView `shouldInterceptRequest` path. Each session keeps at most 500 entries and clears its own log on navigation or explicit user clear. Search and `all / video / audio / image / web / other` filters are presentation state. A cross-host marker is a factual host comparison, not an ad or failure verdict. Copy, download, external-open, and details actions use the recorded URL and existing browser/download owners. The log does not invent response status, response MIME, response bodies, blocking state, or playback capability, and its UI never reloads a resource for preview. |
| **Kiyori Capability API** | UI-independent contracts through which Operit AI observes and operates Kiyori browser, media, reader, file, download, and later domains. |
| **High-Impact AI Action** | An AI-requested operation with destructive, privacy, financial, external-communication, account, permission, or persistent-state impact. It requires explicit authorization and an inspectable operation record. |

## Navigation contract

- App launch opens the center Software Home page.
- The Software Home horizontal order is Minus-One Page, Software Home, then AI Home.
- All three home pages use one `PagerState` and one fling behavior. Movement follows the pointer, and a new reverse drag can cancel an unfinished fling; Shell state changes only after the pager settles.
- The five primary destinations are Software Home, Browser Home, Mini App Home, File Management Home, and Settings Home.
- The five-item bottom navigation is visible on Software Home, Mini App Home, File Management Home, and Settings Home. Browser Home is an immersive root with its own bottom bar; Minus-One Page, AI Home, Full-Screen Web Search, child pages, and immersive content pages also hide the Kiyori bottom navigation.
- The current browser presentation contract is `APP_SHELL <-> BACKGROUND_ANCHOR`. Only Browser Home mounts complete browser chrome, drawers, text-selection actions, and the browser floating player. Leaving Browser Home transfers the same active WebView to the fixed 1×1 background anchor when overlay permission already exists and shows the minimized indicator; tapping that indicator opens the existing `MainActivity` Browser Home. Browser Home activity keeps no empty background-anchor window, direct Browser Home entry does not pre-mount the anchor, and cross-ViewRoot transfer uses a detach/frame/attach transaction. Historical expanded-overlay, overlay Back, cutout, IME, and focusable-window clauses retained in older long-form records are superseded and are not current behavior.
- Browser Home is the only complete presentation of one Browser Runtime. Tabs, the active WebView, history, bookmarks, downloads, userscripts, and pending confirmations are never copied into the 1×1 background anchor or minimized indicator. Browser downloads retain the existing JSON records as their only persisted Kiyori task state, publish one snapshot `StateFlow`, and use a global FIFO scheduler. Each HTTP task freezes its selected ordinary Range concurrency, M3U8 concurrency, package/public-transfer policy, chunk size, protocol, and target directory when created; later settings changes do not alter its running plan. Internal dispatch enters `BrowserDownloadManager`; system dispatch gives Android `DownloadManager` complete ownership and never mirrors progress into Kiyori. Website data remains isolated by immutable WebSession Profile, normal sessions alone write shared search/browsing history, and Browser Home entered from AI Home returns to AI Home after releasing the App Shell presentation.
- Operit AI discovers human-created browser state through `browser_tabs list`. The list enumerates the same Browser Runtime used by Browser Home and the background anchor, exposes each stable `session_id`, `profile`, title, URL, index, and active state, and requires the intended tab to be selected before `browser_snapshot`, click, type, or navigation operations. `browser_tabs create` accepts `profile=normal|incognito`; omission uses the Browser Runtime default Profile. Incognito isolates website data, not Kiyori AI actions already authorized by the user.
- Browser Home's top bar is ordered Back, Search, and Refresh/Stop. The top-left action exits Browser Home according to its recorded Shell source; webpage history is owned by the bottom-bar Back and AI `browser_navigate_back`. Search opens the shared full-screen web search surface without recreating the active WebView. Its Profile control is always present; submission reuses the active tab only when the selected immutable Profile matches, and creates a matching shared WebSession otherwise. Engine selection and recent records remain browser-owned state. The bottom bar is ordered Back, Forward, Home, Tabs, and Browser Menu. Home navigates the active WebSession to the custom home URL, and human/AI new-tab creation uses the same URL. App Shell and browser bottom bars use five equal slots with `16dp` horizontal, `0dp` top, and `6dp` bottom padding, `44dp` circular targets, and `26dp` icons; the App Shell center icon is `25dp`. The browser window counter is a `20dp` square with a `1.75dp` outline. Browser Menu opens a content-sized four-row surface: its three five-column rows use `21dp` outline icons in `32dp` containers with `1dp` row spacing, while its fourth row directly distributes three `46×36dp` actions with `22dp` icons and no synthetic five-slot placeholders. History, bookmarks, downloads, userscripts, network logs, page source, and capability explanation pages open draggable child drawers. User-Agent is a direct modal action: opening it closes the menu and shows `Android / PC desktop / iPhone / Symbian Wap / custom global / custom website`. `WebSessionBrowserSettingsStore` owns the global mode, custom global value, and normalized-domain site rules. An explicit session UA has highest priority, then a matching site rule, then the global mode; applying any choice updates the same WebSession WebViews and reloads only the active page. The menu's Incognito action opens the real window overview, AI Dialogue returns to AI Home, and Exit Browser uses a power icon and removes the presentation layer while retaining sessions. The fourth-row Browser Settings button opens the same Shell child as Settings Home; App Shell presentation keeps the existing WebView mounted underneath, while overlay presentation first minimizes its focusable window and uses the explicit internal Kiyori Intent. The window overview has only normal/incognito selectors at the top, uses 2/3/4 columns, filters the one WebSession registry by immutable Profile, and displays `5:8` vertical in-memory thumbnails that fit the complete current WebView viewport without cropping. New and clear actions affect only the selected Profile. Unsupported Multi-Profile or failed cold-start private-profile cleanup disables incognito explicitly and never substitutes a normal window.
- Browser Network Log exits Browser Menu into the existing draggable child-drawer host. It projects only the active session's bounded request list, keeps search/filter/action-dialog state in the presentation, and clears only that session's network entries. A logged HTTP or HTTPS URL can be copied, handed to the current default Browser Download Runtime with the active Profile request identity, opened externally by explicit user action, or inspected without navigating/reloading the WebView. Response status, blocking and playback remain absent until their own runtime owners provide confirmed data and commands.
- Browser bookmarks remain part of the single Browser Runtime and persist through `WebSessionHistoryStore`. The existing `bookmarks_json` records retain backward-compatible defaults for stable ID, root folder, manual order, icon, and secret-space membership; `bookmark_folders_json` stores the folder tree in the same DataStore. The Browser Menu keeps the add-bookmark glyph fixed and changes only its label between Add Bookmark and Remove Bookmark. Adding opens a four-field editable draft populated from the active page; its folder picker lists `/` first, then uses manual sibling order for a depth-first tree with one indentation step per level. Removing affects only ordinary-space records for the normalized current URL, so the ordinary menu does not expose secret-space membership. The Bookmarks child drawer shares the Download Drawer's partial/expanded viewport owner and adds a dynamic folder title, bookmark search, clickable breadcrumbs, favicon rows, validated folder/bookmark mutations, manual drag ordering, versioned clipboard import/export, and ordinary/secret-space separation. Bookmark and Download menus use the same compact `40dp` option rows, anchored placement, and blocking scrim; centered edit, sort, confirmation, and action dialogs use one full-window scrim. Opening in the current tab or a new foreground/background tab always delegates to the existing WebSession registry.
- Software Home uses one centered single-column composition on phones, tablets, and landscape screens. Its top-left weather owner requests coarse/fine location only through the Android runtime permission flow, resolves `Address.locality`, and sends the resulting latitude/longitude to Open-Meteo for `temperature_2m` and `weather_code`; failures remain explicit icon states and never display invented or stale values. Open-Meteo's free endpoint is non-commercial and subject to its published limits and privacy terms, so commercial distribution requires a separately licensed provider decision. A successful weather tap searches `<city> weather` with the current browser engine in a new shared WebSession. The top-right count is published by the same `StandardBrowserSessionTools` projection used by Browser Home and AI tools; tapping it enters Browser Home and sets the original host route to `WebSessionBrowserSheetRoute.TABS`.
- Software Home's Search action opens Full-Screen Web Search above the existing home pager without rebuilding Software Home or AI Home. The input is focused on entry; Back closes an open search-engine panel before leaving the page. Blank input creates no state. Its Profile button changes the Browser Runtime default new-window Profile when AndroidX Multi-Profile is available, uses open-eye normal and closed-eye incognito icons, and shows only a `1.2s` bottom status message. `BrowserAddressResolver` resolves a submitted address or query with the selected engine, `BrowserPresentationCoordinator.openUrlInNewSession` creates and activates a new shared WebSession with that Profile, and the Shell then enters Browser Home with Software Home as its return target. Only normal-mode searches are written to the `WebSessionHistoryStore` observed by Browser Home. The AI segment resets navigation to the AI Chat root and registers a focus request; pager settlement marks it ready, after which the active classic or agent input requests focus, shows the IME, and consumes the request exactly once. The Software Home attachment quick action uses the same `Icons.Default.Add` glyph and `24dp` size as the default Agent input. Attachment, voice, and camera use the same one-shot channel and delegate to the existing `ChatViewModel` attachment state, input microphone launcher, or `AttachmentSelector` camera launcher.
- Settings Home uses the fixed legacy single-column layout: a four-action header followed by four borderless white cards containing `4/4/4/4` entries. Its first row enters the unique AI Settings root with `KIYORI_SETTINGS` return semantics; `网页浏览器` opens Browser Settings; `文件下载器` opens Download Settings directly; all other rows and header actions remain inert until their own verified implementation milestone. Browser Settings and Download Settings share the Settings Detail Surface, including borderless group cards and the same continuous expanded-to-pinned title motion. The Software Home fifth destination and the browser menu's fourth-row Settings action share the full hexagonal gear derived from the fixed legacy `icons/设置-齿轮` asset. File Management Home uses the fixed legacy category, quick-access, and storage sections and refreshes its read-only phone-capacity label on host resume. The Minus-One Bookmark and Download cards observe real ordinary-bookmark and task counts, then open the same shared drawers as Browser Menu. Browser Settings preserves the reference page's `5/5/2/5/6` card groups. Custom home, external-app permission, geolocation permission, and floating-sniff preference are connected; placeholder navigation opens an empty page with the matching legacy title and placeholder toggles remain non-interactive. Tencent X5 remains a placeholder because Kiyori uses Android System WebView.
- Download Drawer is a Shell-level presentation opened by the Minus-One Download card and a browser child-drawer presentation opened by browser-menu Download; both render the same content and manager snapshots. Its settings action closes the drawer and opens Download Settings, so Back returns to the drawer owner page rather than to a deleted full-screen center. Download Settings preserves the legacy `5/3/3/1` twelve-row structure. Default downloader, skip confirmation, completion tip, persisted SAF custom directory with an explicit restore-default action, `1..8` concurrent-task preference, `3/6/12/20/32` ordinary HTTP Range-thread preference, `3/8/16/20/32/48/64` M3U8 resource-thread preference, M3U8 automatic-package toggle, automatic public transfer, `12288/8192/4096/2048/1024/512/256 KiB` chunk-size selection, APK auto-clean, and `HTTP/2` versus `HTTP/1.1` protocol selection are connected to real consumers. Changing ordinary or M3U8 threads updates the same settings owner and synchronously narrows the allowed concurrent-task range through `128 / max(normalThreads, m3u8Threads)` capped at `8`; changing automatic packaging, public transfer, chunk size, or protocol updates only the settings frozen into subsequently created tasks. The selection sheet uses compact `13dp/10dp/44dp/20dp` header, option, minimum-row, and check-icon metrics. Already running or persisted tasks retain their frozen values. Completed internal tasks expose rename, suffix, move, source-link copy, saved-location copy, share, and public-directory transfer actions from the same manager record. System-owned tasks remain in Android's download UI rather than appearing as incomplete Kiyori records and do not use the SAF directory setting. Opening an internal APK with auto-clean enabled removes its task and file after `90s`. The shared Download Drawer keeps the existing draggable host but uses a dedicated two-tab projection: Completed shows only finished Kiyori tasks, while Downloading contains queued, connecting, downloading, paused, failed, and canceled tasks. Its sort, category, time, and batch-selection state are presentation-only. The compact tabs and indicator line reduce vertical whitespace, and the top menu uses an explicit full-window dismiss layer so tapping around its surface closes it. ## AI action authorization

- Risk is assigned to a concrete command and its target, scope, reversibility, data sensitivity, and external impact. A tool name alone never determines risk.
- **R0 Read-Only** operations do not change local or external state and need no operation confirmation after the tool gate permits them.
- **R1 Low-Impact** operations are local, bounded, and easy to reverse or stop. Persistent tool authorization may permit them without per-operation confirmation.
- **R2 High-Impact** operations change persistent state, access sensitive data, affect multiple objects, or prepare external impact. They require one-time confirmation by default; an explicit session grant is allowed only for a fixed target and scope.
- **R3 Critical** operations are difficult to reverse, privileged, financial, account-sensitive, or create an external action that cannot be recalled. Every operation requires confirmation; session and persistent bypass are prohibited.
- `FORBID`, `ASK`, and `ALLOW` control whether a tool may be invoked. The R0-R3 contract separately controls whether the concrete operation may produce side effects. `ALLOW` cannot bypass R2 or R3 confirmation.
- When `ASK` and an R2 or R3 confirmation apply to the same command, Kiyori presents one combined authorization decision rather than consecutive prompts.

## Compatibility boundary

The following names are implementation or interoperability identifiers, not the Kiyori brand, and are not renamed by a visual-brand migration:

- the source namespace `com.ai.assistance.operit`;
- the `operit://` OAuth callback and other externally consumed URI schemes;
- persisted database, preference, backup, workspace, plugin, ToolPkg, MCP, Intent action, and file-format identifiers;
- `.operit/config.json`, `com.operit.*` ToolPkg IDs, `remote_operit`, `operit-pc-agent` filenames and directories, and `OPERIT_*` environment variables;
- attribution, license history, source references, and upstream documentation that must continue to identify Operit accurately.

Changing one of these identifiers requires a separate compatibility design and migration plan.

Kiyori's user-visible `versionName` and the **Operit Market Compatibility Version** are independent version axes. `versionName` identifies the Kiyori product release. `BuildConfig.OPERIT_MARKET_COMPAT_VERSION` is a non-user-facing semantic version that identifies the inherited Operit script and ToolPkg runtime contract used for market `minAppVer` and `maxAppVer` checks. Its current value is `1.12.0+4`, matching the Operit source compatibility baseline; it changes only when Kiyori adopts a different market runtime contract.
