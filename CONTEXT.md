# Kiyori shared context

This file defines the stable product language and compatibility boundaries for this repository.
Current work status and implementation notes belong in `docs/TODO/`.

## Product identity

- **Kiyori** is the brand.
- **Kiyori** is the Android application and user-visible product name.
- **Kiyori** is the repository and Gradle root-project name.
- The project repository is `https://github.com/Kiyori-CN/Kiyori`.
- The Android application ID is `com.kiyori`.
- Android system surfaces, the default assistant persona, Kiyori-owned file-provider titles, WebChat, generated workspace display text, and Kiyori-owned companion UI use the Kiyori brand.

## Product position and ownership

- **Kiyori** is an all-purpose browser powered by Operit AI. Web access and content handling are the product center; video, music, reading, downloads, files, ad blocking, and later content capabilities are browser-owned domains.
- **Operit AI** is Kiyori's embedded AI subsystem. It owns AI conversation and AI-specific runtime capabilities, but it does not own the Kiyori application shell, global navigation, product identity, or system-wide settings.
- Operit AI conversation renders inline and block LaTeX through the existing JLaTeXMath path. Markdown code spans and fenced code blocks are opaque to every math delimiter, including `$`, `$$`, `\(`, `\)`, `\[`, and `\]`; block quotes remove one quote marker per line and recursively reuse the same block AST, so real display formulas inside quotes render while quoted code remains literal. Display formulas support top-level `\tag{...}` and `\tag*{...}` as separate right-aligned equation-number semantics; streaming does not expose an unfinished block as source text. `\boxed` and `\fbox` retain their existing syntax and metrics while using a fill-preserving frame implementation so framed and following glyphs remain solid.
- Every Kiyori capability may provide a human-facing page and an AI-facing capability contract. AI integrations call those contracts instead of directly driving Activities, Composables, or ViewModels.
- Kiyori has never had a user-facing release. The inherited Operit navigation drawer is not a published Kiyori interface, so the product-shell migration removes that design instead of maintaining a parallel legacy route.

## Architecture ownership transition

- `com.kiyori.capability` and `com.kiyori.integration.operit` are the only planned cross-root contract and adapter boundaries. Neither side may create a second Browser Runtime, PlayerSession, download owner, userscript repository, settings store, or other factual state owner.

## UI design sources

- **Kiyori Professional Browser Theme** owns the fixed application theme, the shared semantic-color vocabulary, and the browser protection domain. Material Blue 600 `#1E88E5` remains the primary action color, while `KiyoriSemanticTone` provides stable blue, green, purple, orange, red, cyan, and pink icon/container pairs for App Shell, settings, AI support pages, statuses, and browser content tools. The browser four-row menu additionally owns a presentation-only `WebSessionBrowserMenuTone` table with one stable light/dark icon-container pair for each of its 18 fixed actions; every pair is unique, child drawers and dialogs reuse the originating action identity, and the detected-media count badge reuses `FLOATING_SNIFFER`. `PLUGINS` is the approved low-saturation deep-plum identity: light `#5E3A8A / #EEE8F4`, dark `#CBB8E2 / #2D2238`. Plugin Center, Userscript Manager, detail, editor, and their primary plugin icons reuse that identity; error, success, warning, and update-risk indicators remain separate state semantics. Minus-One data cards reuse `ADD_BOOKMARK / BOOKMARKS / HISTORY / DOWNLOADS`, and its eight inert quick tools each select a different existing browser identity pair instead of defining another palette owner. This browser-local identity table does not add global semantic meanings, persisted state, user color preferences, or a second application theme owner. The five closed App Shell navigation icons use the exact selected fill `#FFC153`; selection removes the blue outline, preserves page-background details, compensates each vector's visible bounds to match the original outline size, and replays a compression-to-spring-growth animation on every click, including a repeated click on the current destination. Home, Browser, Mini App, and Files use a lower damping ratio for a slightly larger yellow peak, while Settings retains the prior peak and all five destinations retain their prior settled sizes. The clear-weather sun is independent: `#C57C00` in light mode and `#FFD166` in dark mode. Neither color contract participates in stable entry-ID tone hashing. Large surfaces and text remain neutral. Browser Home, browser chrome, Full-Screen Web Search, and browser child-page surfaces stay neutral, while drawer tools may use small semantic icon badges without tinting the chrome or webpage. Software Home retains its fixed five-color search-frame border and fixed blue Search/AI selection. The theme does not use wallpaper dynamic color as a product default.
- **Operit Original UI** remains the visual-language authority for typography scale, shapes, component treatment, general icon behavior, dialogs, settings rows, glass effects, motion, and interaction density so AI and non-AI surfaces form one product. Browser Home, Minus-One Page, Settings Home, and their child pages must be compared against the current Operit source before UI implementation because these Kiyori surfaces directly reproduce Operit layouts and interactions. Kiyori-owned App Shell and browser chrome instead use the Legacy Kiyori outline Vector family. The inherited Operit purple palette and unconditional wallpaper dynamic color are intentional Kiyori product differences.
- **Legacy Kiyori Design Reference** is `Kiyori-CN/kiyori-android@24a2dfa91f0a4166dc58e5c4732d11861173f766`. It provides the page composition, navigation intent, browser behavior, and feature layout for Kiyori-owned surfaces.
- When the two sources differ, an accepted Kiyori product contract determines behavior, Operit Original UI determines visual treatment, and Legacy Kiyori Design Reference determines the Kiyori page's content structure.
- Source references are design and migration evidence, not runtime dependencies. New hard-coded visual systems must not be introduced beside the shared Kiyori theme.

## Product shell language

| Term | Definition |
| --- | --- |
| **Kiyori App Shell** | The Kiyori-owned root navigation, adaptive layout, window-inset, Back, and top-level state boundary. Operit AI is hosted inside this shell. Its five-item bottom navigation keeps the original outline vectors while unselected; the selected icon has no blue outline or selection container, and is rendered as a theme-aware warm-yellow fill with the original line details redrawn in the current page background color. While the home Pager is being dragged from Minus-One or AI Home toward Software Home, bottom-navigation visibility follows the live Pager offset instead of waiting for the settled `softwareHomePage`; stationary non-center pages and non-root AI routes still keep it absent. |
| **Software Home** | The default center page shown after launch and the first of five primary destinations. It owns the three-page horizontal home space and uses one centered title-over-search column at the `<600dp`, `600-839dp`, and `>=840dp` width gates. On regular-height windows, the Search Frame top border is exactly `38.2%` of the available home height; short windows use the minimum top position that keeps the measured title visible. Compact, Medium, and Expanded cap content width at `544dp`, `584dp`, and `624dp`, with minimum horizontal padding of `24dp`, `48dp`, and `72dp`. |
| **Minus-One Page** | The page immediately left of Software Home. It is part of the home pager, hides the five-item bottom navigation, and reproduces the fixed legacy layout with four data cards and eight inert quick tools. Collection, Bookmark, History, and Download reuse the Browser Menu identities `ADD_BOOKMARK / BOOKMARKS / HISTORY / DOWNLOADS`; the eight quick tools use eight different existing browser identities. Bookmark, History, and Download observe their respective Browser Runtime counts and open the same shared drawers as Browser Menu. Collection remains a zero-count inert placeholder reserved for the future Mini App service and must not be routed to browser bookmarks or another current owner. |
| **AI Home** | The full-screen Operit AI conversation page immediately right of Software Home. It hides the five-item bottom navigation, shares Software Home's pager state and fling physics, and has no edge-drawer gesture. Its top-right Browser, Terminal, and Workspace actions use stable blue, cyan, and purple icon colors; the two toggle actions add only their low-saturation semantic container while active. |
| **Browser Runtime** | The single in-process WebSession state owner shared by Browser Home, the 1×1 background anchor, the minimized indicator, and Operit AI browser tools. The anchor and indicator own no tabs, navigation, downloads, or userscript state. |
| **Page Source Workbench** | The Browser Menu's status-bar-safe full-screen native editor for the active WebSession's live DOM snapshot. It preserves the document type, excludes Kiyori-owned selection UI, and binds the editable baseline to one session and one in-memory Document token. Minified HTML, inline scripts, and long attributes use visual soft wrapping by default without inserting source characters; explicit horizontal browsing remains available and always opens at the document's top-left origin instead of following a stale caret at the end of a long line. Long-line analysis, line navigation, cursor/selection status, search/replace, accurately enabled undo/redo, formatting, copy, reload, diff review, retained process-local edits, and confirmed application all operate on one `NativeCodeEditor` buffer and history. The long-line information surface has a right-side close action whose visibility state is local to the current session and Document token; dismissing it does not mutate source text, wrapping policy, or statistics. Applying rebuilds the same Document with `document.open/write/close`, refreshes the shared runtime helpers and userscript state, and creates no second WebView, navigation entry, network-source archive, or persisted page copy. Refreshing or navigating reloads site content. AI reads the same live or editor source through `browser_page_source`; user confirmation remains required for the workbench Apply action. |
| **Browser Plugin Center** | The draggable Browser Menu child drawer opened by the browser's Plugin button. It projects browser-plugin providers into overview/search/add actions without owning another registry. Its overview has provider-level `This Page / Installed` sections; userscript rows appear only inside the Userscript Manager workbench, never again under the provider card. The built-in Userscript Manager workbench has `This Page / Installed / Updates / Logs`, compact multi-selection, script details, explicit safe-versus-risky update review, and a browser-hosted full-screen native source editor. The Plugin button and every primary plugin/script icon in those child surfaces use the same low-saturation `PLUGINS` deep-plum identity; availability, runtime error, success, warning, and update-risk state indicators retain their independent state colors. The top-right Add menu contains New/URL/Local actions and verified plugin-library sources. Logs open detail on tap, copy on long press, and expose full-report copy/export actions. The editor uses a status-bar-safe 44dp header and one bottom control layer at a time. Private drafts, immutable revisions, transaction journals, logs, values, source and dependencies remain owned by the single userscript repository/runtime. This surface is unrelated to AI ToolPkg, Skill, MCP, workflow, or package management. |
| **WebSession Profile** | The immutable website-data boundary of a WebSession: `normal` uses the default WebView profile, while each live `incognito` window group shares one uniquely named Kiyori AndroidX WebKit Profile generation. Closing the last window retires that generation immediately; the next group uses a new generation, and the next cold start deletes all retired Kiyori Profiles before loading any of them. |
| **Browser Home** | The immersive Kiyori browser root. It hides the five-item Kiyori bottom navigation and presents the shared Browser Runtime through browser-owned top-bar search, full-screen search, normal/incognito window overview, fixed browser-menu drawer, draggable child drawers, and bottom-bar chrome. |
| **Browser Presentation Owner** | The exclusive host currently mounting the active browser WebView: `APP_SHELL`, `BACKGROUND_ANCHOR`, or no presentation owner while the WebView remains session-owned and detached. `APP_SHELL` is the only complete visible browser UI; `BACKGROUND_ANCHOR` is a 1×1 invisible, non-touchable, non-focusable attach point used only for an explicitly minimized browser or an AI-activated browser while Browser Home is not mounted. Browser Home owns a one-shot App presentation lease whose terminal mode is `DETACH`, `MINIMIZE`, or `DESTROY`: Compose reconstruction detaches without showing an indicator, AI round trips minimize, and normal user exit destroys only the presentation host. An explicit exit followed by Compose disposal cannot release twice. Repeated requests for the current owner are no-ops. A real `APP_SHELL <-> BACKGROUND_ANCHOR` change removes the old WebView and background window, verifies a null parent, crosses one `Choreographer` frame, and only then attaches the same View to the requested host without navigation or reload. |
| **Player Runtime** | The main process owns one `PlayerSession`, while the non-exported `:player` process owns the single MPV core. Together they own one immutable media request at a time, in-memory request headers, content file descriptor, playback/track/render state, and one explicit Surface lease state machine. A lease records the floating/fullscreen role, owner-instance token, monotonic generation, current and pending owner, native attach/detach state, transfer target, and one-shot fullscreen Activity launch/finish requests; Android `Surface` objects remain session-private. Fullscreen and browser-floating presentations transfer only the Surface and never reload media. The old owner must report `surfaceDestroyed`, then `PlayerSession` completes the single native detach before a pending target may attach. Both presentations use `PlayerSurfaceView`; browser floating is fixed full width, fixed `16:9`, zero side margins and square corners, initially attached to the browser bottom bar and movable only on the Y axis until its top edge reaches the browser top bar. Browser floating marks its Surface as a media overlay while the existing unique WebView retains its normal layer type. A new request creates and initializes the single mpv core before Android Surface callbacks. The first valid Surface is attached only after `mpv_initialize`; `loadfile` remains pending until that Surface lease completes native attach. This ordering matches the packaged mpvlibAndroid binding and the legacy Kiyori player. Decoder selection is the persisted mpv profile `fast/default/high-quality/gpu-hq/low-latency/sw-fast`; the unpublished default is `fast`. GPU Next selects `vo=gpu-next`, Vulkan selects `gpu-context=androidvk`, and both renderer switches apply when the unique mpv core is next created. Anime4K and playback speed begin from their stored value only when their independent memory switches are enabled. Volume enhancement raises mpv software volume to `150%` under a `300%` ceiling. The fullscreen control layer is the source-faithful `kiyori-android@24a2dfa9` layout and original drawable set. Its top status columns always expose value and unit/time as two single lines with identical `10sp` size, `11sp` line height and bold weight; the subtitle, danmaku, audio and aspect buttons keep their outer positions while rendering `24dp` icons. Its bounded `PlayerDebugLogBuffer` merges main-process lifecycle with `:player` command, MPV verbose, file-event and error records through the existing ordered AIDL callback. Each entry receives severity, stable sequence ID and one or more write-time diagnostic topics. The viewer polls the buffer revision at a bounded cadence, renders structured entries newest-first in a lazy list, and exposes one non-wrapping horizontal strip for all, error, warning-and-error, network/loading, playback, Surface/render, track/subtitle and runtime/MPV views. Header close and footer clear/copy/export stay outside the weighted log viewport; clear requires a second tap. Copy and export build a chronological full diagnostic report from the current view. ## AI action authorization

- Risk is assigned to a concrete command and its target, scope, reversibility, data sensitivity, and external impact. A tool name alone never determines risk.
- **R0 Read-Only** operations do not change local or external state and need no operation confirmation after the tool gate permits them.
- **R1 Low-Impact** operations are local, bounded, and easy to reverse or stop. Persistent tool authorization may permit them without per-operation confirmation.
- **R2 High-Impact** operations change persistent state, access sensitive data, affect multiple objects, or prepare external impact. They require one-time confirmation by default; an explicit session grant is allowed only for a fixed target and scope.
- **R3 Critical** operations are difficult to reverse, privileged, financial, account-sensitive, or create an external action that cannot be recalled. Every operation requires confirmation; session and persistent bypass are prohibited.
- `FORBID`, `ASK`, and `ALLOW` control whether a tool may be invoked. The R0-R3 contract separately controls whether the concrete operation may produce side effects. `ALLOW` cannot bypass R2 or R3 confirmation.
- When `ASK` and an R2 or R3 confirmation apply to the same command, Kiyori presents one combined authorization decision rather than consecutive prompts.
