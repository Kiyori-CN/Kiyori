# 首次使用

本指南适用于 Kiyori 开发版。可从本仓库的 [内测预发布](https://github.com/Kiyori-CN/Kiyori/releases/tag/v0.1.0-internal) 获取 Debug APK，或按 [构建指南](../doc-src/dev-core/BUILDING.md) 自行编译。项目尚未正式发行；安装前核对发布说明、下载日期与 SHA-256。

## 安装前

确认设备运行 Android 8.0 或更新系统，支持 `arm64-v8a`。保留足够空间安装 APK 和后续需要的终端、模型与下载内容。

旧 Operit 使用另一 application ID，不能由 Kiyori 直接覆盖。需要迁移时先导出备份，参阅 [隐私与数据](privacy_and_data.md)。相同 application ID 的不同签名构建也不能直接覆盖安装，处理前保留数据。

## 首次进入

1. 阅读四页产品介绍，了解浏览器、AI 与本地工作区。每页用四张卡片说明实际能力与入口，模型、语音和终端标注配置前提；窄屏和大字体自动单列，文字完整换行。左右滑动逐页翻页、上下滑动阅读，也可用底部按钮继续；只有主动点击“跳过介绍”才会跨过尚未读完的介绍，直接前往第五页协议。
2. 分别阅读用户协议与隐私政策，再决定是否确认。
3. 在权限页逐项选择需要的能力，也可以直接开始使用。处理所选权限后，返回引导查看实际状态；点击“继续处理下一项”才会打开下一个授权入口。“停止处理”仅停止后续请求，不撤销已授予的权限。
4. 后续通过 **设置 → 更多功能 → 权限管理** 查看真实状态并逐项处理。系统弹窗、受限设置按钮和身份验证由 Android/OEM 决定。

通过 **设置 → 更多功能** 最底部的独立 **使用引导 → 重新查看首次引导** 每次都从第一页重新阅读，不接续上次重看的页码；第一页返回或完成引导都会回到设置，不重置已有数据、协议同意或首启进度。重看时仍可主动处理所选权限，已授予的系统权限不会因退出而撤销。

无障碍、悬浮窗、Shizuku 等能力服务不同功能，不必为了普通浏览提前开启所有权限。

## 浏览网页

从底栏进入浏览器，使用搜索或网址输入访问网页。通过 **设置 → 网页浏览器 → 网页主页** 选择自定义网址或纯空白页。

- 使用书签与历史保存阅读线索。
- 普通网页导航主要留在当前窗口；明确新建窗口、配置主页的跨站跳转等行为按窗口规则处理。
- 根据需要开启普通窗口恢复、搜索结果恢复或恢复前询问；无痕窗口不保存启动恢复记录。
- 长按链接、图片或媒体查看对应操作；输入框沿用系统复制、粘贴和选区。
- 在网站配置中调整当前域名规则，广告与脚本另有总开关和详细设置。

## 配置 AI

进入软件首页右侧的 AI 首页，从模型配置入口选择供应商、协议、模型与端点，并填写自己的 API Key。多协议供应商需要显式选择协议，服务地址和认证方式以你所使用的服务商为准。

保存后发送一条简短消息确认配置。服务返回的认证、限流、提交未知或网络错误会显示为失败；记录错误类型再检查配置，不把重复发送视为无成本验证。

云服务可能按自身规则计费。模型、语音、搜索和远程工具可能使用不同配置，修改一个配置不意味着其他工具也已配置。

### 思考模式与连续工具调用

GPT-6 Astra 使用工具时请选择 **OpenAI Responses**，并开启思考模式。五档依次对应
`low / medium / high / xhigh / max`；该模型不支持关闭思考，Kiyori 会在发送前提示修正配置。
GPT-5.6 使用同样五档；GPT-5.4/5.5 的最高两档均对应服务端 `xhigh`。
GPT-4.1 等非思考模型不会自动收到思考参数。

OpenAI 显示的是服务实际返回的思考摘要，可能很短，也可能没有可见摘要；这不表示模型没有
推理。提高档位通常会增加等待时间和用量，不能用摘要长度判断真实思考量。
DeepSeek 的 Chat、Responses 和 Anthropic 协议使用同一档位选择，五档映射为
`low / high / max / max / max`，关闭开关会显式请求关闭。

对话统计中的缓存读取与写入来自供应商 usage；没有报告时不会显示为已命中。
Gemini 原生协议的 2.5 Flash/Flash-Lite 可以关闭思考；2.5 Pro 和 Gemini 3 相关模型不支持
真正关闭，应用会提示开启思考。五档会按模型支持范围映射，所以最高几档可能对应相同的服务端档位。
Claude 自适应模型会应用所选思考程度；Fable/Mythos 5 无法关闭，Opus 5 关闭时不能同时使用
自定义 xhigh/max。自定义模型参数可能优先于默认档位，请同时检查参数面板。

流式开关控制回答的交付方式，并不改变模型是否推理。部分 Qwen 模型只支持流式思考；若服务提示
此限制，请显式开启流式、关闭思考或选择支持该组合的模型，应用不会自动更换协议或重复发送。
本地 MNN/llama.cpp 关闭流式时在生成成功后统一返回正文；推理失败和取消分别显示对应状态。

稳定的系统提示、工具和历史前缀有助于复用缓存；编辑历史、压缩、切换模型或调整思考程度都可能
改变实际命中。缓存不会跳过真实文件读取和工具执行。

若提示提交状态未知，服务端可能已经开始生成。应用会保留可安全恢复的部分内容；只有具有
已知 response ID 且支持恢复的官方 Responses 请求会续接同一次生成。再次手动发送前先核对
已有工具结果，避免重复动作。服务端截断、过滤或损坏数据会显示失败，不把不完整回答标记为成功。

## 扩展与本地工作区

AI 菜单的“扩展 / 工具箱 / 工作流”分别管理包与工具入口。需要环境变量的包完成配置后再启用，详见 [扩展指南](extensions.md)。

文件管理入口共用文件管理器；Ubuntu 终端首次使用需要准备环境。代码运行器的命令和输出会出现在可见终端会话，安装工具和执行项目之前先确认目标工作目录。

## 出现问题时

先保存设备型号、Android 版本、Kiyori 版本或源码提交、操作步骤和实际错误。浏览器诊断与 AI 对话详情提供不同领域的证据；导出后检查私人内容，再通过 [Issues](https://github.com/Kiyori-CN/Kiyori/issues) 反馈。

## 查看对话记录与诊断

在“时间线”搜索错误、工具返回或正文，可查找整段聊天的已记录文本；空格分隔多个关键词。
“对话”查看和修订当前消息，“原始事件”检查事件 JSON。“备注”用于保存排障说明，不发送给 AI。
导出保存到 `Download/Kiyori/exports/conversation-audit`：Markdown 便于阅读，签名审计包便于验证和导入，
两种文件都不加密。工具箱的“应用运行日志”用于启动、网络与服务排障，与单次聊天审计互补。
