# 扩展与工具使用

Kiyori 内置 Operit AI 的脚本、ToolPkg、Skill 与 MCP 能力。应用页面中的“扩展”是用户入口，内部包名和协议标识用于准确调用，不应随展示名称替换。

## 配置流程

1. 在 AI 页打开左侧菜单，进入“扩展”。
2. 按类型查看脚本、插件、Skill 或 MCP，阅读用途与所需权限。
3. 填写包声明的环境变量和服务配置。需要环境变量的包首次安装默认关闭，配置后由你明确启用。
4. 回到 AI 页选择对应工具或运行入口，再执行一次范围明确的操作。

本地与远程服务、账户及权限相互独立。Key、Token 和 Cookie 不应复制到聊天或公开问题报告中。

普通脚本更新会先验证完整新文件，再替换旧安装。包名、来源或文件名冲突会明确报错；下载或验证失败保留旧版本。更新后如果提示“已安装，但需要配置”，请进入包的环境变量设置补齐必填项，再重新激活；无需重复下载。包标识发生兼容更名时，包专用凭据需要在新标识下重新配置。

## 工具箱中的 Shell

Shell 命令按当前权限设置执行，运行期间不能再次发送或重执行。可以继续编写下一条命令，当前命令完成后会保留新输入。

命令与结果保留在当前工具会话中，最多 100 条相同命令去重后的记录，不自动保存到磁盘。历史建议使用这些记录；清除历史不会撤销命令已产生的修改。

## 工具箱中的日志

日志导出会保存点击操作后取得的完整日志快照，结果路径保留到手动关闭。清除操作需要确认，只清当前应用日志；已经导出的文件和独立插件日志保留。应用继续运行会生成新日志，清除失败会保留提示以便重试。

## 导入与管理 Skill

在“扩展 → Skill”中选择仓库链接、ZIP 或手动输入。手动输入可以附带资源文件，导入完成后可在技能详情中查看目录内容与 `SKILL.md`。

- 技能名称必须对应技能根目录下的一个目录，不能包含路径分隔符或父目录跳转。已有同名目录不会被覆盖。
- 仓库或 ZIP 中有多个候选技能时，请使用具体技能目录的仓库链接，或准备只包含一个技能的 ZIP；不会任意选择第一个候选项。
- 导入失败时保留输入和错误提示。若提示目录已经生成但后续整理失败，请先刷新列表核对，避免重复导入。
- 删除技能会删除该技能目录及文件，操作前需要确认；符号链接的目标不会随技能目录一起删除。

## MCP 配置与安装

本地插件可以从仓库或 ZIP 导入，远程服务填写 HTTP(S) 地址与所需认证信息。配置编辑会等待保存结果；读取配置失败时保留原文件，并提供重新加载入口。同一配置被其他入口修改时，保存可能提示冲突，请核对后重新打开编辑。

安装会先准备完整的新目录，再替换旧安装；下载或解压失败时保留旧目录。若提示文件已发布但配置或清理未完成，请先刷新列表核对。安装与卸载失败后可在结果弹窗明确重试，ZIP 重试使用本次选中的文件。

自定义部署命令对应当前插件，加载失败时可以重新分析。运行中的部署不能再次启动或修改环境变量；失败后可以修改环境变量并明确重试。部署输出保留最近 2000 行，较早内容被省略时会有提示。

## 市场发布与失败处理

发布前可在确认框中滚动核对完整内容，提交期间不能再次发送或修改表单。Skill/MCP 的版本贡献者可以编辑描述和详情，名称与分类取决于条目编辑权限。

制品上传到 GitHub 后，市场登记仍可能失败。页面会保留资产地址；明确拒绝的请求可以使用“仅重试登记”，无需重新上传。若显示提交结果未确认，请先到市场管理核对，不要重复发布。同版本的已有资产只在内容完全相同时复用，不同内容需要新版本；取消不会删除已上传文件。

## Bilibili 工具包

内置“哔哩哔哩工具包”提供 16 项只读检索、导出与媒体处理工具。在 **扩展 → 插件** 配置 `BILIBILI_COOKIE`，再在 AI 抽屉 Media 分组启用 `bilibili`。Cookie 只由宿主使用，不交给脚本。

- 默认产物位于 `Download/Kiyori/Bilibili`，覆盖已有文件需要显式 `overwrite=true`。
- `bilibili_user full=true` 保留 user 摘要，并按上游实际返回提供 profile。
- 当前分段弹幕和 XML 均不是完整历史；`capture media=false` 不新建媒体目录，也不删除已有下载。
- 媒体请求不向 CDN 发送 Cookie；证书错误、风控与 HTTP 拒绝会明确报告。

工具与验收细节见 [Bilibili 专项](../TODO/bilibili_toolkit/index.md)。

## 办公文档套件

在“扩展 → 插件”启用“办公文档套件”后，工具箱中的“办公文档”提供“文件操作 / 存储管理 / 环境与帮助”三个页签。文件操作可从手机选择文件或输入 Ubuntu 内路径，再选择读取结构、严格校验、预览或转 PDF；复杂生成和编辑可直接在 AI 对话中提出要求。

“手机文件 / Ubuntu 文件”只决定输入在哪里，办公引擎始终运行在本机 Ubuntu。手机文件先复制到 Ubuntu 处理；预览和转换的输出位置可独立选择手机或 Ubuntu。切换文件来源会清空旧路径，避免把两种路径混用。手机侧的 `/storage/<卷标>/root/kiyori_office/` 可能是 Ubuntu rootfs 的映射位置，需要按设备实际配置核实；它不能直接当作 Ubuntu 内路径传入。

- 五份办公指引随插件分发。AI 可通过 `office_read_guide(format=core)` 与 `format=docx/xlsx/pptx/pdf` 按需读取，不需要先安装 Python 或手动导入 Skill。
- 环境分层安装：T1 提供基础文档库，T2 提供转换、PDF 转图与字体支持，T3 提供 LibreOffice。先查看计划，确认后在可见终端执行并复检；安装涉及下载与本地 Ubuntu 环境修改。
- Word 支持创建、模板填充、查找替换和表格等编辑，可设置论文所需的纸张、中文/西文字体、段落行距、缩进、标题分页约束及页眉页脚/页码域；具体格式仍以院校或出版方要求为准。
- 修改论文局部文字时优先查找替换；整段替换/删除遇到公式、域、书签等结构会说明原因并停止。模板填充支持嵌套表格和已有首页/偶数页页眉页脚，替换值中的 `{{...}}` 保持原文。目录、页码和引用仍需在 Word/LibreOffice 中刷新并预览，结构校验不能代替视觉检查。
- PPT 模板填充支持组合对象；外部模板的重名形状需要用索引定位。删除被其他页面或自定义放映引用的页面前，需在支持导航编辑的软件中移除或重定向引用，工具不会自动改变跳转意图。
- Excel 支持读写、区域格式与原生柱状/条形/折线/饼/散点图。同批写入时先写行矩阵，再由显式单元格覆盖，避免矩阵中的空值冲掉公式。
- PowerPoint 支持模板、幻灯片与形状操作，可用厘米坐标创建可编辑文本框、形状、表格与原生柱状/条形/折线/饼图，并设置页面尺寸、背景和备注。PDF 支持读取、页级操作、表单、加密及生成。
- AI 的办公预览会直接附加页面图像，可按页或局部区域查看公式、图片和图表细节；模型及当前配置须支持图像输入。结构报告只辅助定位，不能代替看图。
- 已有 Word 可按段落插入正文、三线表、原生公式、图片与可编辑图表，并定点替换公式、图片或更新图表数据。已有 PPT 可追加元素、调整图层和分组，设置表格/图表颜色、渐变、透明度、阴影、裁剪和线性图标，无需为局部修改重建整份文件。
- PPT 支持基础进入/退出动画、点击/同时/随后执行，以及淡化、推进、擦除等页面转场。PDF 与图片预览不播放动效，最终放映需在目标 PowerPoint/WPS 中确认；Morph、运动路径和任意复杂时间线编辑尚未支持。
- 默认产物位于 `Download/Kiyori/Office/`。多步处理可先保留在 Linux 工作区，最终再交付到 Android；现有输出的覆盖需要显式指定。
- 含公式的工作簿在全部编辑结束后重算，确认错误数与缺失缓存数均为 0。格式、图表或工作表保存会清除旧公式缓存，工具会提示重新计算。含图表、图片或 Excel Table 的工作表复制会明确拒绝，避免静默丢失对象。
- 文件操作只保留当前处理方式的主执行按钮，可填写预览页码（如 `1-3,8`，一次最多 8 页），输出设置按需展开。返回文件可打开或作为输入继续处理。严格校验失败显示具体问题代码与位置；结构通过后仍需查看预览图，确认中文、分页、页码域、图表和文字布局。

存储管理先扫描任务，再预览清理范围，最后确认。**清理临时**保留任务的 `out` 输出；**删除任务**包括该任务输出。预览后目录发生变化会拒绝旧计划，执行中的任务不允许清理。文件主要位于：

| 位置 | 内容与清理方式 |
| --- | --- |
| Ubuntu `~/kiyori_office/runtime`、`runtime.zip`、`unzip_runtime.py` | 程序文件，存储清理保留 |
| Ubuntu `~/kiyori_office/work/<task_id>/in`、`tmp`、`args-*.json` | 输入副本、中间文件与参数，可预览后清理临时 |
| Ubuntu `~/kiyori_office/work/<task_id>/out` | 输出文档与预览，删除整个任务才会删除 |
| Ubuntu `~/kiyori_office/control` | 管理调用参数，正常完成自动移除；超时或失败时按返回路径核实 |
| Android 默认 `Download/Kiyori/Office/` 或指定输出路径 | 已交付文件，不在 Ubuntu 清理范围，在文件管理中处理 |
| 自建的 `workspace/office_test/`、`preview_*`、测试 ZIP | 不在任务扫描范围，按实际创建路径在文件管理中核对后清理 |
| 宿主文件选择器暂存目录 | 导入副本；“移除本页导入副本”只删除本页记录的副本，原始文件保留 |

工作根目录以扫描返回值为准。超时或异常中断后，任务占用可能保留，页面显示暂不可清理；先核实终端进程与产物，目前不提供自动解锁。不要直接删除整个 `kiyori_office` 或 Ubuntu rootfs。环境检查只检测依赖；安装计划只展示命令，确认执行才下载和修改 Ubuntu。阅读指引不执行文档操作。

T4 探测使用实际的 `tesseract` / `xelatex` 二进制。中文 TeX 安装计划包含 `texlive-lang-chinese`，字体缓存和格式重建可能持续数分钟，无新输出不代表卡死。先查看进程与日志，不自动中断 apt/dpkg。Pandoc 使用环境检查中已注册的真实系统中文字体族；ReportLab 默认中文字体为 `STSong-Light`，两种字体来源不可混用。设备临时修改的 runtime 会被新版资源解压覆盖，长期修复应随插件源码分发。

当前尚不支持原生批注/修订、OCR、组合图表与数据透视编辑；含宏工作簿可保留宏编辑，但当前重算入口只支持 `.xlsx`。工具箱触控、Android 文件打开及 PRoot 引擎行为以 [办公套件专项](../TODO/office_document_suite/index.md) 的设备验收为准。

## 搜索与学术工具

OpenAI 搜索使用自己的包配置，不自动沿用当前聊天模型的端点或 Key。Brave 搜索及 arXiv、Crossref、PubMed、Semantic Scholar、OpenAlex 等工具分别遵循声明的接口、权限与限额。

配置后通过明确查询确认；设置中的兼容性探测可能调用付费服务，不在后台自动执行。相关契约见 [OpenAI 搜索](../doc-src/architecture/openai_hosted_web_search.md)。

## 编辑器与远程 Kiyori

内置平台编辑器包为 `kiyori_editor`，远程工具包为 `remote_kiyori`。远程连接使用目标 Kiyori 的 HTTP API 地址和访问令牌：

| 变量 | 用途 |
| --- | --- |
| `REMOTE_KIYORI_BASE_URL` | HTTP(S) 地址，支持 IPv4/IPv6 与路径前缀，未写端口时使用 8094 |
| `REMOTE_KIYORI_TOKEN` | 目标服务访问令牌 |
| `REMOTE_KIYORI_TIMEOUT_MS` | 调用超时配置 |

地址不带账号、查询串或片段。Windows 配套包为 `kiyori-pc-agent`，通过 `kiyori_pc_agent.bat` 启动。跨设备连通性与权限需要在目标环境验证，详见 [迁移与验收说明](../TODO/kiyori_extension_script_brand_migration/index.md)。

## 开发自己的扩展

脚本作者从 [脚本开发指南](../SCRIPT_DEV_GUIDE.md) 开始；ToolPkg 作者继续阅读 [格式指南](../TOOLPKG_FORMAT_GUIDE.md)。普通插件开发不要求修改 Android 主仓；只有新增宿主能力或内置资产时才进入主仓贡献流程。

## 工具测试

从 AI 抽屉打开工具箱中的工具测试，点击卡片可查看参数、完整返回和单项执行入口。批量测试会先列出范围，并真实访问网络、上传生成的测试文本和操作本次测试目录。系统设置、通知、定位、音量、点击与滑动只支持单项运行。

停止或离开页面会停止后续测试，已经发送的工具仍可能完成。结果显示“待核实”时先检查实际效果再重试。未完成清理的测试文件可通过清理用例处理；其参数会显示本次会话目录。
