# 网络、媒体与特权能力

本文适用于 Kiyori 开发版。完成首次使用后，可按需要配置应用代理、在线播放缓存与 Android 特权能力。

## 新建下载

在“下载”抽屉右上角点击“新增”，输入完整 HTTP(S) 链接，也可主动点击“粘贴链接”。长链接直接在输入框内编辑，无需另开弹窗。

“文件命名”默认收起，文件名从链接识别；需要改名时展开填写文件名或扩展名。留空即可沿用自动名称，修改扩展名不会转换文件格式。表单会显示保存位置，输入错误或创建失败时保留已填内容。

选择“内置下载器”后，在 Kiyori 下载列表中查看任务；M3U8 分段由内置下载器处理。选择“系统下载器”后，在 Android 系统下载管理中查看任务，系统下载器不合并 M3U8 分段。确认后点击“开始下载”。

## Shizuku 与应用日志

`super_admin:shell` 的特权能力依赖设备上正在运行并已向 Kiyori 授权的 Shizuku；它与
Ubuntu/proot 终端是不同执行面。权限页显示的是 Shizuku 实时服务、Binder 和授权状态，特权
命令只有在这些条件和执行器检查全部通过时才会报告成功，普通应用 UID 不会被伪装成 Shell/Root。
完整的执行路由、`am` Intent/广播参数合同、真机验收矩阵和日志迁移规则见
[`Shizuku 特权执行与日志命名迁移`](../TODO/kiyori_shizuku_privileged_execution_and_log_migration/index.md)。

应用主日志当前 owner 为 `files/logs/kiyori.log`。首次升级会把同目录旧
`operit.log` 的完整内容迁移到新文件并在写入确认后删除旧文件；namespace、协议、ToolPkg、
MCP、AIDL、native 和历史数据中的 `Operit` 标识仍按兼容合同保留。

## 在线播放缓存

“设置 → 视频播放器 → 在线播放缓存”由一个四选一策略控制：`省流模式 / 智能均衡 / 流畅优先 / 完整缓存`，新安装默认使用“智能均衡”。策略在打开下一条媒体时快照，播放中修改设置不会重载当前视频，也不会中途替换当前请求的缓存所有者。

“完整缓存”仍使用同一个 mpv 请求、同一组请求头和同一个播放内核。只有有限时长、完整可拖动、总大小已知且空间充足的 HTTP/HTTPS 直链视频才会使用应用私有会话磁盘缓存；HLS/DASH、直播、滚动 DVR、未知大小或空间不足的媒体会明确保持为不符合完整缓存资格，并继续使用该档内建的基础播放缓冲。切换视频、关闭播放器或播放器进程重新建立时会释放对应会话缓存；它不是离线下载，也不会创建第二个网络请求或本地媒体副本。

## 应用级网络代理

打开 **设置 → 更多功能 → 网络代理**。该设置统一控制 Kiyori 的 AI、网页、下载、播放器、
工具与在线服务请求；它不替其他应用建立代理。完整路由与失败语义见
[网络契约](../doc-src/contracts/network_proxy.md)。

### 导入订阅与启用

1. 进入“订阅管理”，选择添加订阅地址或导入订阅文件。
2. 支持 Clash/Mihomo 订阅、单文档 UTF-8 YAML、URI 节点列表和 Base64 节点列表；URI 支持
   VLESS、Hysteria2/Hy2、Trojan 与无插件 Shadowsocks。导入摘要分别显示不支持、拒绝与隔离项。
3. 核对可用节点和策略组。零可用节点、重复键、无有效出站或校验失败会拒绝导入；没有有效订阅时不能开启代理。
4. 返回主页，选择模式和节点，再开启应用内代理。首次从 URL 导入使用 Android 系统网络；
   已有代理启用时，订阅更新使用当前 Kiyori 路由，失败会明确显示。

订阅行点击切换当前订阅，行尾菜单可更新、编辑、复制或删除。复制只创建新条目，不切换当前订阅。
订阅地址、配置和控制凭据保存在设备绑定的加密私有目录，不应复制到公开反馈中。

### 模式、节点与规则

| 操作 | 含义与限制 |
| --- | --- |
| 规则 | 先匹配自定义规则，再匹配当前订阅规则；按规则选择直连、代理或拒绝 |
| 全局 | Kiyori 请求统一进入当前策略组 |
| 直连 | 绕过 Kiyori 内嵌代理；Android 系统 VPN 仍可能影响实际网络 |
| 节点选择 | 横向标签切换组，可搜索、整组测速、按默认/名称/延迟排序；自动策略组不提供手动选择 |
| 单节点测速 | 行尾按钮只测试该节点，未测速或失败节点在延迟排序中靠后 |
| 规则管理 | 可搜索与编辑；自定义规则独立保存，订阅更新会覆盖对订阅规则的编辑 |
| 脚本规则 | 为安装清单中的传统 JsEngine 包配置覆盖；不把 ToolPkg 当作传统脚本，也不手输未知包名 |

依赖外部 GeoSite/GeoIP/ASN 数据和远程 rule-provider 的内容不进入自包含运行配置，导入摘要会计数。
规则模式命中“直连”时，连接仍由内置核心转发；整个应用选择“直连”模式才绕过内置核心。
无法协调代理时，远程网页导航会显示失败；重新配置成功后可以继续。应用不会静默换节点或直连来掩盖该失败。

### 系统 VPN 与日志

检测到外部 VPN 后，内嵌代理默认拒绝启动；确需并存时在高级设置显式允许，此时 Kiyori 代理的
连接继续经过系统 VPN。外部工具只有本机代理端口、没有建立 Android VPN/TUN 时，Kiyori 不会自动发现或使用其私有配置。

“代理日志”保留当前进程最近 1000 条记录，可查看、复制、导出文本，或再次确认后清空。
日志先脱敏，不持久化完整订阅 YAML 或控制凭据；反馈前仍需审阅内容。应用运行日志、浏览器
网络日志、浏览器诊断和代理日志的用途不同，按实际出错领域选择证据。
排查对话断流时，代理日志中的 TCP 规则命中与出站链可以确认域名是否实际直连；请求失败记录还会
标明客户端是否取消及核心阶段。结合同次“对话详情”的请求编号与失败阶段判断，不能仅凭端口健康
或错误提示推断请求未发送，也不要在提交结果未知时反复重发。

真实订阅、Range/HLS 播放、VPN 并存与长期稳定性需要在目标设备验证，不能由一次测速或 APK 构建替代。
