# Kiyori Material 3 材质与表面规范

本规范定义用户选定的“实色表面、轻层次、少阴影”方案。适用于应用共用材质与本轮已接线的
AI 输入浮层、浏览器/文件菜单、共享底部抽屉、MCP 弹窗和设置/市场/工作流卡片。
阶段覆盖与验证见[全局视觉专项](../../TODO/kiyori_global_ui_visual_unification/index.md)。

## 表面层级

`KiyoriSurfaceTokens` 与 `kiyoriSurfaceColors()` 只派生当前 `MaterialTheme.colorScheme`，
不存储主题状态，也不新增独立调色板。语义彩色图标继续遵循[图标规范](kiyori_iconography.md)。

| 表面用途 | 颜色角色 | 材质与层次 |
| --- | --- | --- |
| 页面、顶底栏 | 原 background/surface | 实色、无额外阴影；白色浏览器与 AI chrome 保持原约定 |
| 普通阅读卡片 | surfaceContainerLow | 以留白与轻表面差异分组，默认不叠阴影 |
| 操作菜单、居中浮层 | surfaceContainerHigh | 不透明；需要浮起层次时使用 3dp 阴影，必要边界使用 0.5dp outlineVariant |
| 底部菜单和抽屉 | surfaceContainerLow | 菜单 3dp 轻阴影；共享拖动抽屉继续无额外阴影，以遮罩区分层级 |
| 模态遮罩 | scrim × 0.32 | 每个窗口只有一个绘制者；保留底层页面上下文 |
| 轻量弹出菜单遮罩 | scrim × 0.16 | 仅用于原本已有遮罩的轻量弹出菜单，不给所有菜单新增全屏遮罩 |
| 选中、错误、成功、警告 | 既有状态/语义色 | 小面积图标、文字、描边或容器表达；不通过厚阴影表达状态 |

阴影不代替表面层级。居中对话框不再用彩色外边框和同色分隔线包围正文，采用中性 outlineVariant；
功能身份仍由标题图标表达。系统 AlertDialog、媒体控件和未接线表面沿用各自 Material/媒体合同，
不能把本轮覆盖写成全部弹层均已真机验收。

## 圆角与反馈

- 复用 `KiyoriUiShapes`：control 12dp、field 14dp、card 16dp、dialog 20dp、sheet 顶部 16dp。
- 子容器、缩略图、拖动把手、进度条和胶囊有各自几何语义，不机械替换为同一圆角。
- 操作继续使用 Material 点击反馈与现有选中/禁用状态；用于拦截穿透的浮层底板保持无 ripple。
- 不改变命中区域、输入焦点、动画时序、抽屉展开能力或系统返回优先级。
- 文件双栏的轻内阴影用于标识活动位置，拖拽与媒体悬浮层用于表达空间关系，保留独立合同。

## 透明度与模态窗口

AI 的个人背景、透明输入区和媒体覆盖层继续由原偏好与所有者控制；它们不应把透明度传递给操作菜单。
输入设置和附件弹窗使用实色 popup 表面，确保背后的正文、图片不会干扰选项阅读。

自绘遮罩的 Dialog 调用 `KiyoriDialogOwnsScrim()` 或既有等效窗口设置，关闭系统 dim；
未自绘遮罩的普通 Dialog 保留系统遮罩。不能在所有窗口上统一关闭 dim，导致普通对话框失去模态层次。

承载底部抽屉、工具箱及文件操作菜单的全屏 Dialog 使用 `decorFitsSystemWindows = false`，
让自绘遮罩覆盖状态栏区域，避免窗口整体避让系统栏后留下顶部亮色条。抽屉内容继续由现有
状态栏高度约束、导航栏和键盘 Insets 处理安全区，不通过隐藏系统状态栏消除白条。

## 验证边界

自动检查覆盖：浅深 App/Browser 主题下阅读表面的 alpha 为 1、正文对比度至少 4.5:1、
遮罩为中性且保留上下文、现有文件/工具箱接线、精确主题消费者与最终 APK。
设备验收需覆盖文字与背景图片下的弹窗、深色层级、遮罩开合、系统返回、小屏/大字体和滚动；
构建通过不代表这些视觉与手势场景已经验收。
