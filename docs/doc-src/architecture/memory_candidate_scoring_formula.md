# 记忆候选检索与整理

本页描述 MemoryRepository 与 MemoryLibrary 的检索和整理边界。
产品分层与索引生命周期见[记忆与知识架构](memory_knowledge.md)，
实现和验收见[重构专项](../../TODO/memory_knowledge_refinement/index.md)。

## 查询范围

先限定空间、文件夹、记忆/知识类型、归档和创建时间，再进行候选排序。
普通 Agent 查询不返回归档，关系传播也不能带回范围外条目。
通配查询按 limit 浏览候选，不代表一次向模型发送全部数据库。

当前实现仍会读取空间或目录内的记录并在后台检索，不能描述为完全不扫描内存，
也没有大型服务端系统的规模验收证据。默认 UI 使用惰性列表，图谱最多构建前 200 项。

## 多路召回与排序

查询分词用于词法匹配，覆盖标题、正文、文档块和标签。
标签同时参与基础关键词匹配，因此标签额外权重为 0 不会让默认页面无法按标签查找。
文档块的 `a*b` 查询先按最长字面片段取得候选，再验证 a、b 的顺序与间隔。
关键词贡献采用排名衰减与覆盖增益：

```text
coverage = 1 + 0.6 * matchedTokenCount / totalTokenCount
keywordScore = importance * keywordWeight * coverage / (60 + rank)
```

标签、反向包含和语义贡献由现有 scoreMode 与权重控制，高级检索模拟展示各路贡献。
分数不是事实置信度或检索准确率。

语义检索对完整查询生成一次向量，避免每个关键词分别发起网络请求。
记忆查询按单次语义排名计算，不再采用旧版按关键词数量归一的描述。
只有模型身份、内容指纹和维度兼容的记录参与比较；服务或索引损坏显式失败。

关系传播从高分候选沿明确关联进行，形式为：

```text
propagated = sourceScore * linkWeight * edgeWeight + 0.03 * edgeWeight
```

合成后按阈值过滤并排序。自动提取使用有限候选；Agent 每次最多返回 100 项摘要及 UUID、
来源和更新时间，再按需读取完整内容。查询快照排除已返回条目，不是数据库历史快照。

## 整理与写回

自动提取协议保留 `main`、`new`、`update`、`merge`、`links`。
`user` 不是当前写回字段，用户档案只走 `update_user_profile` 工具。
无长期价值时返回空对象，不创建占位内容。

写回按合并、更新、主事件/实体、关联处理。合并原记录进入可恢复归档，保留原正文；
多个同名目标不能凭标题随意选择。旧记忆是线索，不能单凭相似度确认事实或建立关系。
自动分类只组织文件夹，不改变入库标准。

自动整理失败传回候选队列；关闭自动整理后不处理自动候选，手动指定的消息另行处理。
工具回显和思考痕迹不是长期事实，凭据处理复用既有脱敏器。
真实提取质量、重复/冲突处理和大库性能仍需实际样本与设备验收。
