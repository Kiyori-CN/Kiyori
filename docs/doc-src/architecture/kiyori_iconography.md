# Kiyori 图标用途与配色规范

本规范适用于产品 Shell、AI、浏览器、设置、文件管理、扩展、工作流、工具、媒体与应用内浮窗。
图标字形按用途选择；不把 Material 图标包的 `Filled` 名称直接等同于可见的实心图形，箭头、加号等本身即为线形。
本轮执行与验证见[全局视觉专项](../../TODO/kiyori_global_ui_visual_unification/index.md)。

## 字形规则

| 用途 | 默认字形 | 状态表达 |
| --- | --- | --- |
| 顶栏、输入框、弹窗内的新增/搜索/编辑/删除/复制/分享/刷新/设置 | Material Outlined 或既有轮廓 Vector | 点击反馈、可用性、原有文字；禁用不切换字形 |
| 软件首页搜索框三按钮、AI 顶栏四入口、AI 输入区与附件/设置弹窗 | 轮廓，同一图标库和方向规则 | 现有主题色、功能色、开关；开启后不改成填充 |
| 设置入口矩阵、弹窗工具操作 | 轮廓与固定功能色 | 同组统一视觉重量；保留原有分类色 |
| 底部主导航 | 未选轮廓、选中填充 | 原金黄色选中层与无障碍 selected 语义并存 |
| 收藏、书签等明确二态操作 | 空心/填充成对 | 已选填充；同时提供状态描述，不能只靠颜色 |
| 文件/文件夹类型、列表对象、分类徽标 | 允许填充 | 原类型色与文字，选择不得掩盖文件类型 |
| 播放/暂停/停止和媒体覆盖层 | 允许高辨识度填充 | 深色遮罩上白色，活动状态用原播放器强调色 |
| 成功、失败、警告、权限结果 | 允许填充 | 成功绿、危险红、警告橙，同时保留文字或形状差异 |
| 头像、网站图标、应用图标、品牌、预览 | 原始图像 | 不统一着色，不把内容转为单色功能图标 |

有方向含义的返回、发送、打开等图标保留 `AutoMirrored` 能力；不改变按钮命中区域、排序、回调和动画。
同一操作的大小沿用所在组件的既有几何，小图标与点击区域分离，不为图标变细而缩小命中区域。

## 颜色规则

- 普通操作使用所在主题的中性前景色；主操作使用既有强调色，不能给一整排普通操作任意分配彩虹色。
- 功能分类沿用 `KiyoriSemanticTone`；设置使用既有低饱和色表，浏览器菜单使用既有逐项身份色，均随浅深主题切换。
- 危险操作优先 `colorScheme.error` 或既有红色语义，不通过字形猜测并自动覆盖颜色。绿色分类图标不代表操作已经成功。
- 浏览器和文件底栏保留中性灰黑色；同步方向的一灰一黑仍由活动位置决定。主导航金黄选中与工具菜单分类色属于不同角色。
- 禁用状态沿用现有 alpha 和 enabled 语义；重要状态不能只依赖颜色。主要非文本图标与其背景对比度目标至少 3:1。
- 媒体、截图和终端覆盖层有独立背景约束，允许白色控制图标。内容原始颜色不计为主题硬编码缺陷。

## 动态入口与验证

输入菜单的插件图标使用 `MaterialIconNameResolver.resolveOutlinedOrDefault`，缓存包含样式，
避免同名图标先在其他界面解析成填充后污染输入菜单。未知名称沿用调用方原有默认图标；其他消费者保留原默认解析合同。

检查应覆盖：指定输入区的不同状态、通用操作字形、导航/收藏填充保留、浅深色对比度、动态解析隔离、编译与 APK。
静态扫描不等于运行时截图验收；插件自带位图、网页内容与系统选择器图标由其各自所有者决定。
