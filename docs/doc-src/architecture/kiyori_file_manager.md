# Kiyori 内置文件管理器设计

状态：持续实施；阶段与证据唯一入口见[文件管理器专项](../../TODO/mt_file_manager_replica/index.md)。
本文定义原创产品方案和目标契约；标为规划的能力不代表已实现。适用于底栏第四项“文件管理”
经“手机存储”进入的共享文件管理器，以及设置中的文件管理器偏好页。

## 产品目标与边界

面向日常整理、跨目录批量处理和移动开发三个使用层次，提供易理解、可观察、可恢复的文件工作环境。
以专业 Android 文件管理器的通用能力为目标，独立设计信息架构、组件组合、图标使用和文案。
不使用 MT 专有代码、图片、品牌或逐像素几何；保留上游开源归属，原创设计不构成法律审查结论。
“最强”以能力覆盖、数据完整性、可达性和性能实证推进，不作为已证实的竞争排名。

复用 Kiyori MaterialTheme 的颜色、字号、形状、弹层和无障碍规范。浅色与深色均使用语义 token；
不建立第二套全局主题。现有 application ID、文件工具协议、SAF 书签及持久数据格式保持兼容。

## 用户旅程与信息架构

1. 从文件首页进入手机存储；首页显示真实可用位置和容量。收藏、最近、下载、分类入口仅在接入后出现，
   不以空按钮假装支持云盘或回收站。
2. 首次进入显示可关闭的简短使用提示：点击浏览、长按操作、选择后批量处理；不强制翻页或扫描全部文件。
3. 顶部提供返回文件首页、当前目录与搜索、过滤、排序、刷新四个快捷按钮。路径支持点击跳转与复制，长路径省略显示但完整内容可访问。
4. 永久左右双位置等宽布局，通过非活动栏的淡灰内阴影衬托活动栏。触摸任一栏即可激活，
   不保留单位置、自动布局或 A/B 标签行；两个位置仍消费原有窗格状态与导航历史。
5. 常用动作使用文字和图标；选择模式提供数量、全选、清空、复制、移动、删除及更多操作。
   未实现能力不显示可点击入口。删除和覆盖在提交前显示精确对象、目标及不可撤销范围。
6. 执行中保留目录浏览，任务区显示操作、源/目标、已完成项、错误及取消状态；结果可重新查看。
   新建或重命名失败时保留用户输入，允许修正；成功刷新相关位置而不劫持新导航。
7. 打开文件复用 Kiyori 预览、办公套件、播放器及系统 URI 授权能力；不创建第二播放器或下载器。

左右滑动移动完整行（背景/图标/文字/元信息），在固定行/窗格内裁切，结束或取消后回弹。
两侧统一执行幂等选中，短滑和取消不改变选择。没有待完成区间时，有效滑动以文件名建立当前栏锚点；

刷新和排序按名称重新定位，锚点消失后下一次滑动重新建立锚点。
点击和长按共享行级按下变色与轻微内阴影；快速单击保留 80 ms 反馈后执行动作，
等待期间重复点击不重复提交，行离开组合时取消迟到动作，横向拖动时不叠加按压阴影。
自动目录读取期间不绘制文件夹加载图标、“正在读取”或栏顶部进度条；主动刷新显示短暂状态；完成后才显示空目录状态，
失败仍显示可重试错误。导航时未取得新列表的区域保持表面，不冒用旧目录内容。

首尾吸附轨道端点；未测量的不等高行沿用 Compose 的长度估算，不额外扫描文件或创建滚动状态。
初始普通点击打开，首次滑动选中后进入当前栏选择模式，模式内点击切换勾选；长按弹出文件动作，同时提供显式“打开”。
选择模式直接由原 ViewModel 的各窗格选择集合推导，不单独持有模式开关：点击取消最后一项或刷新/筛选到零项，立即恢复该栏点击打开。
长按菜单中的“全不选”只清空并退出活动栏模式；系统 Back 优先清空两栏选择、模式与锚点，再由后续 Back 处理筛选/目录。
显式目录导航、复制后清空及读取失败仍按原生命周期清理对应窗格，避免跨目录批量操作；“上一级”保持导航语义。
手势读取最新回调，选择对象按最新目录快照解析，避免刷新后继续使用旧文件元数据。

- 页面层级：主题表面上的标题栏、位置导航、文件列表、上下文动作。以留白和分隔表达层次，减少大阴影。
- 文件名优先；元数据按空间显示，长名不覆盖按钮。显示扩展名，不擅自改名或推断文件格式。
- 常规触摸目标至少 48 dp；字体放大时容器随内容增长，避免固定弹窗高度、负偏移和裁切。
- 焦点/选中同时提供语义和形状标识，不只依赖颜色。TalkBack 读出名称、类型、选中状态与按钮用途。
- 加载、空目录、空搜索、权限不足、离线、部分失败必须区分；仅对实际就绪能力提供操作。

- 排序提供字段和方向选择，目录优先、自然名称排序、隐藏文件设置有可见状态；恢复不覆盖当前用户动作。

## 顶栏与分列浏览

搜索、过滤、排序沿用底部抽屉，打开时捕获列与位置；关闭或返回不应用未确认的过滤/排序草稿。
搜索默认仅当前列目录，可显式包含子目录，独立于当前列表过滤。已有高级搜索能力与各存储限制保持不变。
过滤确认后才投影当前列，名称包含、扩展名、大小上下限、修改日期与项目类型之间取交集，多个扩展名取并集。
格式只按扩展名判断，支持复合扩展名与无扩展名，不递归计算目录大小。大小/格式条件不匹配目录；
时间不可用项目不匹配日期条件。自定义结束日期包含当地整天；相对时间在确认时固定。
父目录项不参与过滤；筛选后全选、反选和选择保留只覆盖可见项目。换目录清除过滤，刷新保留过滤。
排序支持名称、大小、修改时间和文件格式，每列独立，目录始终优先。

两列顶部下拉各自带阻力与回弹，达到 64dp 视觉距离后松手刷新；横向选择与惯性滚动不触发。
内容位移限制在当前列，顶栏、路径栏和底栏固定，空目录同样可下拉。点击刷新读取当前列并保留滚动与有效选择。
手动刷新复用原目录请求与代际，自动刷新不冒用用户刷新状态、不取消文件写任务。

工具箱包含取消粘贴、显示隐藏、交换窗口、传输任务、最近任务及原 AI/浏览器入口。
取消粘贴仅清理内部待粘贴集合，不取消已经执行的传输。显示隐藏为两栏共享偏好。
交换窗口对调目录/环境、前进后退历史、过滤、排序、选择及滚动，活动状态跟随原内容；
先废弃旧物理栏请求，必要时重读交换后的目录。共享剪贴板与执行任务不对调。
底栏原“同步位置”仍单向复制活动列位置，不能与交换窗口混淆。

## 搜索与任务历史

`FileManagerHistoryStore` 是历史唯一存储，位于 `noBackupFilesDir/file-manager/history.json`，
采用 schema 1、串行写入与同目录原子替换，文件总上限 32 MiB。存储失败明确显示，原记录不被覆盖。
历史只记录用户请求的搜索与操作，不持有文件任务执行权，不保存凭据或文件内容，也不外发。

- 搜索最多 20 次，包含关键词、完整条件、来源环境/目录、时间、结果数、状态与最多 1000 项结果快照。
  超过保存数量显示部分保存提示。查看不重搜，重新搜索使用记录的原目录与条件；定位前核对结果仍存在。
  删除与清空记录不会被迟到搜索结果恢复，历史按搜索开始时间排序。
- 文件任务最多 100 条，包含复制、移动、删除、恢复、永久删除、新建、重命名、压缩与解压。
  每个批次一条，摘要状态来自完整结果，每条最多保存 1000 项详情，裁切时显示明确数量。
  进行中面板消费原执行状态；已结束任务按时间展示，支持来源/目标定位、查看详情、删除记录。
- 首次提交前保存进行中记录，终态在不可取消区间更新。进程中断后无终态的任务标为“结果待确认”，
  搜索标为“已中断”。不自动重试、不提供通用撤销，清空历史不取消执行或删除文件。
- 普通浏览、打开、过滤与排序不记为文件任务；搜索历史单独呈现。设置往返/最小化仍复用会话，
  完整目录工作恢复不由历史记录替代。真实设备上的手势、字体与存储行为保持独立验收。

## 所有权与状态

现有 `FileManagerViewModel` 持有页面会话、左右位置、选择、目录请求代际、搜索和操作呈现。
UI 只发送意图并显示投影。文件读写继续经 `AIToolHandler` 和既有 Android/Linux/SAF 文件能力执行。
需要长期任务时在现有文件能力领域提取执行所有者，ViewModel 仅订阅；不另起文件系统后端。

位置身份必须包含路径和环境；后续文档 URI、挂载卷和归档节点采用明确类型，不能把所有来源当作本地路径。
每次异步工作捕获不可变输入。发布前校验请求代际和位置身份；取消不能被捕获为普通错误或成功。
目录加载、搜索与写任务的进度分别持有，不能互相清除忙碌状态。

## 文件操作与数据完整性

### 2026-09-12 操作确认与同卷回收

共享存储回收根改为各存储卷下 `.kiyori-recycle-bin/<applicationId>`，由标准文件后端按
`getExternalFilesDirs` 返回的卷位置选择。共享路径进入 `Android/data` 在真实设备上返回
`EXDEV`，因此共享回收不再跨越该挂载边界；不是失败后复制并删源，也不自动永久删除。
应用内部内容仍进入内部回收目录，应用外部专属目录内的文件仍使用同一专属目录的回收根。
回收站统一读取这些根及旧记录，不迁移或删除旧数据；共享回收内容不会随卸载自动清除，
内部及旧专属内容仍受应用数据清理影响。存储卡卸载、目录权限、FUSE 行为须现场验收。

确认弹窗按“操作与数量 → 用途/后果 → 来源与项目”组织，写操作不重复完整属性列表。
执行后改为结果摘要与逐项结果，真实错误优先展示，可复制操作详情；删除结果提供“查看回收站”，
关闭后从工具箱“最近任务”查看持久化结果，不重新提交操作。
永久删除单独使用危险按钮，恢复不覆盖，并复核确认时的指纹。多项操作可在当前项完成后停止，
结果未知立即停止后续项，不将未执行项伪装为失败。损坏或残留回收记录显式保留为需检查条目，
不阻断其他有效记录，不自动修复、覆盖或删除内容。

复制/移动目标选择只允许当前支持的手机存储。同目录移动、目录自身/后代及非本地目标在确认前说明原因。
选择浏览后出现待粘贴条，可直接粘贴或取消；原五项底栏和两栏会话不变。剪贴板版本随确认捕获，
旧任务不能消费之后重新选择的同名待移动项目。复制与移动统一核对结构化成功标记和残留路径，
未知结果停止批次，完成后可以查看固定目标目录。批量重命名确认显示前五项名称预览。

Android 无 birthtime 的文件系统可能以 mtime 提供 creationTime；永久删除子项后只比较稳定目录身份，
不把自身引起的 mtime 变化误判为目录替换，真实 birthtime 与可用 fileKey 继续校验。
参考 [Android libcore UnixFileAttributes](https://android.googlesource.com/platform/libcore/+/refs/heads/main/ojluni/src/main/java/sun/nio/fs/UnixFileAttributes.java)。

文件工具在每次执行时解析当前权限，不固化首次注册时的普通身份。未明确配置级别而存在实际授权 Shizuku 时，
采用既有 Shizuku 路由；用户明确选择的其他身份保持。特权目录列表通过真实特权 Shell 并安全引用路径。
普通目录枚举失败不再转换为空列表。Shizuku 是 Shell 身份，并不等于 Root；`Android/data` 与系统 `/data`
不同，系统/厂商拒绝时显示真实错误。此增量不改变严格写入、内容预览仍需应用身份可访问的边界。

### 2026-09-11 菜单与回收站增量

菜单头部显示来源左栏/右栏、位置和实际对象数。长按选中项目使用该栏的整组选项，长按未选项目仅操作该项；
另一栏的选择不混入当前动作。复制/移动先捕获两栏位置，确认后切栏或导航不会改变任务来源与目标。
删除、属性、ZIP 合并压缩、分别解压及多项压缩分享消费同一组对象；重命名、打开方式、书签和工作区是单选动作，
多选时禁用并说明。解压入口仅对全部为 ZIP 的项目启用；Linux、SAF 和网络严格写操作尚未接入，菜单明确说明。
所有写动作记录逐项终态；结果未知立即停止未提交项，不允许在原确认中重放已执行批次。

回收站作为原 ViewModel 内的 `/回收站` 位置展示，环境身份为 `recycle`，同时汇总应用内部与外部存储的回收记录；
它是现有回收存储的展示投影，不是新文件系统或第二目录状态所有者。真实内容仍留在各自同卷的 `file-recycle-bin`。
列表展示原名、原路径与删除时间，记录 UUID 作为选择与滚动键；不同原目录的同名文件保持独立。
点击记录确认恢复，长按/底栏菜单提供恢复、彻底删除、属性和选择；回收站不接受新建、粘贴、改名或普通移动。
恢复前核验磁盘记录及原目标，同名不覆盖；原父目录丢失保留内容。彻底删除经二次确认、指纹复核与隔离删除，
失败或未知结果保留可见的逐项报告与隔离路径。内部及旧专属回收内容在清除应用数据或卸载后不可恢复。

抽屉普通行最小 48dp，文件名称 12sp、分组 13sp、图标 24dp，与双栏紧凑文字比例一致；
所有位置名称下显示路径，根目录和内部存储额外显示真实已用/总容量、百分比与进度条。
路径由文本布局按可用宽度从左侧省略，不按固定字符数裁切。遮罩打开及关闭动画期间保留内容命中阻断层。
以上代码与设备交互分别验收，不把构建结果视为遮罩、字体或真实存储现场通过。

以下是必须逐阶段落实的目标合同，现有传输后端尚未全部满足：

1. 名称校验拒绝空白、路径分隔符、控制字符和 `.` / `..`，保留合法 Unicode、前后空格及显式扩展名。
2. 新建使用不覆盖语义。传输前校验规范路径、环境、源等于目标、目录进入自身子树、符号链接及重复源。
3. 同名冲突逐项显示“跳过 / 保留两份 / 替换”，批量应用只针对本任务；不能静默覆盖。
4. 后端必须具备原子不覆盖或明确冲突契约；仅在 UI 中预检查存在性不足以防止检查与写入间的竞争。
5. 复制采用目标临时文件、完整性校验、最终提交；移动优先同卷原子改名，跨来源须校验复制成功后才删除源。
   源删除失败明确标记“已复制，源仍保留”，重试不能再复制已完成项或误删变化后的源。
6. 任务保存逐项终态、进度和失败原因；取消只停止未提交工作，不声称撤回已完成的副作用。
   进程死亡后先核对实际磁盘事实，再允许用户恢复；不得无条件重新执行移动或删除。
7. 永久删除显示确认；回收站仅用于可保证同卷移动和恢复的位置，记录原位置、冲突与容量，不伪造撤销。
8. 归档拒绝越界条目、绝对路径、链接逃逸与压缩炸弹，限制条目数、解压字节和嵌套深度。
9. 日志不保存目录清单、文件正文、凭据或原始搜索词；可导出的诊断默认脱敏。

## 能力路线与依赖

### 浏览与新建增量（2026-09-10）

- 始终并排显示两个位置，不按屏宽或字体缩放切换模式。无效的父目录行隐藏，底栏第5项为菜单。
- 页面 STARTED 时每 3 秒通过原目录请求自动刷新，跳过在途请求、写任务和长按菜单；
  后台刷新不显示加载占位，不重启滚动恢复，不取消导航请求；结果仍校验目录身份与代际。
- 文件名按自然数字段比较，超长数字不转换为整数；大小/修改时间默认降序，名称默认升序，方向可切换。
  目录始终优先。同字段时使用稳定名称次序；排序与文件元数据转换仍在后台执行。
- 每个窗格保留当前目录的条目快照与已确认过滤条件；筛选不新增 IO 请求。过滤后只显示当前可见项目，
  全选/反选同样限定可见项。刷新清除已删除选择并更新保留项目元数据，历史前进/后退清除原目录选择。
  读取失败或加载时不接受批量选择；筛选与未筛选的滚动位置隔离，过期投影不能写回当前滚动记录。
- 新建空文件原先经过拒绝空正文的 `apply_file`，现使用既有工具的 `create_mode=no_replace` 明确路由。
  Android 使用 `Files.createFile` / `Files.createDirectory`，不预检查后覆盖、不创建缺失父目录、
  不把同名目录当作创建成功。Linux/SAF 和非空内容不支持此模式时返回可见错误，旧无模式调用保持兼容。
- 新建冻结位置、禁止重复提交并保持在途结果发布；未取得工具终态时显示未知并禁止原弹窗重试。
  退出检查统一覆盖复制、新建和重命名。以上不提供进程死亡恢复；现场行为仍待设备验证。

### 内容打开首批增量（2026-09-10）

手机普通路径音视频通过 `FileProvider` URI 交给既有 `PlayerSession` 和 `PlayerActivity`；图片复用
`WorkspaceImagePreview` 的缩放、拖动、加载和失败呈现。文本与源码复用 `CodeEditor`，扩展名仅选择
入口，实际内容需通过有界严格 UTF-8 读取。`.ts` 在文件管理器中优先按 TypeScript 文本打开；未识别的
格式通过系统 ACTION_VIEW 打开，缺少应用时显示错误。Linux/SAF 内容打开暂未接入，提示先复制到手机。

文本草稿及异步代际仍属于文件管理 ViewModel。关闭加载会取消请求并阻止晚到结果；读取失败不生成可保存
的空文档。编辑支持换行与语法显示，保存目前只提供原目录“另存副本”，不直接覆盖原文件；完整路径、内容
在提交前冻结，与复制/新建/重命名互斥。失败保留草稿，未知结果禁止重复保存，关闭脏草稿需明确放弃。
保存采用已有文件工具的显式模式，UTF-8、1 MiB 上限与暂存提交规则见[平台存储契约](../contracts/platform_storage.md)。
原文件原地编辑、编码选择、超大文件分页、保存冲突与进程死亡恢复留在 M5 后续阶段。

### 严格复制机制（2026-09-10）

文件管理器复制统一传递 `copy_file` 的 `copy_mode=no_replace`，未传该参数的既有工具行为保持兼容。
当前支持应用身份可访问的 Android 普通路径。Debugger/Root 入口显式委托该模式，Linux、SAF、
跨环境和未知模式返回不支持，不执行 `cp`、目录合并、静默提权或覆盖写入。

复制在目标父目录创建唯一 `.kiyori-copy-*` 暂存目录，内容写入其 `payload`。普通文件通过
`CREATE_NEW` 写入、刷盘和 SHA-256 暂存内容校验，源项目在读前、读后及提交前检查身份、大小和
修改时间；拒绝直接链接、特殊文件、源自身和后代目标。目录深度上限 256，失败清理本任务暂存，
清理失败返回确切暂存位置。源端不是文件系统快照，外部应用可伪装时间或在最终检查后继续修改；
此增量不把上述检查当成删源安全凭证，也不承诺断电事务或跨进程持久恢复。

最终提交由 `NativeNoReplaceCommit` 调用 `renameat2(RENAME_NOREPLACE)`，只发布完整暂存内容，
目标同名在提交瞬间存在也必须失败。内核或文件系统不支持时失败，不退回普通 rename。
该原语的语义依据为 [Linux rename 手册](https://man7.org/linux/man-pages/man2/rename.2.html)，
独占创建依据为 [Java StandardOpenOption](https://docs.oracle.com/en/java/javase/24/docs/api/java.base/java/nio/file/StandardOpenOption.html)。
最小 JNI 以 UTF-8 字节传递路径，不用 Modified UTF-8 编码文件名。

`FileOperationData` 新增可缺省的 `errorCode`、`destination`、`stagingPath` 字段；旧构造与缺字段
解码保持兼容，默认空字段不写入 JSON。UI 按明确的 `destination_exists` 冲突码进入等待，
允许跳过或改名保留两份；修改名称后仍使用同一个原子不覆盖入口。存在未清理暂存时先报告失败。

复制面板显示固定来源、目标、当前项、完成/失败/跳过/未执行/未知结果。确认后切栏、清空或替换
剪贴板不改变任务。停止语义为完成当前项后停止，当前工具调用和结果发布不因页面清理而丢失；
未取得可靠工具结果时显示未知，不自动重试。进程强杀仍可能遗留暂存或已完成目标，持久恢复在 M2
后续完成前不自动重放。退出入口在复制期间提示等待或停止；目录浏览仍可使用。

剪切与复制复用传输会话；剪切使用 `move_file` 的 `move_mode=move_no_replace`，同文件系统内
跨目录原子不覆盖移动，`EXDEV` 明确拒绝并保留源。不存在复制后删源的替代路径。
来源、另一位置以及批次在目标选择弹窗打开时捕获；可浏览目标目录或直接“使用另一位置”，
均需确认完整来源与目标。剪切完成或结果未知的项目仅从仍属于原批次的剪贴板移除，失败项保留。
覆盖替换与持久恢复仍按阶段逐项闭合。

同目录重命名使用既有 `move_file` 的显式 `move_mode=rename_no_replace`。后端校验源/目标父目录
相同、拒绝源链接和同名目标，再复用同一个原子不覆盖提交；既有不传模式的调用保持原义。
Android 以外的后端明确拒绝，提交失败不会进入复制/删源。名称、来源与环境在打开弹窗时固定，
失败保留输入，未知结果禁止原弹窗重试，成功只刷新相关窗格并清除旧名称选择。复制、新建和
重命名写入互斥，冲突动作显示禁用态，目录读取独立运行。

### 菜单、存储与内容工具

长按与底栏菜单共用固定五列动作，顺序为：

1. 复制、移动、粘贴、删除、重命名。
2. 压缩、解压、分享、属性、工具箱。
3. 全选/全不选、反选、打开方式、加书签、加工作区。

第四行只显示关闭/收起/设置，所有 18 个入口使用互不重复的浏览器菜单颜色。尺寸与浏览器菜单一致，没有上拉展开态，
动作在关闭动画后打开对应面板。文件工具、属性和确认框可滚动。

第二行工具箱在无选择时仍可用。菜单标签与浏览器同用 12sp 行高，两行文案保留在相同的固定高度内。
工具箱替换一级菜单，使用共用的三行五列独立 Dialog，无第四行、不保留一级返回栈，Back/外部点击直接关闭。
文件二级仅提供 AI对话和浏览器，其余位置为不可点击空槽位，仍保留三行高度；浏览器导航先最小化文件会话。
动作会话属于 `FileManagerViewModel`，冻结源位置并保护读写代际；失败检查清除旧清单，未知写入禁止重复提交。

`LocalManagedFileActions` 是既有标准文件后端内的实现，不新增执行器。`file_info` 的显式
`info_mode=manager/manager_sha256` 统计普通树并返回路径、大小、数量、时间、读写能力和指纹，
普通文件可流式计算 SHA-256。树扫描上限 100000 项、128 层，拒绝链接及特殊文件，不能以部分扫描确认删除。
读取可取消；删除、压缩确认后等待当前操作结果，阻止重复写入和退出。

永久删除通过 `delete_file delete_mode=checked` 提交已显示清单的指纹，执行前再次检查，使用
原子不覆盖移动把源隔离到兄弟 `.kiyori-delete-*/payload`，复查一致后只删除该隔离树。
隔离前变化会拒绝；隔离后复查不符会尝试不覆盖恢复原路径，冲突或部分删除失败保留隔离位置。
文件管理器删除默认使用 `delete_mode=recycle`：清单保存原路径后进行同卷不覆盖移动，回收后复核指纹，
源变化则尝试不覆盖恢复。内部文件进入应用内部回收目录，共享存储文件按上文 2026-09-12 契约进入同卷共享回收目录；
跨卷或存储不可用明确失败，绝不自动永久删除。抽屉回收站从磁盘记录加载，支持恢复原路径与二次确认永久删除，
同名/父目录丢失保留回收内容。内部及旧专属回收内容随卸载清除，共享回收内容需手动清理；不承诺恶意并发或断电事务。
元数据指纹包含名称、类型、可选文件标识、创建/修改时间与大小，
兼容 NIO `fileKey()` 缺失的文件系统；它不是内容哈希，不承诺恶意并发、进程强杀或断电事务。

`zip_files zip_mode=no_replace` 将完整源项目压缩到原目录可编辑名称的 ZIP，保留 Unicode 和空目录，
拒绝源内部目标、链接和不能安全表示的归档名称。源检查、同目录 `.kiyori-zip-*` 暂存、刷盘后
复用原子不覆盖提交；源变化、同名、清理失败显式返回。
`zip_mode=extract_no_replace` 解压未加密 ZIP 到新目录，要求中央目录完整，拒绝绝对路径、穿越、重复路径和条目/字节超限；
最多 100000 项、128 层、8 GiB。暂存完整后原子发布，同名不覆盖；其他归档格式与加密 ZIP 尚未接入。

文件分享使用 FileProvider URI、ClipData 和只读授权交给系统 ACTION_SEND 选择器；目录分享先确认
压缩并保留 ZIP，再打开选择器，不自动指定接收人或发送。普通文件/目录书签使用 `ApiPreferences`
现有 DataStore 的 `file_manager_bookmarks_json`；文件书签进入父目录并筛选实际文件名，目录书签直接导航。
删除普通书签不会撤销 SAF 权限，损坏数据不会被静默覆盖。Linux/SAF 新严格动作仍明确不支持。

## 验收矩阵与质量目标

### 统一搜索合同

`FileManagerSearchForm` 由原 ViewModel 持有；顶栏搜索复用浏览器抽屉，默认仅当前目录，勾选后递归。
高级条件支持名称包含、完整名称通配符、正则片段匹配、大小预设/自定义 MiB、修改时间预设/自定义日期、
内容与大小写、隐藏项。日期按本机时区转换，结束日包含全天；大小范围包含端点，预设区间不重叠。
名称可留空按大小/时间/内容查找，空条件和无效表达式不得提交。旧大小写参数错配已修正。

Android 的 `find_files search_mode=manager` 解析序列化 `FileSearchOptions`，由同一标准后端内
`LocalFileSearch` 执行，返回 `FileSearchData` 的类型、大小、修改时间及扫描/跳过/限制信息，不追加每项属性请求。
扫描不跟随链接，默认忽略隐藏子树；最大 100000 项、2000 个结果、128 层递归，时间预算 30 秒。
内容读取仅普通文件、最多 4 MiB、严格 UTF-8；二进制/编码/权限/读取中变化/超限可见，部分结果不冒充完整扫描。
正则长度最多 512 字符，字符读取检查协程取消、200 ms 单次匹配预算与工作量上限；复杂表达式或栈深超限显式终止。
时间预算在文件枚举、读取及匹配边界检查，不承诺中断阻塞的底层文件系统调用。

新搜索捕获条件、路径与窗格，结果须通过代际校验；关闭会取消，条件可保留再编辑。结果目录进入该目录，
文件回到所属父目录并筛选文件名，隐藏文件定位会启用隐藏可见性，拒绝点击不属于当前结果的任意路径。
Linux/SAF 保留既有名称搜索，正确传 `case_insensitive` 与 `max_depth`；不支持的高级条件直接拒绝，
不忽略条件、不自动换本机搜索。旧工具调用不传显式模式时保持原义，旧后端的性能和取消限制不继承本地新搜索保证。

| 维度 | 必测场景 | 完成信号 |
| --- | --- | --- |
| 导航 | A-B-A、快速切栏、返回、旋转、后台恢复、长路径 | 不出现旧结果覆盖、错误目标或来源丢失 |
| 数据 | 空文件、大文件、非ASCII、同名、父子目录、只读、空间不足 | 原文件无意外改变，失败与已提交项可追溯 |
| 任务 | 连续点击、取消、部分失败、进程终止、源被外部改变 | 不重复提交危险操作，不宣称虚假成功 |
| 搜索 | 新搜索替代旧搜索、取消、空结果、不同环境 | 结果属于原搜索位置，过期结果不可发布 |
| UI | 小屏/横屏/折叠、深浅色、字体200%、TalkBack | 无裁切遮挡、触摸冲突或无标签按钮 |
| 性能 | 1万目录项、10万搜索项、大文件与低存储 | 记录设备/样本/耗时/峰值内存；分页和上限可观察 |
| 安全 | 路径穿越、符号链接、URI权限、恶意归档、敏感日志 | 越界不执行，失败明确，诊断不泄露正文 |

性能目标先建立真实设备基线再制定阈值；JVM 测试不能代替触摸、SAF、硬件 IO 和远端实测。
每轮串行构建 Debug APK，风险相关行为测试优先；不机械重复无关全量检查。
每个阶段保持可回滚代码边界，数据迁移须另有前后兼容设计；最终只提交审阅的本专项文件。

## 分类存储与网络能力

存储抽屉固定为本地、网络、书签、工作区、工具五类，均可折叠。本地包含根目录、内部存储、Linux 和已授权 SAF。
书签支持文件与目录；工作区只接受目录，默认工作区复用 `KiyoriPaths.workspaceDir()`，额外位置由 ApiPreferences 保存。
这份目录列表不自动修改 AI 当前对话的工作区绑定。工具类当前只有回收站。

网络配置与分组由 ApiPreferences 持有，密码/Secret Key 用 Android Keystore AES-GCM 加密，跨设备导入需重新配置凭据。
网络环境标识为 `network:<id>`，全部文件工具从原 ToolRegistration/AIToolHandler 入口分流；未支持操作明确拒绝，
不会把同名路径交给 Android 后端。当前原生能力是连接测试和目录浏览：

| 协议 | 当前连接契约 |
| --- | --- |
| FTP | UTF-8、EPSV、MLSD；不支持这些命令时明确失败；账号为明文传输 |
| FTPS | 显式 AUTH TLS、加密控制及数据通道，校验系统证书与主机名 |
| SFTP | 密码认证，要求预先填写 SHA256 主机公钥指纹；复用仓库 JSch 版本的算法能力 |
| WebDAV | Depth 1 PROPFIND，禁用跨地址重定向及 XML 外部实体 |
| S3 兼容对象存储 | SigV4、路径式存储桶、区域与 ListObjectsV2 分页，不含临时会话令牌 |

响应上限 8 MiB、单目录 100000 项，网络刷新间隔至少 30 秒；握手/读取受连接超时约束，阻塞调用不承诺即时取消。
远程文件打开、上传、下载、移动、删除与高级搜索尚未接入，界面明确显示边界。真实 FTP/FTPS/SFTP/WebDAV/S3
服务器兼容性、证书、密钥链、代理路由及 Android 网络现场行为仍为 `verification_pending`。
