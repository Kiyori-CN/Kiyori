# 5. 首页与全屏搜索交互细化

状态：[DONE]

## 现状与根因

- 首页 Search/AI 分段框为 `128×36dp`，相对搜索框底部工具区仍稍显宽高。
- AI 模式主框只切换到 AI Home，没有向聊天输入框传递焦点意图，因此输入法不会随页面进入自动出现。
- 软件首页全屏搜索页传入真实无痕控件，浏览器顶部搜索入口却向同一个 `WebSessionBrowserSearchScreen` 传入固定 `Spacer`，导致底栏第二项进入浏览器后缺少无痕按钮。
- 当前无痕图标始终为闭眼，普通和无痕状态无法仅通过图标区分；无痕选中后还显示长说明，占用搜索页首屏空间。

## 视觉合同

- 分段框调整为 `120×32dp`，继续严格等分，保留 `10sp` 文字和 `15dp` 图标。
- 标题右上角圆环从 `14dp` 调整为 `16dp`，保持轻量角标而不是第二个标题。
- 普通模式使用睁眼图标，无痕模式使用闭眼图标；不可用状态保留禁用视觉和无障碍说明。
- 删除搜索页中的无痕长说明。模式切换后在页面底部显示紧凑文字提示，约 `1.2s` 后消失，不遮挡搜索结果和输入框。

## 行为合同

- 新增 `FOCUS_INPUT` 一次性 AI Home 动作。首页 AI 主框发出请求，AI Home settled 且当前聊天页可见后，当前输入样式的真实文本框请求焦点、显示输入法并消费请求。
- `WebSessionBrowserSearchScreen` 必须直接接收 Profile 状态与切换回调，所有调用方都必须提供真实控件，不能再用空白占位。
- 从浏览器当前标签提交搜索时，所选 Profile 与当前标签一致则继续当前标签；不一致则在共享 WebSession 运行时中新建所选 Profile 标签并加载目标。
- 切换按钮同步更新浏览器默认新窗口 Profile。无痕不可用时不改变状态，也不创建普通窗口代替。

## 验收

- JVM 测试覆盖一次性输入聚焦动作和浏览器搜索 Profile 决策。
- `git diff --check`、正式准备门禁、定向 JVM 测试、显式 Kotlin 编译与 `assembleDebug` 通过。
