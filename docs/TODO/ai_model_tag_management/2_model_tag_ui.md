# 2. 模型标签与添加交互

## 页面结构

- 标签卡片默认展示三行，超过可见范围显示展开入口。
- 展开后显示全部标签和收起入口。
- 收起时使用 `SubcomposeLayout` 按标签真实测量宽度生成前三行放置计划，超出项不执行放置；禁止通过固定高度或测量高度裁切完整列表。
- 第三行使用完整的“还有 N 个”标签，`N` 必须等于最终未放置的真实模型数量。
- “还有 N 个”是独立展开标签，右侧不显示删除叉号；单击整个标签展开全部模型。
- 为展开标签腾出空间时可以整枚移走第三行末尾普通标签，但不得显示任何半截标签。
- 行计划只能显示模型列表的连续前缀；不能跳过一个放不下的模型后再显示后续更短模型。
- 隐藏数量由自定义行计划返回，不读取 `shownItemCount`、`totalItemCount` 或其他溢出作用域。
- 禁止使用当前 Compose 已标记为不再维护的 `FlowRowOverflow` 与 `ContextualFlowRow`。
- 展开时所有标签完整显示，收起入口位于完整列表之后。
- 标签内的模型名称不使用省略号，长名称在标签内部自动换行直至完整显示。
- 第一项使用“测试模型”标记。
- 标签主体单击复制，叉号拥有独立点击热区。
- 长按标签打开纵向排序底部面板；排序面板使用既有 Compose reorderable 依赖。

## 添加路径

- “添加模型”打开多行输入面板，单个模型可以只输入一行；逗号和换行用于批量粘贴。
- “从上游获取”复用 `ModelListFetcher`/ToolPkg 模型获取链路，支持搜索和多选。
- 当前上游列表中已经存在于模型配置的项目默认勾选，但不再禁用，用户可以取消勾选。
- 应用选择时保留仍勾选模型的现有顺序，并按上游顺序追加新勾选模型。
- 当前上游没有返回的手动模型、历史模型或本地模型不参与本次取消操作，继续保留原顺序。
- 取消已绑定模型时必须先确认受影响的功能与角色卡，并显式指定变更后的第一项作为新测试模型。
- 如果取消操作将移除所有可用模型且仍存在绑定，则拒绝应用。
- 完全重复项不重复添加；没有选择差异时禁用“应用更改”。

## 第二轮操作栏

- “添加模型”“从上游获取”和更多按钮固定在同一行。
- 两个文字按钮使用弹性宽度，更多按钮使用固定正方形触控区。
- “添加模型 / 从上游获取 / 更多”与“重命名 / 删除 / 测试模型”共享 `40dp` 视觉高度、`12dp` 圆角、图标尺寸和水平内边距。
- “添加模型”使用描边层级，“从上游获取”使用强调层级，更多操作保持中性容器。
- 按钮文字固定单行并允许在极窄宽度省略，不能把整组操作挤成两行。

## 操作边界

- 更多菜单提供排序、复制全部和清空全部。
- 点击清空全部后立即显示“正在检查绑定”模态状态；检查期间不能表现为无响应。
- 无绑定时进入清空确认；存在功能模型或固定角色卡绑定时显示明确的阻止对话框并拒绝清空。
- 删除单个模型后提供撤销；撤销会恢复列表位置以及受影响的绑定。
