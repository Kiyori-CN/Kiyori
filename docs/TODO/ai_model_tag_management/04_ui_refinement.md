# 4. 第二轮 UI 与布局精修

## 已确认问题

- 模型区三个操作使用 `FlowRow`，在不同文案和字体缩放下可能分成两行，视觉层级不稳定。
- “从服务获取”描述的是实现来源，不如“从上游获取”准确表达用户目标。
- 上游模型对话框把 Material3 `OutlinedTextField` 强制限制为 `48dp`，小于组件的标准内部布局高度，导致“搜索模型”提示文字被垂直裁切。
- 固定 `520dp` 对话框同时承载标题、搜索、全选、长列表和确认区，手机上空间分配过于紧张。
- 模型配置的“重命名 / 删除 / 测试首个模型”继续使用可换行操作区，三个同级入口的排列和按钮层级不统一。
- “测试首个模型”把内部索引规则暴露在按钮文案中；用户只需要理解这是当前配置的“测试模型”，实际测试名称已在结果区展示。

## 设计决定

- 模型区使用单行 `Row`：手动添加和上游获取分别占弹性宽度，更多按钮保持固定宽度。
- 三个操作使用统一高度、圆角、图标尺寸和水平间距，通过描边、强调与中性容器建立层级。
- 上游选择使用 `ModalBottomSheet`，与 Kiyori 设置页现有选择面板保持同一交互方向。
- 搜索框只设置最小 `56dp` 高度，不再用小于 Material3 内部布局的固定高度。
- 上游列表使用带圆角和选中容器色的列表项；已添加项保持不可重复选择。
- 标题、搜索与筛选位于面板上部，确认操作位于固定底部，模型列表独占中间可滚动区域。
- 刷新、搜索、全选、单项多选和追加仍复用既有模型获取与合并逻辑，不建立新的持久化状态。
- 模型配置操作使用单行 `Row`：“重命名”和“删除”为次级描边操作，“测试模型”为强调操作；自定义配置显示三个入口，默认配置只保留可用的测试入口。
- 测试入口继续调用 `ModelConfigConnectionTester`，默认索引仍为 `0`；聊天始终测试，Tool Call、识图、音频和视频按各自能力开关测试。
- 标签名称不做单行省略；长名称允许在标签内部换行直至完整显示。

## 第三轮修正

### 新确认问题

- 上游面板把当前已有模型设置为勾选且禁用，用户无法通过同一选择面板取消当前模型。
- 折叠标签仍受固定 `292dp` 最大宽度、零垂直内边距和仅 `1dp` 裁切余量影响，第二行长标签可能显得没有完整显示。
- 六个模型操作虽然分成两行组织，但各文件继续硬编码尺寸，不利于保持长期视觉一致。

### 修正决定

- 上游面板改为可编辑选择集：当前上游模型默认勾选，所有结果都允许切换。
- 确认操作改称“应用更改”，界面明确显示将添加和移除的数量；没有差异时不可提交。
- 差异应用只影响当前上游返回的模型。上游未返回的模型继续留在当前配置，不因搜索或刷新被静默删除。
- 批量取消复用模型绑定协调器；存在绑定时显示明确确认，变更后无可用模型时拒绝移除绑定模型。
- 标签取消固定最大宽度，交由 `FlowRow` 的可用宽度约束；标签增加垂直内边距，折叠安全区小于行间距，既完整保留第二行又不露出第三行。
- 新增共享模型操作尺寸令牌，六个按钮统一为 `40dp` 高度、`12dp` 圆角和一致图标尺寸。

## 第四轮现场修正

### 截图确认的根因

- 第三轮仍让全部标签进入 `FlowRow`，随后通过测量第二行底边并裁切容器高度实现收起。
- 现场截图显示第三行标签已经完成布局，只是被容器切掉下半部分，因此上半截仍会露出；增加或减少裁切余量无法从根本上保证完整行。

### 最终布局决定

- 删除折叠高度常量、标签坐标测量、底边估算和 `clipToBounds`。
- 收起态使用自定义 `Layout`，根据每个标签的真实测量宽度生成最多两行的放置计划；第三行及后续标签不执行放置。
- 第二行预留完整的“展开全部”标签；空间不足时整枚移除第二行末尾标签，禁止任何像素裁切。
- 标题右侧继续显示“共 N 个”，因此不需要在展开指示器中重复计算剩余数量。
- 行计划保持原始模型顺序和连续前缀，不能因为后续标签更短而跨过隐藏模型。
- 展开态生成不限行数的完整放置计划，现有独立收起入口保持不变。
- 这套布局由 Compose 在当前容器宽度、字体缩放和标签实际尺寸下重新计算，不维护第二套尺寸状态。

### APP_FATAL 运行时修正

- 普通 `FlowRowOverflow` 的 `shownItemCount` 由测量阶段延迟设置，不能在展开指示器的组合内容中读取。
- 崩溃报告 `b79f91c3-11c9-4ea5-87d0-00e34a812f79` 精确命中该违规读取；此前 APK 与证据全部作废。
- `ContextualFlowRow` 的确会在组合阶段初始化计数，但当前 Compose 编译器明确警告该组件已不再维护，不能作为长期方案。
- 普通 `FlowRow` 的 `overflow` 参数与 `FlowRowOverflow` 同样被当前 Compose 标记为弃用，因此也不作为最终方案。
- 最终实现使用稳定 `Layout` API 与纯函数 `planModelTagFlow`；布局只消费测量结果和固定“展开全部”，不访问任何延迟状态。

## 验收

- 三个模型操作在正常手机宽度和大字体下仍保持同一行。
- 搜索框的输入文字、提示文字、搜索图标和清除图标完整垂直居中。
- 打开键盘后搜索框与底部确认按钮仍可用，列表在剩余空间滚动。
- 选中态、已添加态、空结果、加载态和刷新失败信息均有清晰视觉区别。
- 上游添加继续保持原列表顺序，只追加尚未存在的模型。
- 自定义配置的“重命名 / 删除 / 测试模型”始终同一行，不因字体或语言切换换行。
- 连接测试仍展示实际测试模型名，并保持聊天、Tool Call、图片、音频和视频五类测试契约。
- 收起和展开状态下的每个可见标签都完整显示模型名、边框和删除入口，不出现水平省略或垂直裁切。
- 当前已有的上游模型可以取消勾选；应用后仅移除本次上游范围内被取消的模型。
- 上游未返回的模型不因应用选择而丢失；绑定模型的批量移除保持显式确认。
- 六个模型操作按钮的视觉高度、圆角、图标和内边距一致，并比第二轮更紧凑。

## 第五轮三行折叠与清空反馈

### 新确认问题

- 默认两行展示密度不足，用户要求收起状态显示三行完整模型标签。
- 固定“展开全部”无法说明实际隐藏数量；标题总数不能替代当前收起状态的剩余数量反馈。
- “清空全部”存在绑定时只调用页面级通知，而该通知卡位于长页面末尾，当前模型列表视口看不到，表现为点击无反应。

### 设计决定

- 折叠行数改为三行，继续使用完整标签放置而非高度裁切。
- 布局改用 `SubcomposeLayout`：先测量普通标签与最大计数展开标签，再生成最终行计划；计划直接返回隐藏模型数。
- 展开标签显示“还有 N 个”，使用与普通标签一致的圆角容器，但不显示删除叉号；点击整个标签展开。
- 清空状态使用单一模态状态机：`Checking`、`Confirm`、`Blocked`。点击菜单项后立即进入 `Checking`。
- `Blocked` 对话框显示绑定数量和无法清空原因；不再依赖页面末尾通知承担关键反馈。

### 实现结果

- `COLLAPSED_MODEL_TAG_ROW_COUNT` 已由 `2` 调整为 `3`。
- `ModelTagFlowPlan` 增加 `hiddenModelCount`，测试覆盖恰好三行、第三行预留展开标签、整枚移走普通标签、不跳过隐藏项和展开全部。
- `ModelOverflowChip` 只包含可点击文字表面，不包含删除图标或删除回调。
- 清空入口在协程启动前写入 `Checking`，因此绑定检查期间始终有当前视口可见的进度反馈。
