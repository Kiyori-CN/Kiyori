# 身份与数据迁移

## Android application identity

当前 application ID 为 `com.kiyori`，而历史 Operit 安装使用 `com.ai.assistance.operit`。Android 将它们视为两个独立应用，因此 Kiyori APK 不能直接覆盖旧 Operit 安装，也不会自动接管旧应用数据。

这不是需要隐藏的实现细节，而是安装和支持流程的公开前提：

1. 在旧应用中通过备份功能导出数据
2. 安装 Kiyori 开发版或后续正式版
3. 在 Kiyori 中通过备份导入流程恢复数据
4. 保留原始备份，直到聊天、角色卡、设置和工作区确认完整

现有 `Download/Operit` 路径、备份格式、数据库和插件协议继续保留，以便导入和生态兼容。路径名称不因品牌迁移而改写。

## 版本所有权

- `versionCode` 必须单调递增并由发布负责人维护
- `versionName` 使用项目约定的语义版本格式
- application ID、签名密钥、版本号和发布渠道必须在发布记录中一起锁定
- 新的更新通道未建立前，不在应用内添加自动更新检查

任何未来的包名迁移都必须另立兼容设计，包含双包并行期、数据导入、回滚边界和用户提示；不能通过一次全局重命名解决。
