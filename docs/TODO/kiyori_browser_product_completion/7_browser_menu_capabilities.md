# 浏览器四行菜单真实能力

## 原则

以当前四行菜单顺序为稳定 UI。每完成一个能力就删除对应说明页；不得用 Toast、假开关、共享 Cookie、虚构规则或无状态页面宣称功能完成。

## 能力分组

### 已有能力，完成页面整合

- 加书签、书签、历史、下载、插件、UA 标识、网络日志、AI 对话、查看源码、退出浏览器和浏览器设置
- 这些按钮复用现有 owner，只优化来源返回、全屏/抽屉页面和宽屏布局

### 本里程碑可独立实现

- 无痕模式：切换新窗口默认 Profile，并打开无痕窗口总览
- 阅读模式：对当前 session 建立可逆的正文视图状态；保留原 WebView，不重载 URL，退出时恢复同一页面
- 网站配置：以标准化 host 为 key，保存该站点的 UA、JavaScript、弹窗和阅读偏好；设置变化只应用到当前或后续匹配 session
- 标记广告：进入页面元素选择模式，保存站点级 CSS selector 规则，注入可撤销的隐藏样式；规则可在网站配置中查看和删除
- 工具箱：展示当前页面的真实工具集合，包括复制标题、复制网址、页面内查找、分享、阅读模式、网站配置和已注册 userscript 命令

### 依赖播放器后实现

- 悬浮嗅探：在播放器和媒体 candidate owner 完成前继续留在本计划第九里程碑，不在本里程碑伪造

## 阅读模式

- 使用当前 WebView 的 DOM 提取标题、正文、图片和链接，构建浏览器内阅读 surface
- 原 WebView 保持挂载或保留在同一 session，不调用 `loadUrl` 或替换 history
- Back 先退出阅读 surface，再处理网页历史
- 提取失败显示真实错误和返回，不切换到任意简化页面

## 网站配置与广告标记

- 站点 key 使用规范化 scheme/host/port，不按完整 URL 建重复配置
- 元素选择模式必须有明显的完成、撤销和取消状态
- 规则只对用户明确标记的 selector 生效；不猜测广告、不上传页面内容
- 注入脚本与 userscript manager 区分命名空间和生命周期

## 自问自答

### 阅读模式是否等于跳转到新的 data URL？

不是。跳转会改变历史和页面状态。阅读 surface 是 session 的 presentation 状态，原 WebView 和 URL 保持不变。

### 标记广告是否应该直接引入完整 Adblock 引擎？

本按钮语义是用户对当前站点元素做明确标记。订阅过滤引擎属于独立广告拦截产品能力，不能借本按钮扩大范围。

## 验收

- 除悬浮嗅探外，四行菜单中每个入口都有真实状态和返回路径
- 阅读、网站配置和广告规则不刷新当前网页，且能够撤销
- 普通和无痕窗口分别遵守 Profile 生命周期；无痕关闭后不保留站点会话数据
- AI 操作当前 session 时 UI 状态不分叉
- Debug APK、提交和推送门禁通过
