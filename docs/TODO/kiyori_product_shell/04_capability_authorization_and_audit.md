# AI 能力授权与操作记录

## 目标

让 Operit AI 通过稳定的 Kiyori Capability API 管理浏览器、播放器、文件、下载、阅读器和后续内容域，同时确保高影响操作只在明确授权后执行，并留下用户可查看的事实记录。

## 设计原则

- 页面不是 AI 接口
- 每个领域拥有自己的状态和写入权
- AI 工具通过领域 Port 发出明确命令
- 命令具有稳定资源 ID、输入、进度、取消、完成和错误语义
- 权限判断发生在领域副作用之前
- 操作记录区分请求、授权、执行结果和失败原因
- 批量命令必须展示实际影响范围

## 需要设计的内容

- 风险等级与高影响操作定义
- 单次、会话期和持久授权的边界
- 读取、修改、删除、外发、账号和付费操作的确认样式
- 批量文件、批量下载和多标签页操作的范围确认
- 执行中取消与部分完成语义
- 操作记录字段、保留周期、隐私遮盖和导出规则
- 模态 AI 抽屉及 AI 设置中的授权管理与记录入口
- 现有 Operit `ALLOW`、`ASK`、`FORBID` 工具权限如何映射到 Kiyori 领域能力

## 已确认的风险模型

风险等级由具体命令、目标、范围、可逆性、数据敏感度和外部影响共同决定，不能只按工具名称固定。批量操作、跨域编排或范围扩大可以提高风险等级，但不能降低原子操作已有等级。

| 等级 | 定义 | 典型操作 | 授权合同 |
| --- | --- | --- | --- |
| R0 只读 | 不改变本地或外部状态 | 读取当前网页信息、列出书签、查询下载状态 | 工具策略允许后执行，不弹操作确认 |
| R1 低影响 | 本地、范围明确、容易撤销或停止 | 打开标签页、播放或暂停、创建书签、启动普通下载 | 受工具策略控制，可使用持久工具授权 |
| R2 高影响 | 修改持久状态、访问敏感数据、影响多个对象或准备产生外部影响 | 移动或重命名文件、修改设置、批量下载、准备分享内容并停在系统确认界面 | 默认单次确认；仅允许用户显式授予目标和范围固定的会话期授权 |
| R3 关键操作 | 难以撤销、特权执行、账号安全、财务或不可收回的外部行为 | 永久删除或覆盖、授予其他应用权限、特权命令、发送消息、提交表单、购买、修改账号安全设置 | 每次操作确认，不提供会话期或持久免确认 |

现有工具权限与操作风险是两道不同的门：

- `FORBID` 在进入操作风险确认前阻止工具调用
- `ASK` 要求用户授权本次工具调用；若同一命令属于 R2 或 R3，界面合并展示工具、动作、目标、范围和后果，不连续弹出两次确认
- `ALLOW` 允许 R0 和 R1 按工具策略执行，但不能绕过 R2 或 R3 的操作确认
- 单工具例外只影响工具调用门，不得改变具体操作的风险等级

所有 R2 和 R3 操作都写入 AI 操作记录。R0 不进入长期操作记录；R1 只记录产生持久变化或用户后续可能需要追溯的操作。失败、取消和部分完成分别记录实际结果。

## 推荐的结构化确认合同

当前 `PermissionRequestOverlay` 主要展示操作描述、工具名称和参数，并提供拒绝、允许、始终允许。Kiyori 保留 Operit 对语义 token 的使用方式、排版和组件处理，默认色板遵守 [专业浏览器灰白默认主题](../../doc-src/decisions/0007_professional_browser_theme.md)，但 R2 与 R3 需要由结构化请求驱动，不能继续依赖一段自由文本或原始参数决定用户看到的风险信息。

每个确认请求至少包含：

- 请求来源：AI 会话、助手、工作流或插件的可识别名称与稳定 ID
- 具体动作：面向用户的动词和能力域，不能只显示内部工具名
- 目标：真实资源名称、路径、网址、账号或接收方，以及稳定资源 ID
- 范围：对象数量、批量边界和将处理的数据类别；授权后不得静默扩大
- 影响：本地持久变化、外发数据、网络请求、费用、权限提升和后台执行
- 可逆性：是否能撤销、停止或从回收站恢复
- 风险：R2 或 R3 等级以及命中该等级的具体原因
- 授权期限：仅此次，或 R2 可选的本次会话固定范围；R3 只有仅此次

确认界面遵守以下规则：

- 标题使用具体动作，例如“允许 Kiyori AI 永久删除 12 个文件？”，不能只写“权限请求”
- 目标、数量、关键后果和授权期限在首屏可见；完整参数放入可展开详情
- 敏感值默认遮盖，接收方、目标路径、域名、金额和对象数量不能被遮盖到失去决策意义
- `ASK` 与 R2 或 R3 同时命中时只显示一张确认页，并同时说明工具与操作风险
- R2 默认提供“拒绝”和“允许一次”；只有范围可冻结时才显示“本次会话”选项，默认仍为“仅此次”
- R3 提供“取消”和与动作一致的明确按钮，例如“永久删除”；不显示“始终允许”或会话授权
- Back、点击外部区域、请求超时或宿主离开都以拒绝结束，任何副作用必须发生在明确确认之后
- 批量目标在确认后发生变化时原授权失效，必须基于新范围重新确认

该结构化确认合同仍需用户确认。确认后再设计操作记录字段，使确认请求、执行事实和最终结果使用同一组稳定 ID。

## 实施顺序

1. 选取浏览器导航作为第一个只读与低影响合同样例。
2. 选取下载任务作为具有进度和取消语义的合同样例。
3. 选取文件删除作为高影响确认与记录样例。
4. 形成通用授权协议后再扩展播放器、阅读器和其他内容域。

## 验收

- AI 无法绕过 Capability API 直接写内容域状态
- 高影响命令在授权前没有副作用
- 用户可以看到请求者、目标、范围、时间和结果
- 取消、失败和部分完成不会记录为完整成功
- 权限修改对后续命令生效，并有对应测试证据
- 敏感字段不会以明文进入普通日志或操作记录
