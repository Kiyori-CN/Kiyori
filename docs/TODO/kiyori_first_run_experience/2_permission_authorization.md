# 集中权限授权

## 原则

权限页展示当前设备上的完整权限清单，不再按运行时、特殊访问和高级能力分区，也不再提供标准、
无障碍、Shizuku、Root 等执行等级选择。

每项权限继续读取 Android 或既有 owner 的真实状态。用户只选择本次希望处理的项目；应用不得绕过
系统确认、替用户点击设置或把拒绝状态写成成功。

## 状态

每项只允许以下状态：

- 已授权
- 未授权
- 设备不适用
- 需要安装或启动外部能力
- 使用时授权

不得使用本地布尔值替代 Android、Shizuku、Root 或无障碍事实。

## 选择

- 已授权项目自动选中并不可取消，状态显示“已授权”
- 未授权、部分授权和需要设置的项目默认不选中，用户可自由选择
- 设备不适用和使用时确认项目显示在清单中，但选择框不可用
- “全选可授权项”只选择当前设备上可处理且尚未授权的项目
- 无障碍、Shizuku 和 Root 是普通独立条目，不是分组或全局执行模式

无障碍条目首次执行时安装 `app/src/main/assets/accessibility.apk`。该独立应用的用户可见名称是
`Kiyori 无障碍支持`，系统无障碍服务名称是 `Kiyori UI 自动化服务`，并使用 Kiyori 品牌图标。
`com.ai.assistance.operit.provider`、服务类、authority 和
`com.ai.assistance.operit.provider.IAccessibilityProvider` 是当前 AIDL/绑定兼容标识，不参与
用户可见品牌替换。

首启读取到低于内置 `1.7` 的支持应用时，将该条目标记为“需要配置”并重新进入安装流程。继承的
`1.5` APK 使用了仓库中不存在私钥的旧签名，因此已经安装旧版的开发设备无法由 Android 原位覆盖；
这类设备需要先手动卸载一次 `com.ai.assistance.operit.provider`。全新设备直接安装 Kiyori 版本，
不受此开发迁移限制。正式发布前必须使用稳定的 Kiyori 发布签名重新封装该伴随应用。

选择集合必须使用可保存状态。启动外部系统设置前保存当前选择和处理位置；返回前台后重新读取真实
状态，并继续由用户选择的下一项。进程被系统回收时恢复第六页和选择，不自动弹出系统页面。

## 执行

底部只保留一个主按钮：

- 未选择待处理项目时显示“进入 Kiyori”
- 选择了待处理项目时显示“授权并进入 Kiyori”

点击后先使用唯一 `RequestMultiplePermissions` launcher 请求用户选中的运行时权限，再按清单顺序
处理选中的特殊访问、无障碍、Shizuku 和 Root。每次返回前台都刷新状态。所有选中项目均处理后，
直接完成首次启动并进入 Kiyori，不再打开完成摘要页。

## 完成语义

- 用户没有选择任何权限时，点击“进入 Kiyori”立即完成首启
- 用户选择权限后，以“已尝试处理所选项目”为队列终点；拒绝不会阻止进入，也不会改写真实状态
- 屏幕捕获等只能在使用时确认的能力不进入授权队列
- 首启完成时清除临时选择和队列位置，保留系统实际授权结果
- 进入应用后，权限设置页继续作为后续管理入口，但首启不再要求选择一个全局权限等级
