# 语义色与组件规则

## 视觉原则

Kiyori 的现代化不是把每个区域染成不同颜色，而是让用户在中性、稳定的表面上快速识别对象。
页面背景、工具栏、抽屉、正文卡片和浏览器 chrome 使用固定主题的 surface 层级；彩色只作为
小面积、高信息密度的识别信号。

统一结构为：

1. 中性页面背景和卡片承载阅读
2. 低饱和语义色容器承载图标
3. 同色高对比图标、状态文字或细边框表达含义
4. 正文标题保持 `onSurface`，辅助说明保持 `onSurfaceVariant`
5. 危险操作只使用红色；成功和已授权只使用绿色

## 稳定颜色词汇

| 色调 | 语义 | 典型页面 |
| --- | --- | --- |
| 蓝 | AI 对话、浏览、连接、通用主动作 | AI 对话、书签打开、浏览器设置 |
| 绿 | 完成、下载、数据、已授权 | 下载、成功状态、备份 |
| 紫 | 插件、包、收藏、扩展 | 包管理、插件、用户脚本 |
| 橙 | 工作流、自动化、运行、历史过程 | 工作流、历史、任务运行 |
| 红 | 权限风险、错误、删除、退出 | 权限、错误、退出浏览器 |
| 青 | 工具、网络、诊断、媒体发现 | 工具箱、网络日志、媒体嗅探 |
| 粉 | 角色、个性化、外观 | 助手配置、主题与角色 |

同一功能在负一屏、AI 抽屉、浏览器抽屉和独立页面必须使用同一语义色。插件提供的动态入口不
增加持久化颜色字段，而是用稳定 entry id 映射到现有色调，避免列表重排导致颜色漂移。

## 共享组件

- `KiyoriSemanticTone`：全应用唯一语义色枚举
- `KiyoriSemanticColors`：浅深主题下的图标色与低饱和容器色
- `resolveKiyoriSemanticColors`：纯函数，便于 JVM 测试对比度和唯一性
- `KiyoriSemanticIconBadge`：统一圆角、尺寸、图标缩放、禁用透明度和主题感知

设置页现有 `KiyoriSettingsIconTone` 必须被上述全应用命名完整取代，不保留类型别名或兼容
分支。该变化是未发布内部 UI 方案的正常迭代。

## 浏览器边界

浏览器地址栏、底栏、网页容器和抽屉背景继续保持中性；菜单格、空态和内容对象可使用低饱和
语义图标容器。选中状态可使用对应语义色的浅容器和细边框，但正文文字仍保持中性。网页自身
CSS、favicon 和媒体内容不受语义色系统处理。

## 深浅主题

语义色只根据当前固定 `MaterialTheme.colorScheme.background` 判断浅色或深色，不能读取用户
颜色 preference。深色容器必须使用低亮度同色背景，图标保持至少 3:1 的非文本对比度；普通
正文继续满足现有主题的 4.5:1 对比度合同。
