# 覆盖矩阵、实施顺序与验收

## 覆盖矩阵

| 区域 | 当前问题 | 目标 |
| --- | --- | --- |
| 负一屏 | 固定浅灰背景、白卡、黑灰文字；快捷图标自带黑色路径 | 完整浅深主题；数据卡和工具使用稳定语义色图标容器 |
| AI 模态左抽屉 | 所有入口统一 primary 蓝色 | 包管理/工具箱/工作流同排并按业务语义着色；工具箱数量来自唯一导航目录 |
| 浏览器菜单 | 工具矩阵全部 `onSurface` | 中性抽屉表面 + 低饱和语义图标容器；退出明确为红色 |
| 浏览器内容抽屉 | 空态、分组、选中态大多统一 primary | 书签蓝/紫、历史橙、下载绿、脚本紫、媒体青、网络青 |
| 浏览器弹窗 | 标题和对象缺少视觉锚点 | 关键弹窗增加一致图标头或语义选中关系，不改变交互 |
| 包管理 | 标签页、空态和包图标偏单一蓝色 | 插件紫、脚本包青、技能橙、MCP 蓝；卡片表面保持中性 |
| 权限 | 介绍、级别和已授权状态都使用 primary | 权限风险红、已授权绿、不同权限等级稳定分色 |
| 工作流 | 列表偏单一 primary；画布写死浅色背景和黑色标签 | 工作流橙；执行状态保持蓝/绿/红；画布完整适配深色 |
| AI 对话 | 局部个性化与应用语义色边界需复核 | 背景/气泡继续局部个性化；角色选择使用中性/蓝色卡片，默认头像为蓝色；排序菜单无阴影、保留圆角和细描边 |

## 实施顺序

1. 新增全应用语义色与图标容器，迁移设置页调用和测试
2. 改造负一屏与 AI 抽屉，先验证应用壳级影响
3. 改造浏览器菜单及 `WebSessionSheetDecor`，再逐项接入内容抽屉与弹窗
4. 改造包管理、权限和工作流根页面；单独处理 Canvas 深浅色
5. 审计 AI 对话根层和附件/工作区弹窗，确认局部外观没有越界
6. 更新 `CONTEXT.md`、决策文档和 TODO 状态

共享组件完成后先运行 Kotlin 编译，避免错误扩散；所有区域完成后统一运行定向 JVM 测试、
formal readiness、`git diff --check` 和最终 Debug APK 构建。

## 反向检查

- 浅色硬编码是否仍出现在负一屏、工作流画布和浏览器应用弹窗
- 彩色图标是否有稳定业务含义，而非按位置随机循环
- 深色模式下图标容器、Canvas 标签和状态文字是否仍可读
- 浏览器 chrome 是否仍保持中性，没有被应用蓝色大面积覆盖
- AI 对话角色背景是否只影响聊天内容层
- 是否误改了导航 route、回调、手势、WebSession owner 或包/权限/工作流状态
- 是否新增了旧全局颜色 preference、fallback、平行状态或空实现

## 本地验收

- 语义色纯函数测试：浅深色唯一、浅深不同、图标/容器对比度至少 3:1
- 页面结构测试：负一屏、AI 抽屉、浏览器菜单和包管理使用完整稳定映射
- `:app:compileDebugKotlin`
- `python -B ci/script/check_formal_readiness.py --repository . --require-main`
- `git diff --check`
- `.\gradlew.bat :app:assembleDebug --no-daemon --console=plain`
- 核验 APK 路径、时间、大小、SHA-256、包名/版本、v2 签名和 16 KB ZIP 对齐

未安装 APK、未操作设备时，真实视觉、触摸热区、折叠屏和系统深浅切换保持
`verification_pending`，不能宣称设备验收完成。
