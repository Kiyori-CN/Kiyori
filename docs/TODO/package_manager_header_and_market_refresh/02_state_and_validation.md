# 状态、实现与验证

## 唯一快照重载

`PackageManagerScreen` 使用一个挂起函数读取并应用完整 `PackageManagerSnapshot`：

- 可执行脚本包
- 全部已发现包
- ToolPkg 插件容器
- 已启用包名
- 包加载错误与结构化错误信息

首次进入、手动刷新、市场安装成功、删除包和删除冲突源都调用这一个入口。刷新期间
`isLoading=true`，同一页面不启动第二次刷新；异常写入日志并通过 Snackbar 提示，最终恢复可操作状态。

## 市场安装通知

`MarketInstallStateStore` 除现有安装进度外，增加脚本和 ToolPkg 目录修订号。只有
`MarketEntryInstallController.installArtifactEntry` 完成导入和市场安装标记写入后才递增修订号。

包管理页面观察该修订号：

- 页面仍在组合中时，修订变化立即调用唯一快照重载
- 页面在市场导航期间被销毁时，返回后由首次加载读取当前真实目录
- 初次订阅不视为新安装，避免页面创建时重复加载
- Skill 和 MCP 安装不修改这个修订号，因为它们由各自 repository 和页面刷新链路管理

## 验证

自动验证至少覆盖：

1. 插件和脚本包页的顶栏动作列表严格为四项且顺序稳定
2. Skill 与 MCP 页不发布包管理顶栏动作
3. 市场目录修订号只在明确通知时单调递增，不改变安装进度状态
4. `PackageManagerScreen` 不再绑定市场顶栏搜索，也不再声明浮动按钮
5. 插件和脚本包列表底部不再保留 `120dp`
6. 相关 JVM 测试、正式开发准备检查、资源解析、差异检查和 Debug APK 构建通过

本轮结果：

- 顶栏动作顺序策略测试通过，市场目录修订号测试通过
- `PackageManagerScreen` 源码合同检查确认旧搜索绑定、浮动按钮和 `120dp` 预留均已清除
- 目标设备验收未执行，不以本地 APK 代替真实触摸、输入法和市场返回路径证据

设备验收保持独立：

- 360dp 级窄屏顶栏标题和四个动作没有重叠
- 搜索输入法打开后列表和页签布局稳定
- 最后一项脚本包开关可以直接点击
- 从市场安装脚本和 ToolPkg 返回时列表立即出现新项目
- 手动刷新、加载错误提示和环境变量抽屉入口均可操作
