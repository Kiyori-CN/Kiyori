## 项目状态

当前版本为 `0.1.0` 开发基线，Android application ID 为 `com.kiyori`。项目尚未建立公开的正式发布渠道，请从本仓库源码构建开发版，不要将第三方 APK 视为 Kiyori 官方版本。

Kiyori 不连接 Operit 的应用更新、补丁或远程公告服务。当前也不提供应用内自动更新或手动更新检查；项目状态、源码与后续发行信息仅以 [Kiyori 仓库](https://github.com/Kiyori-CN/Kiyori) 为准。

正式开发前的工程门禁、分支规则、兼容性边界和真机验收队列见 [正式开发准备](docs/TODO/formal_development_readiness/index.md)。持续开发只使用 `main` 分支；`terminal` 子模块固定到 KiyoriTerminalCore 的提交。

## 项目简介

Kiyori 是由 Operit AI 驱动的 Android 全能型浏览器，当前代码基于 Operit 演进。浏览器是产品主体，Operit AI 作为内置 AI 子模块负责对话、理解和自动化；网页浏览、视频、音乐、小说阅读、下载、文件管理与广告拦截等能力将逐步形成独立页面，并通过受控接口开放给 AI。

Kiyori 是独立产品，不是 Operit 的品牌替换。项目保留设备端聊天、模型配置、工具调用、工作流、记忆、终端、MCP、Skill、ToolPkg 和本地模型等现有能力，同时由 Kiyori 负责应用壳、全局导航、系统设置、产品发行和后续浏览器能力。

云模型由用户自行选择服务商并配置 API Key、模型与端点，请求由设备直接发往所选服务商。Kiyori 不提供大语言模型推理或聊天请求中转。MNN 与 llama.cpp 等本地模型在模型文件准备完成后可在设备上运行。

## 目标产品结构

以下结构已经确定为正式开发目标。首个 App Shell 切片已经接管启动页、三页首页空间、五个根入口和底栏显示规则；AI 导航使用覆盖当前页面的模态左抽屉。浏览器首页首期已接入人与 AI 共用的 WebSession，软件首页、全屏网页搜索、AndroidX Multi-Profile 无痕窗口和内存网页缩略图也已接入同一 Browser Runtime。负一屏、文件管理首页和设置首页已经按固定旧版参考提交完成布局复刻；文件分类计数仍为占位值，手机存储已显示应用所在数据卷的实际可用与总容量，设置首页只有“AI 设置”接入现有页面，其余复刻按钮保持空动作。小程序首页仍是接线骨架，真机验收尚未完成：

```text
Kiyori App Shell
├── 软件首页
│   └── 负一屏 ← 软件首页 → AI 首页
├── 浏览器首页
├── 小程序首页
├── 文件管理首页
└── 设置首页
```

应用启动后进入软件首页。负一屏、软件首页和 AI 首页共享同一 Pager 状态、释放速度与吸附物理；页面跟随手指移动，未结束的滑动可被立即反向手势中断。软件首页在手机、平板和横屏都保持“标题在上、搜索框在下”的居中单列：常规高度把搜索框顶部描边精确放在可用首页高度的 `38.2%`，短高度按标题完整可见所需的最小顶部位置布置；Compact、Medium 和 Expanded 的内容宽度上限分别为 `544dp`、`584dp` 与 `624dp`，对应最小水平留白为 `24dp`、`48dp` 与 `72dp`。标题右上方显示约 `18dp` 的小圆环标志，搜索框常规高 `114dp`、短布局高 `96dp`，内部与页面同色，只用约 `1dp` 的绿、青、紫、橙五色闭环渐变描边定义边界，不绘制外侧扩散、模糊或阴影。搜索与 AI 位于同一个 `120×32dp` 圆角分段框内，左右严格等宽，文字和选项图标不随边框缩小；选中项在亮色使用 `#2F6FED`、暗色使用 `#79A7FF`，并配合 `10%` 不透明度的同色圆角底，按压水波限制在圆角选区内。选项本身不导航；点击搜索框主体时，搜索模式打开全屏网页搜索，AI 模式进入现有 AI 首页、保留会话和草稿，并在页面稳定后聚焦真实输入框和弹出输入法。模式在返回首页和旋转后保持，冷启动默认搜索。附件、语音和相机仍是右下角立即动作，其中附件入口使用 AI 首页默认 Agent 输入栏同一 `24dp` 加号；三项动作都会先进入 AI 首页，再分别调用现有附件面板、全屏语音会话和相机拍照流程，单次点击只消费一次。

软件首页左上角在获得 Android 定位权限后自动显示当前城市、温度和天气图标，点按后用当前搜索引擎打开该城市天气；右上角直接复用浏览器底栏第四项的方框数字图标显示共享 Browser Runtime 真实窗口数，点按后进入同一个原窗口总览。天气使用 Android 定位与 `Geocoder` 解析城市，并把经纬度发送给 Open-Meteo 获取当前摄氏温度和 WMO weather code；不保存或显示未确认的城市和温度。Open-Meteo 免费接口限非商业用途并受服务限制，坐标处理与保留规则见其[服务条款](https://open-meteo.com/en/terms)，商业发布前必须重新确认许可与 provider。

全屏网页搜索自动聚焦输入框，直接复用浏览器的搜索引擎和普通模式最近记录。软件首页和浏览器顶栏的两个入口共用右侧浏览模式控件：睁眼表示有痕模式，闭眼表示无痕模式；图标按钮不绘制外框、底色或阴影，切换后只在导航栏上方短时显示使用 `inverseSurface/inverseOnSurface`、随亮暗主题自适应的“已开启无痕模式”或“已关闭无痕模式”，不展示常驻长说明。该控件同步 Browser Runtime 的新窗口默认 Profile；软件首页提交始终创建并激活新的共享 WebSession，再进入 Browser Home，因此不会覆盖用户当前正在浏览的窗口。浏览器顶栏提交在所选 Profile 与活动窗口一致时继续当前窗口，不一致时创建对应 Profile 的新窗口。AI 能立即通过 `browser_tabs list` 发现这些窗口。底部五入口只在五个根页面显示，负一屏和保持全屏形态的 AI 首页隐藏底栏。AI 首页即使尚未配置模型或 API Key，也始终显示对话界面和输入框；模型配置由独立 AI 设置页承载，缺少凭据不会阻塞页面进入。AI 首页及 AI 一级根页面的左上角三横线按钮打开模态 AI 左抽屉，深层页面改为返回按钮；从快捷方式或外部入口直达一级根页面时也遵守同一规则。模态 AI 抽屉和 Kiyori 设置首页进入同一份 AI 设置页面与持久状态；前者根页面 Back 返回 AI 首页，后者显示返回语义并回到设置首页，跨来源进入时从 AI 设置根页开始。

浏览器首页、浏览器悬浮窗和 Operit AI 浏览器工具使用同一进程内 WebSession。三者共用标签、活动 WebView、历史、书签、下载和用户脚本；展示位置切换只转挂同一个 WebView。每个窗口持有不可变的 `normal` 或 `incognito` Profile：普通窗口继续使用默认 WebView Profile，同一段无痕会话的窗口共享唯一命名的 Kiyori 私有 AndroidX Profile 代际；最后一个无痕 WebView 销毁后清理 Cookie、WebStorage 和定位授权并立即退休该代际，后续无痕窗口使用全新代际。AndroidX 不允许在同一进程删除已加载 Profile，因此退休代际在下次冷启动、尚未重新加载时物理删除。网页 Cookie、缓存、WebStorage、userscript Cookie/XHR 和下载请求均跟随窗口 Profile，普通与无痕之间不复制网站数据；无痕搜索、访问和标题更新不写入共享历史，书签与下载仍保留用户明确发起的持久化语义。悬浮浏览器展开后，背景延伸到状态栏和挖孔区域；系统 Back 与左上角返回都先按同一浏览器状态机关闭当前浮层，再把网页收缩为悬浮球，不会让网页后退。AI 可通过 `browser_tabs list` 看到人工打开的全部窗口及其稳定 `session_id`、`profile`、标题、网址和活动状态，也可用 `browser_tabs create profile=normal|incognito` 显式新建，再继续读取快照、点击和输入。无痕只隔离网站数据，不隔离用户已授权的 Kiyori AI 操作。浏览器窗口页顶部只保留普通/无痕 selector，按手机和平板宽度使用 2、3、4 列，并显示 `postVisualStateCallback` 驱动、仅驻留内存的 `5:8` 纵向网页缩略图；捕获完整保留当前可见 WebView 视口，不裁切网页。新建与清空只作用于当前 selector。设备 WebView 不支持 Multi-Profile 或冷启动无法安全清理旧无痕 Profile 时，入口会明确禁用，不会创建普通窗口代替。从 AI 首页顶栏打开 Browser Home 后，浏览器返回会回到 AI 首页并恢复悬浮球。App Shell 与浏览器底栏沿用 Kiyori 自有图标：五等分槽位使用 `16dp` 横向、`0dp` 顶部和 `6dp` 底部边距，点击区 `44dp`，普通图标 `26dp`，首页中间图标 `25dp`；浏览器窗口计数为 `20dp` 方框和 `1.75dp` 描边，软件首页第五个设置入口使用旧版 `icons/设置-齿轮` 的完整六边形齿轮图形。浏览器底栏第五按钮打开内容自适应的四行菜单，前三行使用五列 `21dp` 描边图标和紧凑固定间距，第四行直接用 `SpaceBetween` 排列退出、收起、设置三个 `46×36dp` 按钮与 `22dp` 图标，其中设置按钮与软件首页设置入口共用同一完整齿轮资源；菜单不再使用五槽占位或固定 `324dp` 抽屉高度。菜单“无痕模式”进入真实窗口页，“AI 对话”回到 AI 首页，“浏览器设置”打开与设置首页相同的页面，“退出浏览器”只移除展示层，清空全部窗口才清理 session。自定义主页同时约束主页按钮及人工/AI 新窗口；关闭“允许网页打开应用”会阻止网页外部 scheme，关闭“允许网页获取位置”会拒绝 WebView 定位请求。首期继续使用设备的 Android System WebView provider。网页 `http/https` 下载默认先显示文件名、类型、已知大小和下载器确认；设置可关闭确认，也可在内置与系统下载器之间选择。内置任务继续使用唯一 JSON 记录和全局 FIFO，默认同时运行 3 个任务，并在 `128 / max(normalThreads, m3u8Threads)` 的总请求预算内提供最高 `1..8` 并发；普通格式线程候选为 `3/6/12/20/32` 且默认 `6`，M3U8 线程继续为 `3/8/16/20/32/48/64` 且默认 `16`。新任务冻结创建时的普通/M3U8 线程、M3U8 自动合并、分块大小、HTTP 协议、自动转存和 SAF 目标。普通内置文件默认保留在应用下载目录；启用“自动转存公开目录”后，完整文件才复制到 `Download/Kiyori/browser/downloads/` 并删除应用目录源文件，该设置与 SAF 自定义目录互斥。实际 Range 分段保证每段至少 1 MiB，服务器不支持 Range 或长度未知时使用单线程。HEAD 与精确 `0-0` 元数据探测和正文传输使用同一五次有界重试。M3U8 自动合并关闭时只保存 playlist 文本；开启时按最高 `BANDWIDTH` variant 下载 KEY/MAP/分片到同目录 companion package 并改写本地 URI，离线包固定保留在应用下载目录，不移动到 SAF 或公开目录。SAF 写入失败会明确标记任务失败，不改变目标。更换、清除自定义目录或启用自动公开转存时，只有当前设置和既有任务都不再引用旧目录才释放其持久化 URI 权限。系统模式由 Android `DownloadManager` 完整持有，任务只出现在系统下载界面，不复制到 Kiyori 下载抽屉，也不消费 SAF、自定义协议或 APK 自动清理；`blob:` 与 `data:` 网页内联数据仍由内置 manager 保存。已完成的内置任务可重命名、修改后缀、移动到 SAF 目录、复制下载链接或保存位置、分享文件，并手动转存到公开目录；移动和转存只在复制成功后删除源文件。启用“安装包自动清理”后，成功唤起内置 APK 的系统安装器会在 90 秒后删除对应任务记录和当前文件。内置任务完成或失败时可由“下载完成强提示”控制 Toast，系统任务继续使用系统通知。进程恢复不会自动联网，而是等待用户明确恢复；浏览器与负一屏共用的下载抽屉和文件下载器设置界面都读取同一个 Kiyori owner。浏览器菜单里的下载抽屉保留既有拖动与展开动画，内容使用“已下载 / 下载中”双页签，并提供新增、清空、排序、批量删除、文件管理、时间、分类和设置入口。手动新增会以当前默认下载器为初始选择，但本次可明确切换内置或系统下载器；负一屏在没有活动 WebSession 时使用独立请求上下文，不创建隐藏标签或 WebView；已完成网络任务可创建新的重新下载任务，路径型 M3U8 离线包可在本机通过 FFmpeg 合并成 MP4，成功后同一任务切换到生成的 MP4 文件。

浏览器菜单的“UA标识”会先收起菜单，再直接显示居中的六项选择弹窗，不进入下拉抽屉。Android、PC桌面、IPhone 和塞班Wap使用固定预设；自定义全局保存一条非空 UA，自定义该网站按规范化域名保存规则，并提供默认、四种预设和完整域名快捷操作。显式 WebSession UA、命中的站点规则和全局模式按固定优先级作用于同一 Browser Runtime；修改后只重载当前活动页，后台标签不被无提示刷新。

浏览器菜单的“网络日志”会先退出主菜单，再打开与书签、下载相同的半展开/全展开抽屉。日志只读取当前活动 WebSession 在本页捕获的真实请求，最多保留 500 条内存记录，并按网址、请求方法及视频、音乐、图片、网页、其他分类搜索筛选；跨 host 请求显示“第三方”提示，但不直接判定为广告或失败。点击条目可复制完整链接、交给当前默认下载器、外部打开或查看请求方法、分类、主页面/子资源与捕获时间。Android WebView 未提供的响应状态、响应 MIME 和拦截结果不会被补写；列表也不会加载图片缩略图而制造新的网络请求。清空只影响当前窗口的网络日志，不改变网页、历史、下载或其他窗口。

浏览器菜单的“加书签”图标固定不变，已收藏页面只把文字改为“移除书签”。新增书签会打开网站名称、网址、网址图标和书签文件夹四个可编辑字段；文件夹选择第一行是 `/`，之后按书签界面的手动顺序深度优先排列，一级文件夹顶格，子级逐层缩进且只显示当前文件夹名。书签按钮使用与下载相同的半展开/全展开抽屉宿主，提供动态文件夹标题、搜索、可点击路径、文件夹树、favicon、排序、拖拽、导入导出、秘密空间和指定长按操作；当前页、新窗口和后台窗口仍使用同一个 Browser Runtime。书签与下载的菜单统一使用紧凑选项、触发位置锚定和点击阻断遮罩，编辑、排序、确认和操作弹窗居中显示并遮暗弹窗外区域。

下载抽屉顶部菜单显示时，点击菜单周围区域会立即收起，菜单本体点击不会穿透。共享下载抽屉只在显示或执行退出动画时挂载，完全隐藏后会移除全屏遮罩与点击树，不会阻断软件首页的 Pager、搜索框或快捷按钮。抽屉内容会随半展开、完全展开和拖动过程中的实际可见高度连续重排，列表在任一稳定状态都能滚动到第一项和最后一项；“已下载”为空时显示“当前没有已下载文件”，“下载中”为空时显示“当前没有下载任务”。悬浮浏览器中的“修改文件夹”通过独立透明 Activity 持有系统 SAF 目录选择结果，不依赖悬浮 View tree 提供 Activity owner。批量取消只允许选择当前仍可取消的排队、连接、下载或暂停任务，并调用取消动作；它不复用批量删除，也不会删除任务记录或文件。SAF 目录选择或移动失败后，如果该目录没有被当前设置或其他任务持有，Kiyori 会释放本次持久化授权。

设置首页按 `kiyori-android@24a2dfa9` 复刻：顶栏含四个旧版图标，主体以四张无外描边的白色卡片展示 `4/4/4/4` 共 16 个入口；“AI 设置”进入现有唯一 AI 设置页，“网页浏览器”进入复刻的浏览器设置页，“文件下载器”进入文件下载器设置页，“视频播放器”进入真实播放器设置页，其余入口与顶栏按钮暂时为空动作。网页浏览器、文件下载器和视频播放器设置共用同一套子页面视觉：分组卡片不绘制最外围描边；折叠标题初始位于固定返回键下方，并在列表前 `72dp` 滚动中连续向右上移动、从 `26sp` 缩小到 `20sp`，到达 `56dp` 固定顶栏后保持完整显示。浏览器设置保留旧版 `5/5/2/5/6` 五组顺序、尺寸和勾选框视觉；自定义主页、允许网页打开应用、允许网页获取位置和悬浮嗅探偏好已接入唯一设置 owner，其余旧版未实现项目仅打开同标题空页面或保留不可交互勾选状态。浏览器菜单“悬浮嗅探”读取当前 WebSession 被动发现的视频候选，播放会按设置进入浏览器内悬浮 mpv 或同会话全屏播放器，下载继续进入唯一 BrowserDownloadManager；候选 headers 与 Cookie 不显示在界面。浏览器菜单“下载”和负一屏“下载”卡进入同一个共享下载下拉抽屉；抽屉统一使用“已下载 / 下载中”双页签显示 Kiyori 内置下载任务。文件下载器设置保留旧版 `5/3/3/1` 十二行，十二项均已接入固定参考中的真实 consumer：默认下载器、SAF 自定义目录、同时任务数、普通/M3U8 线程、M3U8 自动合并、自动转存公开目录、七档分块大小、安装包自动清理、下载确认、完成提示和 HTTP 协议。选择抽屉使用 `13dp` 标题与取消区垂直留白、`10dp` 选项垂直留白、`44dp` 最小选项高度和 `20dp` 勾选图标；默认普通/M3U8 线程为 `6/16` 时同时任务完整显示 `1..8`。普通或 M3U8 线程提高时会同步收窄之后可选的同时任务数，已经运行的任务不会被取消；自动合并、自动转存、分块大小和协议只约束之后创建的任务。启用自动转存会清除 SAF 自定义目录，选择 SAF 目录会关闭自动转存。完成任务的更多操作可执行重命名、修改后缀、移动、复制下载链接或保存位置、分享和转存公开目录。腾讯 X5 调试在当前 Android System WebView 架构中为空页面。文件管理首页展示 8 个分类、7 个快捷访问和 4 个存储位置，分类计数固定为 0，手机存储在页面进入及恢复前台时刷新实际可用与总容量。搜索引擎、搜索记录、新窗口默认普通/无痕 Profile、桌面/手机 UA、历史与 WebSession 状态仍由浏览器现有 owner 持有。普通网站数据继续保留；无痕网站数据在最后一个无痕窗口关闭后立即停止复用，并在下次冷启动物理删除退休 Profile。

软件首页、负一屏、底部五入口对应页面和 AI 页面共用 edge-to-edge 状态栏：页面背景延伸到手机顶部，交互内容避开状态栏和挖孔。抽屉遮罩仍覆盖整个窗口，但抽屉面板从状态栏底部开始，面板内容不重复加入顶部 inset。状态栏显示时始终透明，外观设置只保留“隐藏状态栏”，不再提供透明开关或自定义状态栏颜色。

抽屉提供动态网络状态、包管理、权限授予、工作流、AI 对话、助手配置、记忆库、工具箱、ToolPkg 动态插件和 AI 设置；WiFi 网络显示为“WiFi”。包管理中的“插件”标签管理 ToolPkg 容器，包括随 APK 预置和从市场安装的插件；普通 JS、TS 与 HJSON 工具项目位于独立的“脚本包”标签。插件继续使用 Operit 市场的 `package/toolpkg_v2` 协议，并可注册抽屉页面、输入框菜单、消息处理和配置页面。原生 AI 一级根保留独立状态与子栈，ToolPkg 页面只在其路由声明 `keepAlive=true` 时保留状态。对话历史、新建和删除对话继续由 AI 首页原有历史选择器负责，不复制到抽屉；Terminal 仍只保留在 AI 首页右上角。负一屏按旧 Kiyori 固定布局展示收藏、书签、历史、下载四张数据卡，以及新版、手册、版本、搜索、工具箱、清理、备份、退出八个空动作快捷工具；书签卡显示普通空间真实书签数并打开共享书签抽屉，下载卡显示真实任务数并打开共享下载抽屉，收藏和历史仍为零计数占位。

抽屉保留原版“权限”高频入口，并继续进入 `Screen.ShizukuCommands`。AI 设置中的 AI 工具授权继续由 `ToolPermissionSystem` 持有；Kiyori 权限中心仍是系统设置目标，但当前复刻设置首页尚未提供入口。三者不复制或混合状态。权限中心以只读总览区分设备能力与 AI 工具授权；高影响操作策略与操作记录将在安全合同中继续设计。备份、聊天记录、Token 统计和修改其他应用权限的工具仍保留在各自原有领域。

模态 AI 左抽屉只能由三横线按钮打开，并通过遮罩点击或系统 Back 关闭。左边缘打开、横向拖动、滑动关闭、主内容倾斜/缩放、平板永久侧栏和抽屉专属主题设置均不属于 Kiyori App Shell。其他功能页内部为自身工作流使用的局部抽屉组件不属于这项顶层导航。

“权限”高频卡片继续使用 Operit 原版短标签和视觉。徽标只显示当前启用功能缺少的必要设备授权数量，无待处理项时显示“正常”；AI 工具授权策略不计入该徽标。

高影响操作确认与 AI 操作记录共同归入权限中心的“AI 安全”分组。AI 操作按 R0 只读、R1 低影响、R2 高影响、R3 关键操作分级；工具被设为允许也不能绕过 R2 或 R3 的操作确认。对应策略页和记录页完整实现前不显示空入口。

Kiyori 新页面的视觉语言向 Operit 原版 UI 看齐，页面结构、浏览器行为和其他 Kiyori 功能参考 [kiyori-android@24a2dfa9](https://github.com/Kiyori-CN/kiyori-android/tree/24a2dfa91f0a4166dc58e5c4732d11861173f766)。手机、平板与折叠屏共享同一导航状态；AI 抽屉按窗口宽度使用 `75%`、`320dp` 或 `360dp`，并限制在折叠屏分隔铰链左侧。详细设计见 [Kiyori 产品壳与导航架构](docs/doc-src/architecture/kiyori_product_shell_and_navigation.md)。

“视频播放器”入口已经不是空动作：它进入与浏览器/下载器一致的折叠标题和分组卡片页面，硬件解码、默认倍速、精准定位、快进/快退时长、网络缓存、字幕缩放、后台行为、全屏返回、播放结束行为和 Anime4K 模式均由唯一 `PlayerSession` 真实消费。播放器接收系统 `ACTION_VIEW` 的本地 `content://`、`file://` 与网络视频，也接收浏览器候选；浏览器悬浮与全屏只转挂同一个 mpv core 的 Surface。

## 构建

### 环境要求

- Windows、macOS 或 Linux
- JDK 21（Gradle 运行时；Java/Kotlin 字节码目标仍为 JVM 17）
- Android SDK Platform 36、target SDK 34、Build Tools 36.0.0、NDK 28.2.13676358、CMake 3.22.1
- rustup、Rust 1.88.0 与 `aarch64-linux-android` target，用于构建 APK 内的 native ripgrep
- Git 与 Git submodule 支持

### 获取源码

```bash
git clone --recurse-submodules https://github.com/Kiyori-CN/Kiyori.git
cd Kiyori
rustup toolchain install 1.88.0 --profile minimal
rustup target add --toolchain 1.88.0 aarch64-linux-android
```

项目部分大型模型和本地运行库未直接存放在 Git 仓库中。若构建提示缺少 `models`、`subpack`、`jniLibs` 或 `libs` 内容，请按项目内构建配置补齐对应本地依赖。`liboperit_ripgrep.so` 不属于手工依赖；Gradle 会从 `tools/native_ripgrep` 构建到 `app/build/generated/` 并自动打入 APK。

### 构建 Debug APK

Windows：

```powershell
.\gradlew.bat assembleDebug --console=plain
```

macOS 或 Linux：

```bash
./gradlew assembleDebug --console=plain
```

输出目录为 `app/build/outputs/apk/debug/`。

- 数据库、偏好、备份、工作区和文件格式标识
- 插件、ToolPkg、MCP 的协议标识与既有备份格式

Kiyori 的产品版本与 Operit 插件生态兼容版本分别维护。市场会按当前继承的 Operit 运行时兼容版本检查插件声明的 `minAppVer` 和 `maxAppVer`，不会使用 Kiyori 的 `0.x` 产品版本误判插件不兼容，也不会跳过发布者声明的版本范围。

由于当前 application ID 是新的 `com.kiyori`，历史 `com.ai.assistance.operit` 安装不能直接覆盖。需要先在旧应用中导出备份，再在 Kiyori 中通过明确的备份或文件选择入口导入。Kiyori 新建的公共运行数据使用 `Download/Kiyori`；应用不会自动扫描、合并、迁移或删除 `Download/Operit`。既有备份格式和插件协议标识继续保留。
