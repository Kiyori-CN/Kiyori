## 项目状态

当前版本为 `0.1.0` 开发基线，Android application ID 为 `com.kiyori`。项目尚未建立公开的正式发布渠道，请从本仓库源码构建开发版，不要将第三方 APK 视为 Kiyori 官方版本。

Kiyori 不连接 Operit 的应用更新、补丁或远程公告服务。当前也不提供应用内自动更新或手动更新检查；项目状态、源码与后续发行信息仅以 [Kiyori 仓库](https://github.com/Kiyori-CN/Kiyori) 为准。

正式开发前的工程门禁、分支规则、兼容性边界和真机验收队列见 [正式开发准备](docs/TODO/formal_development_readiness/index.md)。持续开发只使用 `main` 分支；`terminal` 子模块固定到 KiyoriTerminalCore 的提交。

## 项目简介

Kiyori 是由 Operit AI 驱动的 Android 全能型浏览器，当前代码基于 Operit 演进。浏览器是产品主体，Operit AI 作为内置 AI 子模块负责对话、理解和自动化；网页浏览、视频、音乐、小说阅读、下载、文件管理与广告拦截等能力将逐步形成独立页面，并通过受控接口开放给 AI。

Kiyori 是独立产品，不是 Operit 的品牌替换。项目保留设备端聊天、模型配置、工具调用、工作流、记忆、终端、MCP、Skill、ToolPkg 和本地模型等现有能力，同时由 Kiyori 负责应用壳、全局导航、系统设置、产品发行和后续浏览器能力。

云模型由用户自行选择服务商并配置 API Key、模型与端点，请求由设备直接发往所选服务商。Kiyori 不提供大语言模型推理或聊天请求中转。MNN 与 llama.cpp 等本地模型在模型文件准备完成后可在设备上运行。

## 目标产品结构

以下结构已经确定为正式开发目标。首个 App Shell 切片已经接管启动页、三页首页空间、五个根入口和底栏显示规则；AI 导航使用覆盖当前页面的模态左抽屉。浏览器首页首期已接入人与 AI 共用的 WebSession，软件首页、全屏网页搜索、AndroidX Multi-Profile 无痕窗口和内存网页缩略图也已接入同一 Browser Runtime。负一屏、文件管理首页和设置首页已经按固定旧版参考提交完成布局复刻；文件分类计数仍为占位值，手机存储已显示应用所在数据卷的实际可用与总容量。设置首页当前已接通账号与连接、AI 助手、语音服务、网页浏览器、视频播放器、文件下载器、界面定制和数据备份与同步；小程序管理只为底部第三个小程序产品域保留空入口，不连接 AI 包管理。Kiyori 主题系统保留固定浅色、深色与跟随系统模式，不允许用户颜色重写整个应用；AI 对话背景、气泡、头像、聊天头部和输入区仍可局部个性化。小程序首页仍是接线骨架，真机验收尚未完成：

```text
Kiyori App Shell
├── 软件首页
│   └── 负一屏 ← 软件首页 → AI 首页
├── 浏览器首页
├── 小程序首页
├── 文件管理首页
└── 设置首页
```

应用启动后进入软件首页。负一屏、软件首页和 AI 首页共享同一 Pager 状态、释放速度与吸附物理；页面跟随手指移动，未结束的滑动可被立即反向手势中断。软件首页在手机、平板和横屏都保持“标题在上、搜索框在下”的居中单列：常规高度把搜索框顶部描边精确放在可用首页高度的 `38.2%`，短高度按标题完整可见所需的最小顶部位置布置；Compact、Medium 和 Expanded 的内容宽度上限分别为 `544dp`、`584dp` 与 `624dp`，对应最小水平留白为 `24dp`、`48dp` 与 `72dp`。标题右上方显示约 `18dp` 的小圆环标志，搜索框常规高 `114dp`、短布局高 `96dp`，内部与页面同色，只用约 `1dp` 的绿、青、紫、橙五色闭环渐变描边定义边界，不绘制外侧扩散、模糊或阴影。搜索与 AI 位于同一个 `120×32dp` 圆角分段框内，左右严格等宽，文字和选项图标不随边框缩小；选中项在亮色使用 `#2F6FED`、暗色使用 `#79A7FF`，并配合 `10%` 不透明度的同色圆角底，按压水波限制在圆角选区内。选项本身不导航；点击搜索框主体时，搜索模式打开全屏网页搜索，AI 模式进入现有 AI 首页、保留会话和草稿，并在页面稳定后聚焦真实输入框和弹出输入法。模式在返回首页和旋转后保持，冷启动默认搜索。附件、语音和相机仍是右下角立即动作，其中附件入口使用 AI 首页默认 Agent 输入栏同一 `24dp` 加号；三项动作都会先进入 AI 首页，再分别调用现有附件面板、全屏语音会话和相机拍照流程，单次点击只消费一次。

软件首页左上角在获得 Android 定位权限后自动显示当前城市、温度和天气图标，点按后用当前搜索引擎打开该城市天气；晴天在浅色主题使用清晰的琥珀色 `#C57C00`、深色主题使用明亮的金黄色 `#FFD166`，不与底栏选中色强制一致。云雨使用蓝色，阴天、雾和雪使用青色，雷暴使用紫色，权限或数据异常使用红色或橙色。右上角直接复用浏览器底栏第四项的方框数字图标显示共享 Browser Runtime 真实窗口数，点按后进入同一个原窗口总览。天气使用 Android 定位与 `Geocoder` 解析城市，并把经纬度发送给 Open-Meteo 获取当前摄氏温度和 WMO weather code；不保存或显示未确认的城市和温度。Open-Meteo 免费接口限非商业用途并受服务限制，坐标处理与保留规则见其[服务条款](https://open-meteo.com/en/terms)，商业发布前必须重新确认许可与 provider。

全屏网页搜索自动聚焦输入框，直接复用浏览器的搜索引擎和普通模式最近记录。顶部返回、搜索框和浏览模式按钮与 Browser Home 顶栏使用完全相同的左右边距、槽间距、动作区和搜索框宽度；搜索框保持顶部与左右宽度不变，文本自动换行并平滑向下增加到三行，超过三行后只在三行视口内上下滚动。搜索框左侧只显示当前引擎图标与展开箭头，并随输入框高度始终垂直居中；引擎选择器使用淡蓝覆盖式浮层、白色选项框、黑色文字和真实品牌图标，不下推当前网页或搜索历史。当前网页显示页面标题与网址两行，右侧提供蓝色复制链接和编辑链接图文动作，编辑会把网址回填到搜索框。搜索历史使用自适应宽度标签，垃圾桶进入编辑模式后才显示标签删除叉号；单个标签删除在点击“完成”后提交，“清空”则弹出底部确认框，确认后立即清空并退出编辑模式。软件首页、浏览器顶栏和浏览器菜单的无痕入口共用同一个浏览模式控制：睁眼表示有痕模式，闭眼表示无痕模式；切换后只短时显示使用 `inverseSurface/inverseOnSurface`、随亮暗主题自适应的“已开启无痕模式”或“已关闭无痕模式”，不展示常驻长说明。浏览器菜单点击无痕时保持菜单显示，不进入窗口总览，也不转换当前标签不可变的 Profile。该控件同步 Browser Runtime 的新窗口默认 Profile；软件首页提交始终创建并激活新的共享 WebSession，再进入 Browser Home，因此不会覆盖用户当前正在浏览的窗口。浏览器顶栏提交在所选 Profile 与活动窗口一致时继续当前窗口，不一致时创建对应 Profile 的新窗口。AI 能立即通过 `browser_tabs list` 发现这些窗口。底部五入口只在五个根页面显示，负一屏和保持全屏形态的 AI 首页静止时隐藏底栏；从负一屏或 AI 首页向软件首页拖动后，底栏按 Pager 的实时偏移立即同步显现，不等待页面吸附完成。未选中时保持原空心矢量，选中时取消蓝色描边，使用精确的 `#FFC153` 内部填充和当前页面背景色细节。每个填充 Vector 按自身可见边界补偿到与原空心图标相同的最终视觉尺寸，设置入口只重绘内部圆环，不残留外缘描线。每次点击都会从较小填充态连续弹性放大到最终尺寸，重复点击当前入口也会重新触发；首页、浏览器、小程序和文件入口使用更低阻尼获得更大的黄色峰值，最右侧设置入口保持原峰值。AI 首页即使尚未配置模型或 API Key，也始终显示对话界面和输入框；模型配置由独立 AI 设置页承载，缺少凭据不会阻塞页面进入。AI 首页右上角的浏览器、终端和工作区动作分别使用蓝、青、紫三种稳定语义色，终端和工作区仅在活动时增加低饱和同色容器。AI 首页及 AI 一级根页面的左上角三横线按钮打开模态 AI 左抽屉，深层页面改为返回按钮；从快捷方式或外部入口直达一级根页面时也遵守同一规则。模态 AI 抽屉和 Kiyori 设置首页进入同一份 AI 设置页面与持久状态；前者根页面 Back 返回 AI 首页，后者显示返回语义并回到设置首页，跨来源进入时从 AI 设置根页开始。

上述 AI 设置入口当前统一显示为“AI 助手”。它只承载模型与 API、功能模型、用户偏好、提示词、人设、分句回复、上下文、AI 工具授权、Token 统计和外部 HTTP 对话；包管理、MCP、Skill、ToolPkg 和工作流继续留在各自 AI 导航目的地，不进入设置首页的“小程序管理”。

“模型与 API”中的模型名称使用有序标签列表管理：标签按可用宽度自适应换行，默认只显示前三行完整标签；存在隐藏模型时，第三行以无删除叉号的“还有 N 个”标签显示真实剩余数量，点击整个标签展开全部。模型总数仍由标题右侧“共 N 个”显示；收起状态不通过高度裁切完整列表，因此不会露出后续行的半截标签。展开时显示全部标签，每个可见标签中的长模型名会自动换行而不省略或裁切。第一项明确标记为测试模型，点击标签复制名称，点击叉号删除，长按进入拖拽排序。用户可以手动输入一个或多个模型名称，也可以从上游获取模型后在底部面板中搜索和多选；当前上游模型默认勾选且可以取消，应用更改只同步本次上游范围内的添加和移除，上游未返回的手动或历史模型继续保留。模型顺序变化会按模型名称同步功能模型和固定角色卡的绑定，删除有绑定的模型需要明确确认替代模型，删除操作支持撤销；清空全部会先显示绑定检查状态，无绑定时进入确认，有绑定时显示明确的无法清空对话框。添加、上游、更多以及重命名、删除、测试模型六个入口共享更紧凑的单行操作样式，测试结果会显示实际测试模型名。

全屏搜索页的紧凑尺寸以浏览器下拉抽屉菜单为基准：顶部两侧动作区为 `40dp`，搜索框单行基准高
`42dp`，操作图标使用约 `21dp`，标签文字使用约 `11–12sp`。搜索历史垃圾桶为 `26dp`，标题行固定
`34dp`，因此进入“清空 / 完成”状态时标题不会上下移动；复制与编辑图标向文字轻微靠近。浏览器顶栏
右侧固定显示刷新图标，点击始终重新加载当前网页，不切换成叉号，圆形按压反馈与无痕按钮一致。引擎
面板显示时点击周围区域会收起；点击当前网页的标题与网址区域会直接返回现有网页，不触发第二套页面状态。

自 2026-07-28 的方案 A 起，完整浏览器界面只在现有 `MainActivity` / Kiyori App Shell 的 Browser Home 中显示。返回目标与离开后的 presentation 方式分开记录：从负一屏、软件首页、AI 对话、微应用、文件管理或设置首页进入 Browser Home 时，Shell 记录真实入口页；2026-08-08 起，浏览器顶栏左侧返回会直接释放当前 Browser Home presentation 并回到该入口页，不消费 WebView 历史。普通入口关闭展示后不显示 indicator；浏览器菜单点击“AI 对话”会进入 AI 首页、请求真实输入框焦点并把当前页缩为 indicator，AI 首页右上角浏览器按钮进入 Browser Home 后顶栏返回或系统 Back 最终退出时仍恢复 indicator。AI `browser_*` 在 Browser Home 未挂载时主动使用浏览器，同样可通过唯一 WebSession 建立 1×1 background anchor 并显示 indicator。单击已有 indicator 通过专用恢复入口回到 Browser Home，再次退出仍恢复同一个 indicator。长按 indicator 会消费本次进入动作，并在球体右上角外围创建一个透明的 `28dp` 临时触控层，其中只绘制较小的 `16dp` 红色叉号。按住期间叉号不可触摸，不会抢走当前手势；松手后才允许点击并保留 3 秒。叉号随球体拖动并约束在屏幕内，点击后与浏览器下拉抽屉第 4 行第 1 个“退出浏览器”按钮复用同一 `onExitBrowser` 展示层关闭流程。临时叉号不持有 WebView、session 或第二套 Browser Runtime。人工界面与 Operit AI `browser_*` 始终共用同一组 WebSession、稳定 `session_id`、`activeSessionId` 和实际 WebView，宿主转换不执行 `loadUrl`、`reload` 或 WebView 重建。下一段中关于“悬浮浏览器展开”、overlay Back、状态栏和挖孔的旧说明仅作为历史记录，已由本段当前行为取代。

网页 `http/https` 下载默认显示文件名、类型、已知大小和下载器确认，设置可跳过确认或选择 Kiyori 内置下载器与 Android 系统下载器。内置任务只由 `BrowserDownloadManager` 的原子 JSON 记录和全局 FIFO 持有；默认并行 3 项，普通线程为 `3/6/12/20/32`、M3U8 线程为 `3/8/16/20/32/48/64`，并受 `128 / max(normalThreads, m3u8Threads)` 总请求预算限制。新任务冻结线程、M3U8 离线包、分块、HTTP 协议、保存位置、网络条件和漫游策略。普通 Range 下载按至少 1 MiB 分片，使用强校验器保证断点续传不会拼接不同远端版本。M3U8 离线包受文本、深度、循环、资源规模和完整性校验；独立音轨、画面或字幕 playlist 会明确拒绝。普通文件可保存到应用目录、完整后转存公开目录或写入 SAF；离线包固定留在应用目录。系统下载器任务完全归 Android 所有，不镜像进 Kiyori。完成的内置任务支持重命名、修改后缀、移动、复制链接或位置、分享、公开转存、重新下载和 M3U8 到 MP4 的本地封装。APK 自动清理只在系统报告精确包名和版本安装成功后删除，取消安装不会清理。进行中通知、完成/失败通知和共享下载抽屉都读取同一个 owner；进程恢复不自动联网，等待用户明确恢复。共享“我的下载”抽屉使用绿色语义标题徽标、菜单触发器和统一操作弹窗容器；四竖线菜单整体紧邻“载”字右侧，图形在 `36dp` 圆形点击反馈内严格水平、垂直居中，不再显示正方形阴影，新增与清理动作继续位于标题栏右侧。书签、历史、下载、网络日志、视频资源、占位功能页和插件/脚本子页统一使用 `52dp` 顶部栏、`34dp` 语义徽标、`8dp` 图标标题间距及同一标题字级；其项目自定义弹窗统一使用语义色徽标、`20dp` 圆角、细描边、标题分隔线、阴影和全窗口遮罩。

2026-07-29 的文件下载器封板契约覆盖上段从网页下载确认开始的旧下载器说明。`BrowserDownloadManager` 仍是唯一 Kiyori 任务、队列、调度与文件 owner；任务状态改为 `AtomicFile` 串行落盘，同名目标在入队前预留，网页确认使用有界 FIFO。Android 14 及以上由用户发起数据传输 Job 承载，Android 8 至 13 使用 `dataSync` 前台服务；进行中通知显示聚合进度与速度并提供全部暂停，完成和失败通知可从设置关闭。新任务冻结任意网络或仅非计费网络、漫游许可和原有并发、线程、目录、协议策略，内置运行时与 Android 系统下载器都消费相同网络约束。普通文件断点续传使用强 ETag 或 Last-Modified `If-Range` 校验，表示变化时清理旧分片并明确失败，不拼接不同版本资源。M3U8 设置统一称为“离线包”：文本受大小上限和 `#EXTM3U` 校验，最高带宽 master 最多四层且拒绝循环，重复或字节范围资源只保存一份，KEY、MAP、PART 与媒体文件按有界批次下载并在提交前逐项校验；使用独立音轨、画面或字幕 playlist 的 master 会明确失败，不生成看似完成但缺轨的离线包。启用安装包自动清理时不再计时删除：任务持久化目标包名和版本，SAF 安装包只使用短生命周期缓存副本读取包信息，系统安装器继续读取获得授权的原始 SAF URI；只有 Android 报告精确包名和版本安装成功后才删除原文件和记录，取消安装不会清理。状态文本会移除下载地址中的账号、查询参数和片段，只有用户显式“复制下载链接”会返回原始地址。

抽屉保留原版“权限”高频入口，并继续进入 `Screen.ShizukuCommands`。AI 助手中的 AI 工具授权继续由 `ToolPermissionSystem` 持有；Kiyori 权限中心仍是系统设置目标，但当前设置首页尚未提供入口。三者不复制或混合状态。权限中心以只读总览区分设备能力与 AI 工具授权；高影响操作策略与操作记录将在安全合同中继续设计。备份、聊天记录和 Token 统计分别进入数据设置或 AI 助手，修改其他应用权限的工具仍保留在原有领域。

模态 AI 左抽屉只能由三横线按钮打开，并通过遮罩点击或系统 Back 关闭。左边缘打开、横向拖动、滑动关闭、主内容倾斜/缩放、平板永久侧栏和抽屉专属主题设置均不属于 Kiyori App Shell。其他功能页内部为自身工作流使用的局部抽屉组件不属于这项顶层导航。

“权限”高频卡片继续使用 Operit 原版短标签和视觉。徽标只显示当前启用功能缺少的必要设备授权数量，无待处理项时显示“正常”；AI 工具授权策略不计入该徽标。

高影响操作确认与 AI 操作记录共同归入权限中心的“AI 安全”分组。AI 操作按 R0 只读、R1 低影响、R2 高影响、R3 关键操作分级；工具被设为允许也不能绕过 R2 或 R3 的操作确认。对应策略页和记录页完整实现前不显示空入口。

Kiyori 新页面的视觉语言向 Operit 原版 UI 看齐，页面结构、浏览器行为和其他 Kiyori 功能参考 [kiyori-android@24a2dfa9](https://github.com/Kiyori-CN/kiyori-android/tree/24a2dfa91f0a4166dc58e5c4732d11861173f766)。手机、平板与折叠屏共享同一导航状态；AI 抽屉按窗口宽度使用 `75%`、`320dp` 或 `360dp`，并限制在折叠屏分隔铰链左侧。详细设计见 [Kiyori 产品壳与导航架构](docs/doc-src/architecture/kiyori_product_shell_and_navigation.md)。

“视频播放器”入口进入与浏览器/下载器一致的折叠标题和分组卡片页面。Kiyori 尚未发布，旧页面中没有真实 owner 的静态伪设置已经删除；当前按“播放与连播、手势与进度、画面与超分、音频与字幕、保存与下载、窗口与在线”排列 `4/7/5/2/2/4` 六组 24 项，全部由唯一 `PlayerSettingsStore` 持有并被 `PlayerSession`、`:player` runtime、播放器 UI 或既有 `BrowserDownloadManager` 消费。设置覆盖默认/记忆倍速、自动下一集、队列播完行为、两种双击手势及独立跳转时长、长按分段加速、按钮跳转、精确 seek、章节节点、拖动缩略图、记忆与默认 Anime4K、解码器、GPU Next、Vulkan、音量增强、字幕缩放、截图保存位置、视频下载位置、重力自动旋转、在线播放缓存、全屏退出和后台行为。未持久化过的双击手势默认是暂停/播放。长按加速只在按住期间按当前速度区间临时切到 `1.0x / 2.0x / 3.0x`：低于 `1.0x` 到 `1.0x`，从 `1.0x` 到低于 `2.0x` 到 `2.0x`，从 `2.0x` 到低于 `3.0x` 到 `3.0x`；松手或手势取消后恢复按下前速度，不写入倍速记忆。截图和视频下载默认实时跟随文件下载器主设置，也可分别保存到独立 SAF 目录；播放器视频仍进入唯一下载任务 owner，独立目录使用现有内置下载器，M3U8 离线包继续遵循下载器的应用目录契约。GPU Next 与 Vulkan 明确标注在下一次唯一 mpv core 创建时生效，其余适用设置会通过现有 runtime 命令更新当前会话。播放器接收系统 `ACTION_VIEW` 的本地 `content://`、`file://` 与网络视频，也接收浏览器候选；浏览器悬浮与全屏只转挂同一个 mpv core 的 Surface。

全屏与悬浮画面都使用 `SurfaceView`，悬浮 Surface 位于实时 WebView 上方。新媒体先创建并初始化唯一 mpv core；有效 Surface 到达后才绑定 Android `wid`，完成当前 Surface lease 的 native attach 后才执行 `loadfile`。浏览器悬浮播放器保持内容区全宽、固定 `16:9`、零左右边距且只能上下平移，并与全屏播放器读取同一按钮跳转设置。悬浮控制层按比例沿用横屏播放器的顶部、侧边与底部布局，共用蓝紫进度渐变、白色轨道、蓝色滑块、上下渐变遮罩和同一倍速弹窗；显示网速直接读取唯一 `PlayerSession` 的实时值，不再另建全局流量轮询。全屏控制层继续使用现有播放器专用图标和横竖屏结构；所有播放器按钮直接显示图标或紧凑文字，不绘制静态圆形/胶囊底色和描边，完整点击热区保持不变。锚定菜单由单一深色圆角表面绘制，四角不再露出第二层白色容器，并保留清晰选中态和现代加载/错误/手势卡片。顶部网速/单位和电量/时间为完整两行；字幕、弹幕、音轨和画面模式四个按钮保持原位置。右上角更多菜单提供自动旋转开关和播放日志，开关直接写入同一设置 owner；开启后 Activity 使用 `FULL_SENSOR`，底部旋转按钮显示“自动”并禁用，关闭后恢复默认横屏与手动横竖屏切换。单一稳定手势 detector 不再随播放位置更新重启；单击切换控制层，双击按设置执行暂停/播放或左右半屏快退/快进，左右滑动 seek。左侧上下滑动仍控制亮度但提示显示在右侧，右侧上下滑动仍控制音量但提示显示在左侧。倍速菜单从上到下按 `0.25x` 步进显示 `3.0x..0.25x`，选项垂直间距压缩，并提供 `0.00x..3.00x`、最多两位小数的自定义输入；`0.00x` 暂停播放但保留原非零倍速。Anime4K 按钮从上到下显示“关 - 原始画质 / A - 强力重建 / B - 柔和重建 / C - 降噪处理 / A+ - 双重强化 / B+ - 双重柔和 / C+ - 降噪强化”，使用 `mpv-android-anime4k@32f5f169` 的 Balanced/M shader 链并立即应用；打包资产、私有缓存和 MPV `glsl-shaders` 属性都经过校验。MPV 章节节点和当前章节按设置显示；拖动进度条时由同一 `:player` runtime 的单线程提取器返回最大 `320px` 预览帧。系统打开的本地视频按同目录、同系列名和自然序建立真实队列，上一项/下一项据此启用；网络视频维持单项，除非调用方明确提供有序队列。自然 EOF 可自动进入下一项，最后一项按设置停留、关闭或从头播放当前视频。播放中空闲三秒自动隐藏，暂停、加载、弹窗、日志、进度拖动或全屏手势期间不隐藏；锁定后解锁按钮也会自动隐藏，单击视频区域可重新显示。没有真实 owner 的弹幕入口显示为禁用。日志弹窗固定标题、单行横滑分类、最新在前正文和底部清空/复制/导出区域；复制与导出生成当前分类的时间正序脱敏报告，文件写入 `Download/Kiyori/exports`。

已有开发安装中的旧 `off / fast / balanced / quality` Anime4K 设置会在严格读取前一次性迁移为 `OFF / B / A / A_PLUS`，避免七档方案升级后因旧持久化 ID 无法识别而阻断应用启动；其他非法值仍保持严格报错。

浮窗与全屏之间现在由唯一 `PlayerSession` 的显式 Surface lease 状态机完成交接。每个 `PlayerSurfaceView` 都携带 floating/fullscreen role、实例 token、单调 generation 和 Surface identity；新 Surface 可以先登记为 pending，但旧 owner 的 `surfaceDestroyed` 与 native detach 完成前禁止 attach。浮窗进入全屏时先从 Browser Home 移除旧 Surface，再发出一次全屏 Activity 启动请求；全屏返回时先发出一次 finish 请求，旧全屏 Surface 释放后 presentation 才切回 floating。整个过程保留同一媒体 request、URL、headers、位置、暂停、速度、轨道、字幕、Anime4K 状态、`loadGeneration` 和唯一 mpv core，不重新 `loadfile`、嗅探或刷新网页。

## 构建

### 环境要求

- Windows、macOS 或 Linux
- JDK 21（Gradle 运行时；Java/Kotlin 字节码目标仍为 JVM 17）
- Android SDK Platform 37、target SDK 34、Build Tools 36.0.0、NDK 28.2.13676358、CMake 3.22.1
- rustup、Rust 1.88.0 与 `aarch64-linux-android` target，用于构建 APK 内的 native ripgrep
- Git 与 Git submodule 支持

### 获取源码

```bash
git clone --recurse-submodules https://github.com/Kiyori-CN/Kiyori.git
cd Kiyori
rustup toolchain install 1.88.0 --profile minimal
rustup target add --toolchain 1.88.0 aarch64-linux-android
```

项目部分大型模型和本地运行库未直接存放在 Git 仓库中。若构建提示缺少 `models`、`subpack`、`jniLibs` 或 `libs` 内容，请按项目内构建配置补齐对应本地依赖。`liboperit_ripgrep.so` 不属于手工依赖；Gradle 会从 `tools/native_ripgrep` 构建到 `app/build/generated/` 并自动打入 APK。

### 构建 Debug APK

Windows：

```powershell
.\gradlew.bat assembleDebug --console=plain
```

macOS 或 Linux：

```bash
./gradlew assembleDebug --console=plain
```

输出目录为 `app/build/outputs/apk/debug/`。

## 兼容性说明

为避免破坏已有数据和生态兼容，本轮品牌迁移不会直接重命名以下实现标识：

- 源码 namespace `com.ai.assistance.operit`
- `operit://` OAuth 回调及既有 Intent action
- 数据库、偏好、备份、工作区和文件格式标识
- 插件、ToolPkg、MCP 的协议标识与既有备份格式

这些名称不代表当前软件品牌。任何协议级重命名都需要独立的兼容迁移设计。

Kiyori 的产品版本与 Operit 插件生态兼容版本分别维护。市场会按当前继承的 Operit 运行时兼容版本检查插件声明的 `minAppVer` 和 `maxAppVer`，不会使用 Kiyori 的 `0.x` 产品版本误判插件不兼容，也不会跳过发布者声明的版本范围。

由于当前 application ID 是新的 `com.kiyori`，历史 `com.ai.assistance.operit` 安装不能直接覆盖。需要先在旧应用中导出备份，再在 Kiyori 中通过明确的备份或文件选择入口导入。Kiyori 新建的公共运行数据使用 `Download/Kiyori`；应用不会自动扫描、合并、迁移或删除 `Download/Operit`。既有备份格式和插件协议标识继续保留。
